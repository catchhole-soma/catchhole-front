# 설정집 분석과 출처별 검토 — GH221

설정집은 `설정DB → 설정집 목록`에서 회차 없이 업로드한다. TXT·DOCX·HWP·HWPX 업로드가 저장한 원문 리비전으로 인물과 세계관을 함께 분석하는 작업 하나를 예약한다. 회차 업로드의 세 가지 방식에는 설정집 첨부 옵션이나 추가 파일 입력이 없다.

원문 `저장`은 리비전만 저장한다. 본문과 기준 시점이 모두 같으면 새 리비전을 만들지 않으며, 저장은 분석을 시작하지 않는다. 본문 또는 기준 시점에 저장하지 않은 변경이 있으면 분석 버튼을 잠근다. 기존 미분석 설정집은 `분석 시작`, 완료된 설정집이나 변경한 원문은 `다시 분석`을 명시적으로 선택한다. 설정집은 기존 `AUTOMATIC + ORDERED_PROVISIONAL`을 사용하며 반영 방식 선택기를 추가하지 않는다.

기준 시점은 `미지정`(기본), `작품 시작 시점`, `특정 회차 기준`이다. 특정 회차는 양수 N의 종료 시점이며 등록된 회차나 episode ID를 만들지 않는다. `referenceTimeKind/referenceEpisodeNo`는 원문 리비전과 함께 고정되어 과거 원문·근거에서 그대로 읽는다.

기준 시점 입력은 업로드·편집에서 기본으로 접힌 선택 항목이다. 펼치거나 접어도 저장된 값과 초안은 유지하며, 접힌 채 저장해도 기존 기준 시점을 보낸다. `EPISODE`일 때만 회차 번호를 보내고 그 외에는 번호 필드를 생략한다. 필수 번호 검증과 편집 잠금은 펼침 상태와 무관하다.

원문 편집은 수정 시작 때 확인한 `revisionNo`를 고정하고 PATCH의 필수 `expectedRevisionNo`로 보낸다. 리비전이 없는 레거시 원문만 0을 사용한다. 편집 중 조회 응답으로 이 기준 버전을 바꾸지 않는다. 다른 창의 본문 또는 기준 시점 변경으로 새 리비전이 확인되면 초안·시점 입력을 유지하고 저장과 분석을 잠근다. 조회와 저장 사이에 서버가 바뀐 409 충돌에서도 같은 잠금을 유지한다. `취소`로 최신 원문·시점을 다시 조회한 뒤 다시 편집하며, 이 조회가 실패하면 초안을 버리지 않는다. 변경 없는 저장도 버전 검증을 생략하지 않는다.

## 진행과 복구

책 작업은 실제 `source.sourceKind=SETTING_BOOK`으로 식별한다. null 회차 ID·0개 회차·배치 종류만으로 출처를 추측하지 않는다. `/episode-upload?workId=…&sourceAnalysisJobId=…`는 기존 라우트 안의 설정집 진행 화면을 복원하며, 회차 입력이나 회차 개수 안내를 표시하지 않는다.

`PENDING/RUNNING`과 자동 적용 대기는 갱신한다. 완료는 `SUCCEEDED`, `analysisRun.journalStatus=SEALED`, `automaticAppliedAt`까지 확인한다. `SUCCEEDED+INCOMPLETE`와 일반 실패는 중단으로 표시하고 반복 조회를 멈춘다. 재개 요청은 보존된 완료 단계와 같은 Job을 사용할 수 있다. 사용량 중단도 설정집 문맥으로 안내한다. `INVALIDATED`나 원문 변경은 이전 실행의 재개와 구별하고 저장한 현재 원문 분석을 제공한다.

현재 설정집 조회가 실패하면 기존 Job 상태가 조회됐더라도 재개를 잠그고 `상태 다시 확인`을 제공한다. 이 행동은 원문과 Job을 다시 읽으며 분석을 예약하지 않는다. 조회 복구 후 사용자가 명시적으로 재개해야 기존 Job을 사용한다.

갱신 중에도 열린 원문·검토 수정 초안을 유지한다. 생성 응답으로 상세 캐시를 갱신하고, 새 Job ID가 생기면 진행 URL도 새 origin으로 전환한다. 자동 적용 완료 뒤 현재값·검색·이력·근거·분석 목록 캐시를 무효화한다.

## 검토 범위

`sourceAnalysisJobId`는 최초 추출 Job ID다. 숨김 재비교 Job ID를 쓰지 않는다. 설정집의 인물·세계관 목록, 그룹, 상세, 집계, 페이지, 수정·연결·확정·제외·재개 요청과 캐시/URL에 동일한 origin ID를 전달한다. 이 값이 없는 기존 회차 검토는 회차 범위를 유지한다. 같은 배치의 다른 회차나 책 분석을 합쳐 표시하지 않는다.

현재 책 리비전과 최신 origin이 다른 이전 분석, 보관된 책, 출처 확인 실패는 읽기 전용이다. 열린 수정·연결 창의 입력은 남기고 제출만 잠근다. 제출 직전에도 URL·작품·배치·origin과 현재 출처를 확인한다. 느린 이전 요청 응답은 새 출처 화면을 바꾸지 않는다.

origin이 명시된 Job 응답에 출처가 없거나 sourceKind가 유효하지 않으면 읽기 전용을 유지한다. origin 없는 기존 회차 검토의 호환성과 출처 미확인 작업의 변경 권한을 구분한다.

분석 목록에서 출처 목록이 로딩 중이거나 실패하면 진행 액션을 보류하고 재조회를 제공한다. 명시적으로 EPISODE인 ID만 회차 진행 URL로 전달한다. 책 카드의 검토 건수는 origin으로 한정한 두 후보 API에서 받으며, 회차 전용 배치 합계를 책의 개수로 쓰지 않는다.

완료 전환은 진행 중 집계를 재사용하지 않는다. 완료 이후 캐릭터·세계관 양쪽의 새 집계가 성공하기 전에는 결과 행동을 잠그며, 이전 숫자나 탭으로 검토를 시작하지 않는다.

## 현재 설정 반영 선택

설정집이 직접 입력·수정한 현재값이나 시점 충돌을 발견하면 해당 보류 사유를 표시한다. 기존 검토 선택 컴포넌트를 사용하며, 초안 저장은 현재값을 반영하지 않는다. 캐릭터의 현재 반영은 저장한 `APPLY_PROPOSAL` 결정과 기존 `applyEditedValue` 규칙을 유지한다. 미래·비현재 내용도 먼저 작가 결정을 저장해야 현재 반영을 선택할 수 있다.

캐릭터 ordered 비교의 before 값은 앞선 임시 반영을 포함할 수 있어 `비교 당시 내용`으로 표시한다. 이후 보류·복원이 일어나면 실제 현재값과 다를 수 있으므로 이 값으로 `이력에만 저장` 선택의 현재 유지값을 단정하지 않는다. 비교 값, 수동 선택과 버전 검증은 그대로 사용한다.

기존 인물 등장(`CHARACTER_DISCOVERY`) 후보는 Fact 현재 반영 선택 대상이 아니다. 연결된 인물의 등장 검토는 현재값 선택 없이 기존 연결 확정을 사용한다. 현재 반영이 지원되지 않는 설정집 캐릭터 `REMOVE`는 현재 반영과 현재 수정 경로를 제공하지 않으며 이력 선택으로 확정한다. 이전 초안이 `APPLY_PROPOSAL`로 저장돼 있으면 이력 선택이 완료된 것으로 추측하지 않는다. 수정 창을 다시 열어 명시적으로 `HISTORY_ONLY`를 저장해야 확정한다. 회차의 기존 REMOVE 정책은 유지한다.

명시적으로 현재 반영을 고른 행에만 `applyToCurrent=true`를 보낸다. 캐릭터는 실제 응답의 `currentSnapshotVersion`을 `baseSnapshotVersion`으로, 세계관은 `currentWorldSettingVersion`을 `expectedWorldSettingVersion`으로 보내고 양쪽 모두 후보의 `expectedUpdatedAt`을 보낸다. 비교 당시 버전을 현재 버전으로 대체해서 쓰거나 없는 버전을 0으로 만들지 않는다. 다른 행·새 대상·일반 확정·저장 요청에는 이 권한을 전파하지 않는다. 원문·대상·후보 시각·현재 버전이 바뀌거나 확정이 실패하면 기존 현재 선택을 다시 사용하지 않는다.

세계관의 before 값도 비교 당시 내용이며 실제 현재 버전보다 오래될 수 있다. 이력 선택에는 `현재 설정을 바꾸지 않습니다.`라고 안내하고 비교값을 유지될 현재값으로 약속하지 않는다.

세계관의 `applyToCurrent=false`는 보편적인 이력 전용 요청이 아니다. 응답에 현재 보호/시점 보류 사유가 남은 행만 `이력에만 저장`이라고 안내한다. 초안 저장 후 그 사유가 사라진 기본 선택은 `검토한 내용 확정`이며, 서버의 기존 보호·시점 규칙에 따라 현재값 또는 이력이 된다. 별도 HISTORY_ONLY 세계관 API를 가정하지 않는다. 초안의 최종 분류·대상이 원래 비교 대상과 달라지면 이전 대상의 버전으로 현재 반영을 허용하지 않는다.

## 근거와 원문

인물 검색·현재값 `sourceFacts`·설정 이력·근거와 세계관 현재값·후보 이력은 실제 책 이름/리비전과 회차 출처를 구분한다. 출처 객체가 없는 기존 응답은 `episodeNo` 또는 `sourceEpisodeNo`와 그룹의 실제 회차 번호를 사용한다. 책을 수동 입력이나 가상의 회차로 표현하지 않는다.

책의 `/editor?workId=…&settingBookId=…&revisionId=…`는 revision GET으로 분석 당시 원문을 읽는다. 수정·보관 후에도 동일 원문을 제공하며, 실패하면 최신 원문으로 대체하지 않는다. 인물 Fact evidence의 `content`도 저장된 근거 원문이다. 세계관의 책 링크는 `분석 당시 원문 보기`, 기존 회차 GET 링크는 `현재 회차 원문 보기`로 표시한다. 회차 링크가 수정 전 원문을 보장한다고 표현하지 않는다.

인물·세계관 검토 행의 기존 원문 근거 영역도 같은 분석 당시 원문 링크를 사용한다. 작품·책·리비전 ID가 있어야 링크를 제공하며, 누락된 ID를 현재 원문이나 다른 리비전으로 추측하지 않는다.

## 계약과 검증

실제 Backend OpenAPI와 생성 SDK가 경로·DTO의 기준이다. 생성 파일은 직접 수정하지 않는다. `setting-book-analysis.spec.ts`는 진행/저장/재개를, `setting-book-source.spec.ts`는 범위·이력·근거·느린 응답을 검증한다. `setting-book-current-review.spec.ts`는 실제 버전·행별 권한·충돌·원문 변경·미래 초안·세계관 기본 확정 문구·새 대상을 검증한다. `setting-book-runtime.spec.ts`는 명시적인 합성 로컬 fixture에만 연결하며 UI 로그인, HttpOnly 갱신 쿠키, 업로드/저장/분석의 실제 API·PostgreSQL 반영과 보관·고정 원문·정리를 검증한다. 이 테스트는 LLM을 호출하거나 분석 완료를 가장하지 않는다.

`setting-book-edit-conflict.spec.ts`는 독립된 두 탭의 원문 편집, 기준 시점만 바뀐 새 리비전, 조회 직후 저장 충돌, 레거시 버전 0, 변경 없는 저장, 일반 오류 재시도와 취소 중 최신 조회 실패를 실제 컴포넌트와 목 API로 검증한다.

PR1 회귀의 `e2e/fixtures/pr1-conflict-policy-public.json`은 Task 2의 실제 Java HTTP 공개 응답 네 개를 보존한다. 테스트는 경로 ID만 정규화하며, 보류된 MERGE의 비교 당시 `168`과 실제 현재 height 부재를 구분한다. 별도 음식·직업 행은 명시적인 API 목 UI fixture다. 이 E2E는 실제 컴포넌트의 표시·요청·상태 복원을 검증하며, 자동 충돌 정책이나 실제 LLM 실행의 증거로 사용하지 않는다.
