# GH261 가계도 배치와 렌더러 선택

가계도는 React Flow 12.12.0의 인물 카드·관계 선택·확대·이동에 ELK 0.12.0 배치를 연결한다. 가족 의미는 라이브러리가 추론하지 않는다. 입력에 있는 실제 인물 ID와 확정 관계 ID를 보존하고, 별도 세대 제약을 적용한 뒤 최종 좌표에서 선을 다시 계산한다. 새로운 LLM 호출이나 추출 프롬프트 변경은 없다.

## 같은 예제로 비교한 결과

2026-10-19에 `e2e/fixtures/family-tree-fixtures.ts`의 앞 네 예제를 Mermaid 12.2.0의 실제 브라우저 SVG 렌더와 ELK 기반 가계도 배치에 동일하게 넣었다. Mermaid는 `flowchart TB`, 부모는 방향 선, 배우자·형제는 방향 없는 선으로 작성했고 dagre와 ELK 두 엔진을 각각 실행했다. 아래 Mermaid 수치는 두 엔진에서 같았다.

| 예제 | 인물 / 실제 관계 | Mermaid 부모 위 배치 | 가계도 부모 위 배치 | Mermaid 배우자·형제 같은 높이 | 가계도 같은 높이 | 가계도 공유 부모 연결점 |
| --- | --- | --- | --- | --- | --- | --- |
| 일반 가족 | 4 / 6 | 4/4 | 4/4 | 0/2 | 2/2 | 1 |
| 재혼·이복 형제 | 5 / 7 | 4/4 | 4/4 | 0/3 | 3/3 | 2 |
| 부모 미상 형제 | 3 / 2 | 해당 없음 | 해당 없음 | 0/2 | 2/2 | 0 |

두 방법 모두 입력한 인물과 관계 수를 보존했다. Mermaid로 가족을 표현할 수 없다는 결론은 아니다. 기본 flowchart에서는 방향 없는 배우자·형제 선도 순차 배치에 참여하므로 가족별 세대 규칙, 복수 관계 선택, 프로필·근거 모달 및 URL 연결을 추가해야 한다. 이번 제품은 인물·관계의 개별 클릭과 선택 유지가 중요하여 React Flow의 컴포넌트·이벤트 모델과 직접 좌표를 제공하는 ELK 조합을 선택했다. React Flow 자체가 배치 엔진은 아니며, Mermaid도 ELK를 사용하므로 **ELK 선택만으로 가족 배치가 완성되는 것은 아니다**. [React Flow 배치 문서](https://reactflow.dev/learn/layouting/layouting), [Mermaid flowchart 문서](https://mermaid.js.org/syntax/flowchart.html), [ELK partition 옵션](https://eclipse.dev/elk/reference/options/org-eclipse-elk-partitioning-partition.html).

비교 산출물: [수치 JSON](screens/gh261/layout-comparison/results.json), [일반 가족](screens/gh261/layout-comparison/ordinary-comparison.png), [재혼](screens/gh261/layout-comparison/remarried-comparison.png), [부모 미상 형제](screens/gh261/layout-comparison/siblings-only-comparison.png), [친생·입양](screens/gh261/layout-comparison/biological-adoptive-comparison.png). 오른쪽은 실제 ELK 좌표를 SVG로 확인하는 배치 프로토타입이다. 실제 React Flow의 클릭·키보드·모바일·URL 동작은 가계도 브라우저 E2E에서 별도로 검증한다. 이 정적 비교를 제품 상호작용 검증으로 대신하지 않는다.

## 초기 순수 배치 계약 — 아래 가시성 교정 전

`src/app/components/catchhole/relationship/family-tree-layout.ts`는 생성 API 타입이나 React 상태를 참조하지 않는다.

- 입력 `nodes`: `{ id, name }`인 실제 인물. 표시명과 출생 순서는 위치 판단에 사용하지 않는다.
- 입력 `edges`: `{ id, subjectCharacterId, objectCharacterId, kind, subtype?, temporalScope?, timeLabel? }`. `kind`는 `PARENT_OF | SPOUSE | SIBLING`이다. 관계 ID를 합치거나 바꾸지 않는다.
- 출력 `nodes`: 실제 인물별 위치, 카드 크기 192×88, 세대와 연결 가족 ID. 실제 인물을 여러 노드로 복제하지 않는다.
- 출력 `edges`: 원 관계 ID, 원 source/target, 상하좌우 handle, 최종 꺾은선 좌표, 라벨 위치·연결점·예약 크기. 동일 인물 쌍의 친생·입양이나 현재·과거 관계도 각각 선택할 수 있다.
- 출력 `junctions`: 확인된 부모 집합과 공통 자녀를 잇는 화면용 공유 연결점. 인물이나 혼인 관계가 아니며 API에 저장하지 않는다.
- 출력 `components`, `width`, `height`: 분리 가족과 라벨까지 포함한 영역. `warnings`는 순환·정렬 충돌·입력 누락·단순 배치 전환을 표시한다.

## 세대·연결점·예외 규칙

1. 인물과 관계를 ID 순으로 정렬하고 연결된 가족 단위로 분리한다. 동일 입력의 순서나 이름이 달라져도 좌표는 안정적이다.
2. 부모 방향의 강결합 요소를 찾아 실제 순환만 같은 안전 영역에 배치한다. 순환 관계 ID를 경고하며 원 방향과 선을 유지한다. 라이브러리의 선 뒤집기로 정상 가계도처럼 보이게 만들지 않는다.
3. 배우자, 확인된 공동 부모, 형제를 같은 높이에 두는 제약을 차례로 적용한다. 합쳤을 때 부모 DAG가 순환하면 해당 정렬을 포기하고 경고한다. 부모가 자녀보다 위에 오는 조건이 우선이다.
4. 부모 DAG의 최장 경로로 세대를 정하고 ELK layered의 partition과 고정 seed로 가로 배치를 얻는다. 최종 세대 간격을 적용한 뒤 같은 세대의 카드가 겹치지 않도록 간격을 확보한다.
5. 같은 확인된 부모 집합·세부 관계·시점·시점 설명이 공통인 자녀는 공유 연결점을 사용한다. 친생과 입양은 서로 다른 연결점이다. 공동 부모라는 이유만으로 배우자 선을 만들지 않는다. 부모가 없는 형제는 형제 선만 연결한다.
6. 모든 실제 관계 선은 최종 카드 좌표에서 계산한다. 여러 세대를 건너뛰는 부모 선은 중간 인물의 카드를 통과하지 않도록 바깥 경로를 사용한다. 공유 선이 있어도 실제 관계 ID별 라벨은 유지한다.
7. 라벨은 최대 180×80의 클릭 영역을 예약하고 카드·공유점·다른 라벨과 8px 여유를 둔다. 부모 아래·자녀 위의 빈 공간을 먼저 찾고 필요하면 바깥 여백에 배치한다. `labelAnchor`는 원래 선 위 가장 가까운 점이며 UI의 보조 연결선에 사용한다. 화면의 라벨 높이는 이 예약 영역 이내로 제한하고 전체 설명은 근거 상세에서 읽는다. 마지막에는 카드·선·라벨의 실제 범위에 32px 여백을 더해 전체 보기 영역을 계산하므로 라벨이 잘리거나 불필요한 빈 공간 때문에 과도하게 축소되지 않게 한다.

일방향 부모 관계 하나만 확인되어도 해당 선을 그대로 그린다. 반대 방향의 중복 사실, 배우자, 다른 부모, 나이·출생 순서는 추정하지 않는다. 형제 또는 배우자를 같은 높이에 정렬한 것은 새 관계를 확정했다는 뜻이 아니다.

원 데이터에 없는 인물을 가상 부모로 만들지 않는다. 한쪽 인물 자체가 응답에 없으면 해당 관계 ID를 `MISSING_PERSON` 경고에 남기며 연결선을 만들지 못한 이유를 알린다. 중복 식별자는 경고 후 한 번 표시한다. 정상 입력의 서로 다른 관계 ID는 제거하지 않는다.

## 큰 그래프와 검증

전체 입력이 350명을 초과하거나 관계가 1,400개를 초과하면 ELK 대신 같은 세대 규칙을 지키는 결정적 기본 배치를 사용하고 `DENSE_GRAPH` 경고를 반환한다. 노드나 관계를 잘라내지 않는다. ELK 오류도 경고와 기본 배치로 복구한다. 서버의 조회 범위·페이지 제한은 별도이며 이 함수가 전체 작품 조회를 수행하지 않는다. 수백 명의 그림을 한눈에 읽기 좋다고 보장하지 않으며 UI의 확대와 인물 중심 보기를 함께 사용한다.

```sh
npm run test:layout
```

2026-10-19 순수 배치 테스트 **19개 통과**. 일반 가족·재혼·이복·부모 미상·친생/입양·분리 가족·순환·세대 모순, 인물과 실제 관계 ID 보존, 공유 연결점, 동일 쌍 복수 관계, 카드·라벨 비중첩, 순서 안정, 부모 방향, 다세대 우회와 경계를 확인했다. 300명은 실제 ELK 경로, 500명 연결/분리 그래프는 기본 배치 경로를 실행했다. 로컬 Node 실행에서 300명은 약 1.4초, 500명 연결/분리는 각각 약 34ms/3ms였다. 이는 해당 실행의 배치 시간이며 실제 브라우저 렌더·네트워크 성능 수치가 아니다.

같은 토폴로지의 주기 조회에서 재배치하지 않기, 이탈 후 늦은 결과 폐기, 선택·viewport·URL 보존, 모바일 클릭 영역 및 프로필·근거 진입은 React Flow와 화면 계층의 책임이며 별도의 브라우저 테스트로 확인한다.


## 2026-10-19 가시성 교정 후 표시 계약

위 Mermaid 비교와 180×80 라벨 배치는 초기 구현 기록이다. 사용자의 가시성 교정 이후 기본 렌더는 `connections`를 사용한다. 기존 `edges`와 `junctions`는 원본 방향·관계 검증을 위해 유지하지만 화면의 선과 전체 보기 영역은 `connections.paths`와 짧은 라벨을 기준으로 계산한다.

`connections`는 ID·종류·세부 종류·시점, 여러 선분 경로, 짧은 라벨과 위치/크기, `relationshipIds`와 `personIds`를 반환한다. 실제 관계 ID는 정확히 한 connection에 포함된다. 일반 가족의 배우자 1개와 부모·자녀·FULL 형제 5개를 두 개의 표시 연결로 표현하며, 복수 관계 선택은 화면의 하단 목록이 맡는다.

인물 간격은 128px, 세대 간격은 160px이며 기본 카드는 192×88, 모바일 입력 옵션은 112×72다. 표시 라벨은 112×44(배우자는104×44)의 영역을 예약한다. 같은 행에서 인물 사이에 다른 카드가 없을 때 배우자 선을 곧게 잇는다. 부모 집합·시점이 일치하는 확인된 배우자 선만 중앙 줄기의 출발점으로 사용한다. 배우자가 없으면 카드 아래 부모 합류선을 만들며 혼인으로 해석하지 않는다. 재혼 배우자 체인은 공통 배우자를 가운데 놓고 자녀는 각 부모 집합 아래에 정렬한다.

같은 친생 부모 아래의 FULL 형제 또는 친생/미상 부모 아래의 UNSPECIFIED 형제는 그 부모 묶음에 포함할 수 있다. 입양·의붓 묶음에 FULL 형제를 넣지 않으며 이복·부모 미상 형제 등 별도 정보는 독립 표시한다. 다세대 부모 연결과 순환은 기존 우회 경로·경고를 유지한다. 모든 실제 ID와 부모 방향, 표시 연결의 분할 완전성, 가운데 줄기와 자녀 분기, 입양·친생 구분을 순수 테스트로 검증한다.

교정 후 순수 테스트 23개 통과. 앞선 19개는 초기 표현 계약의 기록이며, 현재 테스트는 실제 인물·관계 보존에 더해 표시 연결의 분할 완전성·중앙 줄기·재혼 위치·FULL 형제의 입양 묶음 흡수 방지를 검증한다. 실제 화면은 [일반 가족](screens/gh261/revised-family-tree-ordinary-desktop.png), [재혼](screens/gh261/revised-family-tree-remarried-desktop.png), [입양](screens/gh261/revised-family-tree-biological-adoptive-desktop.png)에서 확인했다.

## 2026-10-19 이름만 언급된 인물

표시 문구는 사용자의 후속 선택에 따라 `프로필 미등록`으로 통일한다. 카드·근거 배지·관계 선택 목록과 도움말에 적용하며, 아래의 언급 노드 의미와 근거·연결 동작은 유지한다. 문구 변경 후 기존 언급 E2E 4개와 타입 검사·린트를 통과했다(기존 Fast Refresh 경고 2개 유지).

서버가 현재 프로필 근거로 인정한 미등록 상대도 독립 그래프 노드로 입력한다. `mention:<candidateId>` 식별자를 사용하며 같은 이름의 서로 다른 후보를 합치지 않는다. `CHILD_OF`는 서버에서 부모→자녀로 정규화한다. 배치의 순수 그래프 계산은 등록 인물과 같은 규칙을 따르되 노드·간선의 타입 및 후보 ID를 보존한다. UI는 등록 인물을 프로필로, 언급 노드와 해당 간선을 후보의 현재 설정·근거로 연결한다. 언급 노드를 캐릭터 ID로 취급해 초점 API를 호출하지 않는다. 실제 인물 연결은 명시적인 후보 수정·확정 이후 다음 응답부터 반영된다.

## 2026-10-19 안내와 캔버스 정리

인물·관계 수만 상단에 유지하고 반복 안내와 범례를 native details의 `가계도 안내`로 모았다. 선택적 인물 연결 건수는 안내 안에서 작품 전체 기준으로 설명한다. 캔버스와 선 위 라벨을 흰색 표면으로 바꾸고 캔버스에 옅은 점 격자를 사용해 외부 배경과 구분했다. 데이터·배치·관계 호칭은 변경하지 않았다.

타입 검사·린트·빌드·Knip을 통과했다(기존 Fast Refresh 경고 2개와 빌드의 큰 청크 경고 유지). 가계도/언급 E2E 13개를 통과했으며 키보드 이동 테스트의 포커스 대상에 native summary를 포함했다. localhost:3000의 실제 작품에서 데스크톱 표시와 안내 펼치기, 320×568의 가로 넘침 없음과 키보드 접기를 직접 확인했다. 사용자 데이터를 수정하거나 다시 분석하지 않았다.

## 2026-10-19 부모·자녀 선 양끝 호칭

부모 간선 입력의 `subjectRole`/`objectRole`을 끝점 표기에 사용한다. 서버가 반환한 부모 쪽 `PARENT/FATHER/MOTHER`, 자녀 쪽 `CHILD/SON/DAUGHTER`만 부모·아버지·어머니, 자녀·아들·딸로 표시한다. 이름이나 카드 위치로 성별을 추정하지 않는다. 비요른의 현재 설정이 `얀델의 아들`이면 부모 쪽 **부모**, 자녀 쪽 **아들**이며 얀델을 아버지로 바꾸지 않는다.

각 표시 연결은 `endpointLabels`에 인물 ID·역할·문구·좌표·60×44 영역과 그 인물에 연결된 실제 부모 간선 ID를 가진다. 부모가 여러 자녀를 두거나 자녀가 여러 부모를 가진 공유선은 끝점별로 한 호칭을 사용한다. 참여하는 모든 부모 간선이 같은 명시 호칭을 반환할 때만 구체적인 호칭을 표시한다. 하나라도 generic·누락이거나 서로 다른 호칭이면 부모/자녀로 낮춘다. 이는 서버가 근거 충돌을 generic으로 보류한 결과를 다른 간선의 호칭으로 덮지 않기 위함이다. 묶음에 포함된 형제 관계는 부모 호칭을 판단하거나 끝점의 근거 목록을 만드는 데 참여하지 않는다.

부모 카드 아래·자녀 카드 위의 선 끝을 우선하며, 배우자가 확인된 경우에도 부모 호칭은 각 부모 카드 하단 중앙에 붙인다. 혼인선에서 중앙 자녀 줄기로 이어지는 기존 선은 유지하고 부모 선을 추가하지 않는다. 카드와 다른 호칭·중앙 표기를 피하는 근거리 배치를 적용하고 모든 끝점 영역을 전체 보기 경계에 포함한다. 한 자녀의 중앙 `자녀 1명`은 생략한다. 여러 자녀의 개수와 입양·의붓·과거 문맥은 중앙에 남길 수 있다. 역할 텍스트는 데스크톱 14px, 모바일 17px이며 줄바꿈 없이 예약 영역 안에 표시한다. 기본 확대 비율에서는 큰 가족의 텍스트가 축소되므로 확대·인물 중심 보기와 목록을 함께 제공한다.

호칭 버튼은 해당 끝점의 실제 관계만 열고 복수이면 선택 목록으로 표시한다. `data-endpoint-person-id`/`data-endpoint-role`/`data-endpoint-relationship-ids`가 끝점 메타데이터다. 단자녀처럼 중앙 문구가 없는 경우 첫 실제 끝점 버튼이 표시 연결 전체의 `data-connection-id`/`data-relationship-ids`도 보관하되 클릭은 해당 끝점의 근거만 연다. 보이지 않는 키보드 정지점을 추가하지 않는다. 부모·자녀 어느 쪽에서 근거를 열어도 닫을 때 실제로 누른 버튼에 초점을 돌려준다. 언급 인물은 후보 근거를, 등록 관계는 관계 근거를 계속 사용한다.

순수 배치 테스트 26개와 가계도/언급 브라우저 테스트 14개를 통과했다. 전체 예제의 카드·중앙/끝점 라벨 비중첩·전체 보기 경계, 같은 이름의 독립성, 공유선의 관련 관계만 선택하는 동작, generic/충돌 호칭 보존, 양끝 클릭 후 초점 복귀, 320px 표시, 입양·재혼·부모 미상·순환·다세대 우회를 확인했다. 이 브라우저 검증은 합성 응답 기반이며 실제 API/DB 검증 기록과 구분한다.

기존 관계 화면 회귀 테스트 36개와 실제 Java API·PostgreSQL을 사용하는 E2E 2개도 통과했다. 실제 API 검증은 합성 계정·작품의 수동 설정으로 아버지/아들 및 부모/아들 표기, 미등록 상대의 근거 열기와 뒤늦은 인물 연결 후 호칭 보존을 확인한 것이며 LLM 추출 품질을 측정한 것은 아니다. localhost:3000의 실제 작품에서도 양끝 호칭, 근거 열기와 닫은 뒤 초점 복귀, 320px 화면의 가로 넘침 없음을 확인했다. 사용자 데이터는 수정하거나 다시 분석하지 않았다. 최종 타입 검사·린트·빌드·Knip을 통과했으며 기존 Fast Refresh 경고 2개, 큰 청크 경고와 React Doctor의 기존 208개 지적은 유지된다. 백엔드 관계 패키지 테스트 383개도 통과했다.

## 2026-10-19 기존 프로필 사진

가계도 응답의 등록 인물 `image`를 기존 캐릭터 이미지 컴포넌트로 표시한다. 서버는 표시 범위의 등록 인물만 일괄 조회하고, 가계도는 인물별 상세 조회를 추가하지 않는다. 미등록 언급·공통 기본·이미지 없음·허용되지 않은 경로·로딩 실패는 기존 기본 인물 아이콘을 사용한다. 개인 이미지는 기존 인증 SDK와 세션별 Query/Blob 수명을 유지하고, 이전 암호화 방식이나 이미지 디코딩 실패도 가계도에서는 기본 아이콘으로 표시한다.

이미지는 순수 배치 입력과 별도의 맵으로 전달하여 사진 변경만으로 재배치하지 않는다. 프로필 이미지 저장 후 해당 작품의 가계도 Query를 무효화하며 주기 조회에서도 반영한다. 카드 클릭·호칭 근거·확대·이동 위치는 유지한다. 모바일 카드는 136×88, 원형 이미지는 32×32, 이름은 22px, 관계·끝점 호칭은 18px로 표시한다. 앞선 112×72와 17px 기록은 이전 계약이다. 데스크톱 원형 이미지는 36×36이다.

검증: 순수 배치 26개, 가계도/언급 E2E 16개, 기존 개인 이미지 E2E 3개를 통과했다. 공개·인증 개인 사진, 기본/잘못된 경로/깨진 파일/미등록 언급의 아이콘, 이미지 단독 갱신 시 viewport와 노드 유지, 추가 프로필 조회 없음, 320px 가독성을 확인했다. 백엔드는 관계 패키지와 캐릭터 이미지 통합 테스트 394개(H2·PostgreSQL 포함)가 통과했다. 실제 localhost:3000 작품의 비요른 사진이 로드되고 다른 인물의 기본 아이콘이 유지되는 것도 확인했다. 실제 사용자 데이터를 수정하지 않았으며 합성 UI 캡처는 [모바일 가계도](screens/gh261/revised-family-tree-mobile-canvas-320.png)에 있다. 타입 검사·린트·빌드·Knip 통과, 기존 Fast Refresh 경고 2개·큰 청크 경고·Doctor 208개 지적은 유지된다.

## 2026-10-20 중간 계보를 생략한 조상·후손

순수 배치 입력에 `ANCESTOR_OF`와 nullable `generationGap`을 추가했다. `DESCENDANT_OF` 원문은 서버에서 조상→후손으로 정규화한다. `5대손`은 세대 차이 5인 관계 한 개로 보존하며, 화면에는 두 실제 인물 사이에 한 연결을 표시한다. 빠진 부모나 네 명의 중간 인물을 생성하지 않는다. 세대 차이가 없는 명시적 후손 관계는 `후손 · 세대 미상`으로 표시한다. 이 관계만으로 과거 관계가 되지는 않는다.

조상은 후손보다 위에 놓지만, 배치의 `generation`은 화면 행이다. 실제 세대 차이 5만큼 빈 행을 만들지 않는다. 알려진 부모 경로가 함께 있으면 그 경로와 조상 관계를 모두 보존한다. 조상 연결은 부모 합류점·형제 묶음에 흡수하지 않으며, 부모와 조상이 섞인 순환도 기존 경고 경로를 따른다.

각 후손으로 내려가는 선을 끊고 두 개의 사선으로 생략을 표시한다. 그 가지에 `N대손`과 `중간 계보 생략`을 붙인다. 실제 계보가 다른 근거에 존재할 수도 있으므로 항상 '미상'이라고 단정하지 않는다. 같은 조상의 출발 호칭은 한 개로 모아 관련 근거를 선택할 수 있게 하며, 각 후손의 세대 수·근거는 독립적으로 유지한다. 행 간격과 미상 세대 배치는 아래 혼합 가계도 규칙으로 개선했다.

순수 배치 테스트 31개 및 가계도 브라우저 E2E 14개가 통과했다. 두 인물만 보존하기, 등록·미등록 인물, 세대 수 미상, 알려진 부모 경로 병존, 혼합 순환, 한 조상의 여러 후손마다 올바른 가지에 세대 수 표시, 데스크톱과 320px에서 근거 열기·전체 보기 경계를 확인했다. 브라우저 E2E는 합성 API 응답 기반이며 실제 로컬 DB 재현과 구분한다.

실제 localhost:3000에서도 별도 작품에 프로필 설정을 저장해 PostgreSQL·Java 자동처리를 거친 가계도 5인물·3관계를 확인했다. 등록 조상/미등록 조상의 5대손과 세대 미상 후손을 표시하고, 부정·추측·비유 세 사례는 가계도에 포함하지 않았다. 근거 클릭과 한 조상의 복수 근거 선택도 직접 확인했다. 원본 작품과 앞서 만든 5세대 예시는 내용 해시를 비교해 보존을 확인했으며, 별도 manifest로 새 예시만 정리할 수 있다. 이는 LLM 추출 품질 검증이 아니다. 최종 타입 검사·린트·빌드·Knip을 통과했고 기존 Fast Refresh 경고 2개와 큰 청크 경고는 유지된다.

## 혼합 가계도의 세대와 별도 영역

- 부모·자녀는 차이 1, 명시된 조상·후손은 `generationGap`으로 상대 세대를 계산한다. 예를 들어 조상·자녀·3대손·5대손은 실제 상대값 0·1·3·5를 유지해 계산한 후, 사람이 없는 층만 압축한 화면 행 0·1·2·3에 놓는다. 3대손에서 5대손으로 새 선을 잇지 않는다.
- 배우자나 형제의 동일 행 정렬은 알려진 세대 차이와 충돌할 때 포기한다. 모순된 입력은 경고하며 원래 방향과 모든 관계 ID를 보존한다. 큰 대손 수 때문에 수백 개 빈 행을 생성하지 않는다.
- 세대 차이가 없는 조상 관계는 순위 계산에 가중치 1을 넣지 않는다. 그 관계만으로 연결되는 가족 덩어리는 `세대 미상` 옆 영역으로 분리하고, 그 안에서 알려진 부모·자녀와 세대 차이를 독립적으로 배치한다. 다른 알려진 경로로 이미 위치가 정해진 동일 인물을 복제하거나 옮기지 않는다. `regions`는 화면 장식이며 실제 인물·관계에 포함되지 않는다.
- 같은 부모의 자녀 블록은 통째로 배치해 다른 인물이 자녀 사이에 끼지 않게 한다. 배우자 행에서는 기존 배우자 연결 순서를 우선한다. 직접 자녀의 공유선과 조상 연결은 합치지 않는다.
- 조상 연결은 알려진 가족의 바깥 통로를 사용한다. 옆에 배우자나 다른 인물이 있으면 카드 위의 빈 공간으로 나갔다가 바깥 통로에 합류한다. 각 가지에 생략 기호와 대손 수를 붙이고 해당 가지의 근거 ID를 유지한다.
- 일반 부모 행은 기존 160px 간격, 조상 관계와 함께 있는 직접 자녀 행은 최소 180px, 먼 후손만 있는 행은 128px를 사용해 불필요한 공백을 줄인다. 카드·관계 라벨·옆 영역을 모두 전체 보기 경계에 포함한다.

검증: 순수 배치 35개, 가계도 E2E 15개, 묶기/미등록 인물 E2E 11개, 기능 OFF E2E 4개를 통과했다. 실제 localhost의 별도 작품에서도 자녀 2명·3대손·5대손·세대 미상 후손을 함께 표시했다. 태조의 두 언급은 직접 묶어 9인물·7관계로 만들고, UI 해제 시 10인물·7관계, 다시 묶으면 9인물·7관계가 되는 것을 확인했다. 각 후보의 3대손/5대손 근거 전환을 확인했으며 기존 두 작품과 모든 원 관계·근거는 보존했다. 예시는 루트 `.codex-artifacts/gh261-local/explicit-ancestry-demo/manifest.json`으로 별도 정리할 수 있다.

### 친생·입양 자녀가 함께 있는 부모의 호칭

같은 인물·역할·관계 시점의 부모 호칭은 자녀 묶음이 달라도 한 번만 표시한다. 친생·입양 연결선과 원본 관계 ID는 각각 유지하며, 부모 호칭을 누르면 그 부모에게 해당하는 모든 근거를 선택할 수 있다. 서로 다른 호칭·과거/현재·시점 설명은 합치지 않는다. 혼합 근거의 접근성 제목에 첫 연결의 `입양`·`의붓` 유형을 전체 관계의 유형처럼 붙이지 않는다.

순수 배치 37개, 중복 호칭 및 기존 양끝 호칭·근거·초점 회귀 E2E 2개가 통과했다. 실제 localhost 5세대 예시에서도 루미의 어머니와 카일의 아버지 호칭이 각각 하나이며, 루미 호칭에서 에린·루카·비칼의 관계 3개를 선택할 수 있음을 확인했다. 데이터 변경 없이 화면만 수정했다. 빌드(타입 검사 포함)·린트·Knip 통과, 기존 Fast Refresh 경고 2개와 큰 청크 경고는 유지된다.
