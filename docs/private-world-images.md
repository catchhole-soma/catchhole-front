# 세계관 내 이미지 — GH194

번호 안내: 2026-09-16 main 통합으로 미배포 GH194 migration을 V55~V60에서 **V57~V62**로 이동했다. 아래 계약은 최종 번호로 표기하며, 이전 검증 실행 당시에는 각 번호가 2씩 작았다. SQL 내용과 기존 사용자 선택은 보존했다.

대표 이미지 선택창의 `내 이미지`에서 작품 전용 이미지를 올리고 선택한다. 공용 도감과 기본 이미지 복귀 흐름은 유지한다. 기존 원고 처리와 LLM 프롬프트는 변경하지 않는다.

사용자 안내는 첫 화면에서 비공개 보관의 의미를 먼저 설명한다. `복구키`·`브라우저 암호화`·`서버` 등의 구현 용어를 노출하지 않고, 시작한 다음 실제 보관이 필요한 단계에서 `보관용 코드`로 안내한다. 코드 분실 시 이미지를 다시 열 수 없다는 설명과 보관 확인은 유지한다. 아래 문서의 복구키는 같은 코드를 뜻한다.

- 처음 이용하면 보관함을 만들고 복구키를 별도 보관한다. 확인 체크 후 업로드할 수 있다.
- 원본·썸네일·파일명은 브라우저의 Web Crypto AES-256-GCM으로 암호화한다. 키는 서버로 전송하거나 브라우저 저장소에 자동 저장하지 않는다.
- 페이지 새로고침, 로그아웃, 다른 탭의 계정 변경, 보관함 잠금 이후에는 복구키를 다시 입력한다. 잠금 상태에서는 카드와 상세에 `잠긴 내 이미지`를 표시한다. `이미지 변경 → 내 이미지`에서 잠금을 푼다.
- PNG/JPG/WebP, 8MB, 3,200만 화소, 최대 한 변 16,384px, 작품당 50개다. 현재 작품에서만 이미지를 고른다. 사용 중인 이미지는 대표 이미지를 바꾼 뒤 삭제한다.
- 복구키를 잃으면 운영자도 이미지를 복원할 수 없다. 보관함 초기화/키 교체 기능은 제공하지 않는다.
- 보장 범위는 저장된 이미지 암호문·DB만 가진 사람의 복호화 방지다. 악의적인 서버 JavaScript 변경, XSS, 사용자 기기나 복구키 파일 탈취까지 막는다고 주장하지 않는다.

## 구현 파일

- `private-image-crypto.ts`: CHI1 envelope, nonce/AAD, 메타데이터 암호화, 로컬 썸네일 생성.
- `private-image-keys.ts`: 탭 메모리 키와 세션 세대. 늦은 비동기 완료가 로그아웃 후 키를 되살리지 못하게 한다.
- `PrivateImageVaultGate`: 키 생성/복구키 보관/잠금 해제. `PrivateWorldImagePicker`: 암호화 업로드, 선택, 삭제 확인.
- `PrivateSubjectImage`: 인증된 SDK로 암호문을 받고 메모리에서 Blob URL 생성. Query cache에는 암호문만 저장한다. URL은 키 변경/언마운트 때 revoke한다.
- SDK는 Backend OpenAPI에서 자동 생성했다. multipart JSON metadata의 Content-Type은 업로드 요청의 bodySerializer로 지정한다. 생성 파일은 직접 수정하지 않는다.
- `e2e/private-images.spec.ts`는 실제 브라우저 암호화, 변조·잘못된 키·다른 대상 AAD 거절과 세션 키 제거를 검증한다.
- `e2e/private-images-live.spec.ts`는 보관함 없는 일회용 계정으로 실제 업로드/선택/잠금/복구/삭제를 검증한다. `CATCHHOLE_E2E_API_BASE_URL`, `CATCHHOLE_PRIVATE_E2E_EMAIL`, `CATCHHOLE_PRIVATE_E2E_PASSWORD`가 필요하다. 일반 사용자 계정으로 실행하지 않는다. 테스트 작품은 finally에서 purge한다.

Backend 프로토콜·위협 범위·V59 명세는 Java 저장소 `docs/private-world-images.md`에 정리했다. `/demo`에는 보관함/API를 연결하지 않는다.

## 2026-09-16 확인

- 빌드·타입 검사·ESLint(기존 경고 2개)·Knip 통과. 전체 Playwright 321 통과/환경 조건부 4 건너뜀, 개인 이미지 실제 API E2E 별도 1개 통과.
- 실제 PostgreSQL V59과 e2e 파일 저장소로 암호문 업로드·선택·새로고침 잠금·잘못된 복구키 거절·복호화·사용 중 삭제 거절·기본 복귀·삭제를 확인했다. 일회용 계정과 테스트 작품을 정리했다.
- 실제 요청에 복구키/원본 파일명이 없고 이미지 조회가 CHI1 암호문이라는 것을 확인했다. 데스크톱과 320px 화면은 `docs/screens/gh194/private-image-picker-*.png`에 기록했다.
- React Doctor 비차단 진단의 기존 updater 오탐 2건은 유지한다. 고정 signature prefix를 비교하는 crypto의 `.every` 두 곳에는 길이 비교 휴리스틱 경고가 남으며 전체 배열 동등성 검사로 사용하지 않는다. 보관함 컴포넌트에는 상태 개수 경고가 있다.

## 캐릭터와 함께 사용

같은 작품의 캐릭터 이미지 선택에서도 이 보관함·업로드·조회 API와 CHI1 계약을 재사용한다. 서버 경로/저장 키는 호환성을 위해 유지한다. 개인 이미지 삭제는 세계관과 캐릭터 선택을 모두 확인한다. 자세한 선택 우선순위와 V60은 [캐릭터 이미지](character-images.md)를 참고한다.
