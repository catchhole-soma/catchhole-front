# 한글 파일 업로드 (GH224)

단일 회차, 한 파일 여러 회차, 여러 파일 다회차, 설정집, 원고 교체에서 TXT/DOCX/HWP/HWPX를 선택할 수 있다. 다회차 여러 파일은 형식을 섞을 수 있다. 모든 accept/검증은 `src/app/lib/fileValidation.ts`의 `ALLOWED_EXTENSIONS`를 공유하며 원본 형식 표시는 파일 확장자를 기준으로 한다.

본문 추출은 서버가 수행한다. 브라우저에서 한글 문서를 임의로 텍스트 디코딩하거나 글자 수를 계산하지 않는다. 공백 포함 250,000자 검증과 `totalUploadCharacters`, 회차 감지/정렬의 `detectionOrder` 및 `sourceFileIndex` 계약은 유지한다. 선택한 원본 파일 배열은 다시 정렬하지 않는다.

암호 없는 일반 HWP 5.x/HWPX를 지원한다. 문단/줄바꿈/탭과 표의 행·셀을 구분하며 글상자는 연결된 문단 뒤에 포함한다. 머리말·꼬리말·각주·미주·숨은 설명은 분석 본문에서 제외한다. OCR/페이지 서식 재현과 암호·배포용·DRM/구형 HWP는 지원하지 않는다. 서버가 반환하는 암호, 미지원 버전, 손상, 내부 읽기 한도 오류 메시지를 그대로 표시한다.

회차 업로드의 동반 설정집은 기존처럼 별도 설정집 API로 저장하며 자동 AI 분석을 시작하지 않는다. 설정집은 추출 텍스트를 수정하고 원본 파일을 보존한다. 분석 시 학습 미사용/백그라운드 유지 안내는 기존 정책을 유지한다.

`e2e/fixtures/hangul`은 Java GH224의 fixture 생성기로 작성한 합성 원고의 복사본이다. 개인 원고나 사용자 제공 문서를 포함하지 않는다. 서버의 실제 파싱/저장 회귀는 Java 테스트, UI 파일 선택/전송/형식 표시 회귀는 `upload-policy.spec.ts`, `setting-book.spec.ts`, `manuscript-analysis-refresh.spec.ts`에서 검증한다. 실제 연동 테스트는 `hangul-upload-live.spec.ts`이며 `docs/local-image-live-tests.md`의 일회용 로컬 계정 환경 변수를 사용한다.

로컬 검증에서 제공된 HWP의 본문/표 문단 46개가 별도 라이브러리 기준과 같은 순서로 일치했다(표 2개·셀 9개, 머리말 컨트롤 2개 제외). 이는 해당 문서의 텍스트 대조 결과이며 모든 한글 서식의 호환성을 보장하지 않는다. 실제 API/DB/로컬 파일 저장소 검증은 합성 원고만 사용했으며 단일/한 파일 여러 회차/혼합 여러 파일, 설정집 조회·편집·재조회, 원고 교체를 통과했다.
