# GH254 설정집 분석 프론트엔드 공개 준비

GH221의 설정집 단독 업로드·분석·출처별 검토를 현재 main에 통합했다. 다중 원고의 번호 수정·정렬·파일 연결, HWP/HWPX, 캐릭터 연결 범위·장르별 표시명, 확정 REMOVE, 랜딩·데모 회귀를 함께 검증했다. SDK는 배포된 Backend 공개 OpenAPI에서 생성했다.

설정집은 TXT·DOCX·HWP·HWPX를 지원한다. 업로드는 저장한 리비전으로 분석을 예약하고, 이후 원문 저장은 분석을 시작하지 않는다. 기준 시점은 미지정·작품 시작·특정 회차다. 대표 시점의 별도 입력 UI는 제공하지 않는다.

과거 비교값을 실제 현재값으로 안내하지 않는다. 이력 선택은 현재 설정을 바꾸지 않는다고 표시한다. 현재 반영은 서버가 허용한 Fact에만 명시적으로 선택하고 실제 현재 버전과 후보 시각을 보낸다. 기존 인물 등장 후보는 Fact 현재 선택 없이 연결을 확정한다. 설정집 REMOVE는 이력 선택을 사용한다. 이전에 현재 반영으로 저장한 REMOVE도 이력을 명시적으로 다시 저장해야 확정한다.

원문 조회가 실패하면 상태 다시 확인으로 원문과 Job을 읽는다. 재조회만으로 분석을 시작하지 않는다. 저장한 세계관 초안은 완료 요약으로 접고 수정에서 범위·방식·내용을 다시 확인한다.

첫 9개 실패는 형식 표시·접근성 회귀와 변경된 검토 계약의 테스트를 구분해 수정했다. 다음 전체 실행의 1개 실패는 원고 초기 GET과 배치 상태 GET의 응답 순서 가정이었다. 변경 없는 10회 반복에서 9회 통과·1회 실패로 재현했다. 기존 원고 UI가 표시된 뒤 분석 상태를 응답하도록 fixture를 고정했다. 요청 수, 주기 갱신, 완료 후 최종 조회와 반복 조회 중단 단언은 유지했다. 수정 후 10회 반복과 관련 26개 회귀가 모두 통과했다.

최종 ESLint·타입 검사·production build·Knip·React Doctor 명령은 정상 종료했다. ESLint의 기존 Fast Refresh 경고 2개와 build의 큰 bundle 경고는 남는다. Knip은 제품 코드에서 통과했다. 보존된 `output/playwright/**` 과거 소스 사본 34개만 보고한 원본 실패를 남기고, 임시 설정에서 `output/**`만 제외해 다시 검사했다. 제품 설정이나 미사용 코드 규칙은 바꾸지 않았다.

React Doctor는 전체 검사를 마쳤고 건너뛴 검사가 없다. 제품 진단은 기존 오류 2개·경고 171개다. 두 오류는 `requestPropertyDraftDiscard`의 일반 callback을 state updater로 판단한 기존 오탐이다. 과거 출력 사본의 경고 6개를 포함하면 원본 결과는 오류 2개·경고 177개다. 종료 코드 0을 진단 없음으로 해석하지 않는다.

최종 실행 전후 소스·테스트·설정 hash는 같았다. 게시 준비 중 신규 파일 `FileDropArea.tsx`와 `dialog-escape.spec.ts`의 끝 빈 줄을 각각 1개 제거했으며 실행 코드는 같다. 화면 참조 482개를 보존했고 테스트가 덮어쓴 31개를 원래 byte로 복원했다. 새로운 참조 이미지는 없다.

## 실제 API와 검증 한계

격리된 브라우저 → Java HTTP → PostgreSQL 시나리오 1개가 8.96초에 통과했다. UI 로그인, HttpOnly refresh 쿠키, 만료 access token의 정확히 한 번 갱신, 업로드의 PENDING Job, 저장의 새 리비전과 분석 미생성, 변경 없는 저장, 저장 리비전의 명시적 분석, 보관 후 고정 원문, 작품 정리를 확인했다. 기존 개발 서버를 재시작하지 않았다.

이 실제 HTTP 검증은 앞선 통합 snapshot에서 실행했다. 이후 변경은 검토 표시·명시 선택·출처 재조회 UI 경로이며 최종 브라우저 회귀에서 확인했다. 테스트 파일 저장소는 in-memory adapter다. LLM worker를 호출하지 않았으므로 모델 추출 품질이나 전체 분석 완료의 증거가 아니다.

## 산출물 보존

실행 묶음은 `outputs/pr254-front-publication-20261015/`다. 최초 실행의 log·집계·source audit, 중간 실패와 최종 결과를 보존했다. 다만 이번 작업의 최초 실패 screenshot/context 첨부는 targeted 설정 경로 오류로 덮어써졌다. 이를 원본 첨부가 보존됐다고 표현하지 않는다. 로컬 보존 기록 `outputs/pr254-front-publication-20261015/artifact-correction.md`에 경위와 범위를 남겼다. 과거 작업의 원본 자료는 변경하지 않았다.

최종 결과는 `final-v2/verification-results.json`, Doctor는 `final-v2/doctor-summary.json`, 실제 HTTP 공개 요약은 `live/public-proof.json`이다. 인증정보·원본 쿠키·개인 계정 값은 이 문서에 포함하지 않는다.

PR CI 첫 실행은 634개 통과·1개 재시도 통과·12개 opt-in 생략이었다. 기준 시점만 저장하는 테스트가 클릭 직후 동기적으로 `saveBodies`를 읽어 요청 도착 전 빈 배열을 관찰했다. 같은 파일의 두 비동기 단언에서 요청 도착을 `expect.poll`로 기다리도록 보완했다. 요청 payload·저장 횟수·분석 미생성 단언은 유지했다. 최초 한 사례의 10회 통과 기록을 보존했고, 두 사례를 각각 10회씩 총 20회 반복해 재시도 없이 모두 통과했다. 이후 원격 CI 상태는 [PR #92 checks](https://github.com/catchhole-soma/catchhole-front/pull/92/checks)에서 확인한다.
