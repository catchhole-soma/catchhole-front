# 회차별 인물 관계도 화면·검증 (#323)

공통 데이터·운영 계약은 [회차별 인물 관계도 계약](episode-relationships.md)을 따른다.

## 화면과 출처

`/dashboard?workId=<id>&nav=graph`의 일반 진입은 인물 관계도를 열며, `relationMode=people`을 명시한 주소도 같은 화면이다. 탭은 왼쪽 `인물 관계도`, 오른쪽 `가계도` 순서다. 인물 관계도에서 분석한 회차를 선택한다. 기본은 최신 관계 분석이 반영된 회차다. 선택한 회차까지 드러난 이름, 관계 설명과 근거만 표시한다. 이전 회차를 고르면 당시 알 수 없었던 정체나 뒤 회차의 근거를 가져오지 않는다. 회차 선택 목록은 번호만 표시한다.

가계도는 `relationMode=family`로 열며 기존 가족 상세 URL·조회·후보 검토를 유지한다. 종류가 생략된 과거 가족 상세 링크도 가족 화면으로 열어 일반 기본값 변경으로 선택한 내용을 잃지 않는다. 두 종류의 공통 탭만 `RelationshipWorkspace`로 옮겼다. 인물 관계도에는 후보 확정·애매함 판단·필수 검토 목록을 만들지 않는다. 가족 후보를 인물 관계로 변환하지 않는다.

## URL과 조회

- `relationMode=people`: 인물 관계도. 명시한 종류가 다른 종류의 남아 있는 상세 상태보다 우선한다.
- `relationMode=family`: 가계도와 가족 관계 목록·확인·연결. 가계도 탭 선택은 이 값을 명시한다.
- 종류가 없는 일반 `nav=graph`는 인물 관계도다. 다만 기존 가족 상세 키인 `relationView`, `relationPage`, `familyFocus`, `familyHistory`, `relationshipCandidate`, `relationshipId`, `relationshipFactId`가 있으면 가족 화면으로 호환한다. 실제 가족 보기 키는 `relationView`다.
- 이전 `nav=settingDB&tab=relations` 또는 nav 없는 `tab=relations` 가족 링크는 명시적인 종류 선택을 존중하면서 가족 상세 상태를 보존해 `nav=graph`로 정규화한다. 가족 프로필 모달도 실제 선택된 종류가 가족일 때만 노출한다.
- `relationEpisode=N`: 이 회차까지의 관계. 없으면 최신 반영 회차.
- `relationFocus=<nodeId>`: 해당 인물과 직접 연결된 관계를 중심으로 보기.
- `relationEdge=<edgeId>`: 선택한 연결의 회차별 설명·인용을 바로 펼친다.
- 다른 메뉴로 나갈 때 가족·일반 관계 선택을 함께 정리한다. 명시적 관계 화면 OFF에서도 동일하게 제거한다.

생성 SDK의 `getEpisodeRelationshipGraph`와 `getEpisodeRelationshipEdge`를 사용한다. 회차는 Query key에 포함하고 이전 회차의 데이터를 placeholder로 사용하지 않는다. 최신 보기는 10초 갱신과 창 포커스 갱신을 사용한다. 특정 회차는 분석 중일 때만 주기 조회하며 포커스 갱신은 유지한다. 성공 응답이 없는 경우 예시 데이터로 대체하지 않는다.

서버가 회차 기준으로 제공한 노드 이름·프로필 등록 여부만 사용한다. 현재 캐릭터 목록·상세·이미지 API를 추가로 조회하지 않으며, 인물 카드는 해당 인물의 연결을 강조한다. 프로필 미등록도 근거가 명확하면 표시할 수 있지만 프론트가 동일 인물로 합치거나 프로필을 생성하지 않는다.

## 그림과 근거

현재 전체 보기 실험(2026-10-30)은 인물이 4명 이상일 때 연결 수가 높은 인물을 가로 중심축에 놓고, 각 중심축에 연결된 인물을 위·아래 부채꼴로 배치한다. 여러 중심축과 연결된 인물은 그 사이에 한 번만 표시하고 더 먼 인물과 연결이 적은 인물은 바깥에 놓는다. 중심축은 연결 구조에 따른 표시 기준으로, 주요 인물·진영·서열을 추론한 결과가 아니다. 중심축이 뚜렷하지 않은 경로형 묶음은 인접한 사람들을 가까이 두며 서로 연결되지 않은 묶음은 분리한다. 같은 입력은 API 배열 순서와 무관하게 같은 기본 좌표를 만든다.

전체 보기의 관계선은 곡선을 기본으로 사용하고 카드에 가로막히면 필요한 구간만 둥근 대각 경로로 우회한다. 중심축 카드는 연한 파란색으로 구분하고 관계 이름은 테두리 없는 흰 바탕으로 표시한다. 여러 선이 만나는 큰 그래프에서 모든 교차나 공유 구간이 사라진다고 보장하지 않으며 각 관계는 라벨과 목록에서 따로 선택한다. 이전 stress 배치·1.8배 좌표 확대·13개 이상 직교 경로 분기는 아래의 과거 실험 기록이며 현재 전체 보기 정책이 아니다.

인물이 3명 이하이면 기존 방사형 배치와 곡선을 유지하여 두 사람의 복수 관계를 좌우로 읽게 한다. 특정 인물 중심 보기에서는 선택한 인물을 중심에 두고 연결이 가장 많은 상대를 왼쪽에 놓는다. 같은 상대와 연결된 관계가 많을수록 주변 각도에 더 넓은 공간을 배분한다.

배치를 계산할 때만 연결을 방향 없이 다루며 위치의 높이·좌우는 가족 관계나 서열을 뜻하지 않는다. 원본 인물·관계 ID와 같은 쌍의 여러 관계를 모두 유지한다. `DIRECTED`는 한 방향 화살표, `MUTUAL`은 양방향, `UNDIRECTED`는 화살표 없는 선이다. 종료된 관계는 점선과 `종료` 표기를 함께 사용한다.

관계의 짧은 이름을 누르거나 그림 아래 목록의 두 인물을 누르면 같은 근거를 펼친다. 상세는 두 이름을 동일하게 강조하고 설명, 회차, 실제 인용을 같은 흰 표면에 표시한다. 근거 안에 또 다른 근거 버튼을 넣지 않는다. 키보드로 접근 가능한 목록은 작은 화면의 대안도 된다.

회차를 바꾸면 현재 선택과 중심 인물을 정리한다. 같은 회차를 갱신하거나 연결을 선택할 때에는 확대·이동 위치를 초기화하지 않는다. 회차·중심 인물 또는 화면 크기가 바뀔 때 해당 범위의 보기 영역을 다시 맞춘다. 4명 이상 전체 보기의 최초·초기화 화면은 최소 0.6배를 유지하며, `전체 보기` 도구를 누르면 카드·선·라벨 전체를 맞춘다. 중심 보기와 3명 이하 전체 보기는 기존 전체 맞춤을 유지한다. 인물 카드를 끌면 화면 안의 위치와 연결 각도가 바뀌고 드래그 중에도 모든 관계선과 연결점을 유지한다. 같은 회차의 갱신·근거 선택에서는 이동 위치를 유지하며, 새로고침·회차/중심 인물 변경 또는 `배치 초기화`에서 기본 배치로 돌아간다. 배치는 브라우저 메모리에만 두며 서버 관계를 수정하지 않는다.

## 선택적 정정

`설명 수정`은 AI가 잘못 읽은 설명을 정정하는 행동이다. 작품 속 관계의 실제 변화·종료를 입력하는 기능이 아니다. 서버의 `expectedVersion`과 함께 저장하며 모든 회차의 해당 관계 설명에 적용됨을 편집창에서 알린다.

`이 연결 삭제`는 인물이나 원문을 지우지 않고 잘못된 연결을 모든 회차에서 제외한다. 확인 후 DELETE를 한 번 실행하고 서버의 자동 복원 방지 기록을 유지한다. 저장 실패와 409에서 초안을 보존한다. 409에서는 최신 내용을 조회한 뒤 사용자가 `변경 내용 확인`으로 기준 버전을 받아들여야 재시도할 수 있다. 조회만으로 버전이나 초안을 자동 채택하지 않는다. 세션 변경·이탈 뒤 늦은 mutation 응답으로 화면을 변경하지 않는다. 생성 Query key에 인증 세션 태그를 붙이고 비활성 캐시를 즉시 정리해 다른 계정에 직전 이름·근거를 재사용하지 않는다.

### 실제 브라우저 → Spring → 격리 PostgreSQL

`e2e/episode-relationships-live.spec.ts` 1개가 실제 API로 통과했다. Backend 전용 테스트에서 만든 두 회차·세 인물의 합성 작품만 사용했으며 기존 로컬 DB와 사용자 작품은 변경하지 않았다.

- 최신 2화에서 관계 3개, 1화에서 당시 활성 동행 1개와 인용 1개만 표시했다. 2화의 새 인물 세린·관계 종료 상태가 1화에는 노출되지 않았다.
- 2화의 아라 → 보라 경계 설명을 화면에서 수정해 PATCH 200을 확인했다. 브라우저 새로고침과 별도 GET에서 동일한 정정값을 다시 읽었다.
- 아라 ↔ 세린 친구 연결을 화면에서 삭제해 DELETE 200을 확인했다. 새로고침과 별도 GET에서 해당 연결이 제외되고 나머지 2개 관계와 정정값이 유지됐다.
- 실제 Backend가 발급한 테스트 JWT를 로컬 저장소에 넣었고 브라우저 관계 요청의 Bearer 전송을 확인했다. 이 검증은 로그인·refresh 쿠키 발급을 다시 실행한 테스트가 아니며, 주입 방식상 refresh 쿠키가 없음을 확인했다.
- 재현은 격리 fixture를 새로 만든 뒤 `VITE_API_BASE_URL=http://localhost:18233 CATCHHOLE_E2E_PORT=3324 CATCHHOLE_RELATIONSHIP_LIVE_FIXTURE=<0600 fixture JSON 경로> npx playwright test e2e/episode-relationships-live.spec.ts --workers=1`로 실행한다. fixture 경로를 생략하면 테스트는 건너뛴다. 테스트는 합성 연결을 수정·삭제하므로 기존 작품에 사용하지 않는다.
- 이 브라우저 테스트는 관계 LLM 추출 품질을 평가하지 않는다. Worker 실호출과 DB 행 직접 확인은 Backend·AI 검증 기록을 함께 본다.

Backend가 격리 DB 행도 직접 확인했다. 경계 연결은 `corrected_summary`에 정정문과 `version=2`가 저장됐고, 친구 연결은 `suppressed=true`, `version=2`였다. 실제 화면 캡처는 [1화](screens/gh323/episode-relationships-live-episode-1.png)와 [저장 후 근거](screens/gh323/episode-relationships-live-correction.png)에 있다.

### 2026-10-29 복수 관계 겹침과 드래그 개선

같은 두 인물 사이의 상호 관계와 양쪽 일방 관계를 독립적으로 유지한다. 방향만으로 3개를 상한으로 두지 않으며 여러 종류의 관계도 각각 보존한다. 카드의 가로폭에 맞춘 타원 배치와 라벨의 제한된 너비·두 줄 높이를 기준으로 공간을 확보한다. 선은 별도의 곡선을 사용하고 카드 경계의 연결점을 나누며, 라벨은 다른 라벨·카드와 겹치지 않는 위치를 고른다. 긴 이름은 두 줄 뒤 생략하고 전체 이름은 title·접근성 이름과 근거 상세에서 확인한다.
