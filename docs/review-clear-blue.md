# Clear Blue 후보 검토 · GH215

승인된 시안의 흐름을 실제 캐릭터·세계관 API에 연결한다. 검토 시안의 43개 항목은 43개의 새 페이지가 아니라 후보 상태·그룹 상태·조회 및 저장 오류의 조합이다. 기존 분석 진행 화면과 겹치는 상태는 검토 잠금 안내와 기존 화면 이동으로 통합한다.

관련: catchhole-soma/catchhole-backend-java#215, 선행 조사 #211.

## 공통 표현과 데이터 경계

- `review-ui/ReviewPrimitives.tsx`: 사진 제목, 결과가 보이는 선택 카드, 값 비교, 원문 펼침, 짧은 상태 안내.
- `review-text-diff.ts`: 한글·공백·줄바꿈을 유지하는 표시 전용 diff. 계산량이 큰 값은 공통 앞뒤를 보존하고 변경 구간을 강조한다. 저장값 생성에는 사용하지 않는다.
- `ReviewSubjectThumbnail`: 실제 연결 ID가 있는 대상만 기존 생성 SDK와 Query 캐시로 이미지를 조회한다. 같은 ID는 공유하며 신규 대상은 기존 기본 이미지를 사용한다. 개인 이미지 URL은 기존 인증 이미지 컴포넌트로 처리한다.
- `review-clear-blue.css`: Theme V2 토큰 기반, 원문과 최종값의 대비, 모바일/키보드 조작. 기존 시안 및 공유 HTML은 수정하지 않는다.
- 빨강/초록은 실제 변경, 노랑은 미결정 비교, 중립은 제외·이력·실패 등 변경을 단정할 수 없는 상태다.
- 시안의 이름·수치·사진은 운영 데이터가 아니다. 대상 후보 목록이 응답에 없는 경우 기존 대상을 실제로 검색/조회하여 선택한다. 결과를 AI 추천으로 소개하지 않는다.

## 검증 기준

확정 단위는 그룹 전체이며 개별 확정 버튼을 추가하지 않는다. 기본 필터는 미처리다. 대상 연결과 내용 결정은 서로 다른 작업이며, 사용자 선택을 서버가 받아들인 이후에만 준비 완료로 표시한다. 원문·버전·현재값 보호·이력 저장·공유 결정의 원자성과 숨겨진 후보 보호를 유지한다.

## 서버에 보관하는 캐릭터 선택

완료된 순차 분석 후보의 저장 방식을 `reviewedApplicationMode`로 저장한다. PATCH와 이 선택의 confirm에는 마지막 응답의 `updatedAt`을 `expectedUpdatedAt`으로 보낸다. 내용·대상·현재값의 비교 기준이 달라지면 다시 확인한다. 단순 대상 연결에서 서버가 안전하다고 판단해 준 선택만 추가 확인 없이 이어받는다. `userModified` 자체를 내용 판단 완료로 사용하지 않는다.

초안을 고르는 동안 원래 `temporalScope`는 보존한다. 실제 확정에서 현재값 반영을 선택한 경우에만 현재 시점으로 적용한다. 최신 회차·작가가 직접 변경한 값·삭제 이력에 대한 보호는 그대로다. 따라서 현재 반영을 선택했더라도 서버가 `historyOnly=true`로 확정하면 현재값을 바꿨다고 표시하지 않는다.

V72 마이그레이션과 새 프론트는 함께 배포해야 한다. 이전 클라이언트에서 로컬 확인만 하고 확정하던 완료된 순차 후보는 새 서버에서 선택 저장이 필요하다. 자세한 서버 검증은 Java 저장소의 `docs/gh215-review-decision.md`를 참고한다.

### 실제 HTTP 검증을 재현하는 방법

기존 로컬/운영 DB와 격리한 Spring+H2 서버에서만 수행한다. LLM 추출 성능이나 운영 원고를 시험하는 것은 아니다. 이 fixture는 실제 확정으로 소비되므로 다시 실행할 때 서버를 새로 시작한다.

1. Java 저장소에서 `GH215_REVIEW_RUNTIME=true ./gradlew test --tests '*ReviewUxHttpRuntimeTest'`를 실행한다. 로컬 API는 18081이며 fixture가 준비될 때까지 기다린다.
2. 프론트에서 `VITE_API_BASE_URL=http://127.0.0.1:18081 npm run dev -- --port 3100 --strictPort`로 별도 확인 서버를 실행한다.
3. `CATCHHOLE_REVIEW_LIVE_FIXTURE=/tmp/gh215-review-runtime.json npx playwright test e2e/review-clear-blue-live.spec.ts --workers=1`로 검증한다. 기존 기본 개발 서버/테스트 webServer와 함께 사용할 수 있다.
4. 테스트 계정 인증 정보가 담긴 fixture 파일을 로그·문서·커밋에 붙이지 않는다. Java 테스트의 종료 파일로 해당 테스트 서버만 종료한다.

실제 HTTP 검증은 세계관의 합친 최종 문자열→새로고침→그룹 확정→현재값 재조회, 캐릭터의 현재/이력 선택 전환→초안 재조회→낡은 후보 저장 409→그룹 확정→현재값 재조회, 인물 선택 카드와 320px을 검사한다. 실제 PostgreSQL Flyway/JPA 검증은 Java 저장소 테스트로 별도로 수행한다.

### 실제 컴포넌트 캡처

- 실제 Spring fixture: `world-scope-choice.png`, `character-semantic-choice.png`, `character-target-choice.png`, `character-mobile.png`.
- 상태별 목 API: `character-diff-1280.png`, `character-diff-320.png`, `character-targets-1280.png`, `character-targets-320.png`.

미정인 계약도 있다. 인물 목록은 당시 API의 페이지 단위로 탐색했다(2026-10-31 #211 후속 2차부터 연결 모달은 `GET /characters?query=` 서버 이름 검색으로 작품 전체를 찾는다). 어느 쪽이든 AI 추천 후보가 아니다. 세계관도 실제 등록 대상 목록을 사용한다. 구조화된 충돌 `sourceValues`가 없으므로 원문 한 줄씩을 별개의 대안으로 제시하지 않고 최종값 편집을 제공한다.


## 후속 수정: 확정 전 재선택과 스크롤 유지 · 2026-10-02

### 선택 저장은 최종 확정이 아니다

세계관의 포함/별도 저장, 병합/교체 선택은 검토 초안이다. 초안을 저장해도 선택 카드를 유지하고, `모두 확정` 전에는 다시 선택하거나 최종 내용을 수정할 수 있다. 재선택은 이전에 합친 초안이 아니라 최초 추출값과 비교값에서 다시 계산하므로 같은 문장이 반복해서 붙지 않는다. 같은 비교 결정의 여러 원문은 한 요청에서 함께 변경한다. 서버의 최종 확정·원고 변경·현재값 보호 검증은 유지한다.

대상 동일성 확인에서는 다른 실제 대상으로 연결한 뒤에도 다시 고를 수 있다. 선택한 대상에 같은 속성이 있으면 그 대상의 현재 설정을 조회하여 병합/교체를 제시한다. 이전 대상의 비교값을 새 대상에 섞지 않는다. 일반 범위 결정에는 불필요한 대상 검색을 추가하지 않는다. 확정·제외된 후보는 이 재선택 대상이 아니다. 기존 범위의 연쇄 이동 제안은 작가 수정 후 비활성화되는 기존 보호 규칙을 유지한다.

캐릭터의 현재 설정/이력 선택은 이미 재선택 가능하며, 기존 캐릭터 변경 경로도 유지한다. 이번 수정으로 개별 확정 버튼을 추가하지 않는다.

### 비교표의 양쪽 본문 시작점

기존 범위·설정명과 선택한 범위·설정명을 양쪽에 표시하고 제목, 경로, 본문을 같은 행 높이로 맞춘다. 한쪽 경로가 길게 줄바꿈되거나 한쪽만 메타데이터가 있어도 비교 본문의 시작점이 어긋나지 않는다. 모바일과 `한 줄씩` 보기에서는 세로 배치를 사용하고 빈 보조 행은 생략한다.

### 상위종 / 분류 기준은 기존 case 09

실제 로컬 후보는 원문 추출과 회차 처리가 끝났지만 `FAILED / COMPARISON_VALIDATION_FAILED` 상태로, 유효한 비교 결과를 받지 못했고 `manualReviewAvailable=true`인 사례였다. 일부 비교 시도에는 이미 식별한 대상 참조가 응답에서 빠진 `CANONICAL_TARGET_REQUIRED` 진단이 있었다. 모든 시도의 상세 원인이 남아 있는 것은 아니므로 전체 실패 원인을 같은 것으로 단정하지 않는다.

이는 새 설정이라고 판단한 결과도, 내용이 충돌한다고 판단한 결과도 아니다. 시안 09의 비교 실패 후 직접 검토에 해당한다. 구현이 처음부터 큰 수정 폼을 노출해 사용자가 무엇을 해야 하는지 알아보기 어려웠다. 이제 원문 내용과 `이 내용 그대로 추가` / `내용·저장 위치 수정`을 먼저 보여 주고, 수정할 때만 입력 폼을 연다. 기존값이 없다고 단정하지 않으며 비교를 마치지 못했다는 안내와 원문 근거는 보존한다. 추가 선택은 수동 초안 저장이며 LLM 재실행이 아니다.

### 왼쪽 대상을 바꿀 때 스크롤이 위로 튀던 원인

같은 페이지의 대상 전환에서 화면 전체가 재생성되거나 목록을 다시 조회한 것은 아니었다. 긴 상세가 짧은 상세로 바뀌면서 공통 스크롤 영역의 높이가 줄어들었고, 브라우저가 기존 위치를 새 최대 스크롤값으로 강제 조정했다. 1440px 높이에서는 캐릭터·세계관 모두 `scrollTop 550 → 0`을 재현했다.

데스크톱에서 대상 전환 직전에 현재 화면을 유지하는 데 필요한 최소 높이만 확보한다. 위로 스크롤하면 확보한 높이를 줄이고, 맨 위·창 크기 변경·필터/페이지 변경 때 해제한다. 목록과 상세를 전환하는 모바일에는 적용하지 않는다. 목록 재조회나 강제 스크롤 복원 반복을 추가하지 않는다.

### 추가 검증

- 검토·자동 반영·순차 복구·세계관 범위·스크롤 관련 회귀 157개 통과. 마지막 대상 변경 보호 보완 후 세계관 중심 21개 재검증 통과. 숫자는 중복 실행을 포함하므로 합산한 고유 테스트 수가 아니다.
- 새로고침 후 병합↔별도 저장, 다른 대상에서 병합↔교체, 공유 원문 원자성, 원본 실패 보존, 비교표 정렬, 긴 상세→짧은 상세의 스크롤 유지와 높이 해제를 확인했다. 표시용 캡처는 목 API와 실제 React 컴포넌트로 만들었다.
- 공개 체험·랜딩·안내 관련 43개 중 최초 실행 42개 통과, 안내 모달 Escape 닫기 1개 타임아웃. 해당 사례를 코드 변경 없이 단독 3회 실행해 모두 통과했다. 후속 수정과 직접 관계없는 간헐 실패로 기록하며 최초 실행 전체 통과로 보고하지 않는다.
- `lint`, `typecheck`, `build`, `check:unused` 통과. 기존 Fast Refresh·번들 크기 경고와 Doctor의 기존 진단은 앞 절과 동일하다. 마지막 대상 변경 보완 후 typecheck·ESLint도 다시 통과했다.
- 실제 로그인 화면은 읽기 전용으로 확인했으며 이번 후속 점검에서 사용자 후보를 확정·제외하지 않았다. 서버 코드와 DB 스키마는 이 후속 수정에서 변경하지 않았다.

### 로컬 직접 검수에서 발견한 추가 수정 · 2026-10-02

- 최초 요약 API 응답 전에는 `0개`나 `대상 회차 없음`으로 단정하지 않고 확인 중으로 표시한다. 한쪽 후보 집계만 도착한 경우에도 부분 합계를 전체로 표시하지 않는다. 실제 빈 결과만 0개이며, 캐시가 있는 배경 재조회에서는 기존 집계를 유지한다.
- 비교 실패 후 수동 초안을 저장한 후보만 남았다면 그룹·목록도 확정 준비됨으로 표시한다. 이미 저장했는데 다시 저장하라는 안내를 반복하지 않는다. 처리 중·사용량 부족·재비교 상태의 잠금은 유지한다.
- 저장한 초안을 인라인에서 다시 수정하면 미저장 상태를 그룹에 전달한다. 변경을 저장하거나 취소하기 전에는 `모두 확정`을 잠가, 화면에 보이는 입력과 다른 이전 초안이 확정되지 않게 한다. 재저장 실패에도 입력과 잠금을 유지한다.
- 한 종류의 검토를 먼저 마치면 빈 대상을 선택하라는 안내 대신 완료 상태와 남은 종류로 이동하는 버튼을 표시한다. 필터 때문에 목록만 비어 있는 경우와 서버 집계상 실제 검토 완료를 구분한다.
- 새 인물 발견 후보를 기존 인물에 연결하면 `인물 연결 / 연결된 인물`로 표시한다. 이미 연결했는데도 새 인물을 등록한다고 오해시키지 않는다.
- 비교가 완료된 `EXCLUDE` 후보는 기존 서버의 그룹 확정 계약에 따라 묶음에 함께 포함한다. 카드에 `모두 확정하면 이 후보는 제외돼요`, 하단에 반영·제외 개수를 표시한다. 단건 확정과 비교 미완료·현재값 버전·인물 연결·형식 검증은 유지한다. 개별 제외로 같은 인물 전체를 재비교하던 불필요한 동선을 줄인다.
- 일반 직접 검토의 현재값/이력 선택은 캐릭터와 세계관 탭의 공통 부모에서 보관한다. 탭 왕복 후 선택을 잃지 않으며, 작품·업로드 묶음 변경과 인물 재연결 시 기존 초기화 규칙을 유지한다. 브라우저 새로고침 이후까지 저장하는 서버 계약을 추가한 것은 아니다.
- 여러 원문을 통합한 `MERGED`에서도 교체값에는 이번 추출 원문 전체를 사용한다. 병합에만 기존 내용이 포함된 AI 최종 제안값을 사용한다. 같은 결정을 공유하는 여러 후보도 원문을 빠뜨리지 않으며 `CONFLICT`의 직접 확인은 유지한다.
- 통합된 신규/관련 브라우저 테스트 67개, typecheck, lint, build, check:unused 통과. lint에는 기존 Fast Refresh 경고 2개가 남아 있다. 앞의 30개 검증을 포함하는 재실행이므로 테스트 수를 합산하지 않는다.

요청한 실제 검수 범위는 새 작품에 1~5화를 한 회차씩 업로드하고 매번 `모든 설정 직접 검토`로 분석·확정하는 흐름이다. 기존 작품 후보를 살펴본 점검과 이 흐름을 구분한다. 최초 1화의 인증 실패는 로컬 자격 증명 갱신 후 재시도로 복구했다. 실제 1~4화 검토를 완료했다. 4화에서 비교 작업은 성공했지만 후보 5개가 PENDING에 남는 서버 문제를 재현·수정했다. 비교 입력 해시는 원문 순서를 사용하고 배치 배정 순서와 분리하며, 실제 입력 변경 감지는 유지한다. 수정 전 실패한 회귀를 포함한 Java 관련 406개 테스트와 빌드를 통과했고, 같은 인물에 다시 연결하는 일반 UI 경로로 5개 비교 완료·그룹 확정까지 확인했다. 원고 전체 재분석이나 DB 강제 상태 변경은 하지 않았다. 이후 5화까지 직접 검토를 마쳤고, 성공한 추출 작업은 모두 `CONFIRMED_ONLY + MANUAL`, 자동 반영 시각은 NULL임을 DB에서 확인했다.

실제 검수에서는 새 인물 등록, 미상→기존 인물 연결, 원문 펼침, 현재값/이력 선택과 탭 왕복, 숫자 갱신, 상태 종료, 중복 제외를 포함한 그룹 확정, 세계관 병합↔교체 재선택을 수행했다. 5화 미궁의 여러 원문을 정리한 조명 환경에서도 교체는 이번 내용만, 병합은 기존 정보와 이번 내용을 함께 보여 주는 것을 확인했다. 3화의 병약했던 과거 묘사와 5화의 치료 전 출혈은 이력만 저장하도록 검토했다. 5화의 오른발 부상 종료와 정신 35→36, 전투지수 67→68을 선택해 확정했으나, 최종 DB 대조에서 현재값 보호로 이력에만 남은 것을 발견했다.

추가 원인은 앞 회차 후보를 기존 인물에 연결할 때도 `userModified=true`를 기록하고, 뒤 회차 확정에서 이를 내용의 직접 수정으로 해석하던 서버 로직이었다. 이름만 수정한 설정집 편집 때문은 아니었다. Java는 V73의 nullable `user_content_modified`로 내용 수정과 연결/검토 선택을 구분한다. 새 후보는 false, 실제 내용 수정은 true이며 기존의 미구분 NULL은 기존 보호를 유지한다. 기존 NULL 후보도 아직 수정된 적이 없다면 최초 연결 시 false로 구분하고, 이미 수정 여부가 섞인 NULL/true는 추정하지 않는다. 같은 회차·뒤 회차·설정집 직접 수정·출처 불명·삭제된 현재값 보호는 그대로 둔다.

이 검수 작품에서 이미 확정된 5화의 세 후보는 당시 결과를 보존했다. 정신/전투지수 현재값은 여전히 35/67이고 오른발 부상 현재값도 남아 있으며, 해당 5화 제안은 이력에 저장되어 있다. **75개 확정은 현재값 75개가 바뀌었다는 뜻이 아니다.** 기존 기록에 내용을 수정했는지 소급 추정하거나, 확정된 후보를 강제로 재반영하지 않았다. 사용자가 명시한 출혈의 이력 저장과 서버 보호로 이력이 된 세 후보를 구분한다.

이 수정은 관련 Java 552개 회귀와 별도 PostgreSQL V1~V73 마이그레이션/JPA 검증 2개, bootJar를 통과했다. 마지막 기존 미수정 후보의 최초 연결 경계 보완 후 Entity·수동 보호 통합 95개를 재검증해 모두 통과했고, bootJar와 로컬 Java health UP도 다시 확인했다. 이는 앞의 552개와 중복되는 재실행이므로 합산하지 않는다.

세계관에는 같은 문제가 없었다. 검토 초안은 `final*`만 바꾸고, 설정집에서 직접 고친 경로는 별도 `manually_edited_paths`로 보호한다. 실제 바바리안 전투 강점의 3→4화 병합과 미궁 조명 환경의 4→5화 병합 모두 `history_only=false`이며 현재값에 정상 누적됨을 확인했다.

다음은 화면 수정으로 해결된 것으로 보고하지 않는 AI/데이터 과제다.

- **동적 설정명 중복:** `profile.가족_관계`와 `profile.가족관계`처럼 뜻이 같은 이름이 서로 다른 키로 추출될 수 있다. 이번 검수에서는 중복을 제외했다. 모든 구분자를 제거하는 식의 광범위한 정규화는 하지 않았다.
- **이름 연결 기억:** ‘주인공’에 ‘비요른’을 연결해도 별칭으로 영구 저장되지 않아 다음 회차에서 다시 새 인물로 나왔다. 3화 이후 동일 인물의 표시 이름을 정상 UI에서 ‘비요른’으로 바꾸어 검수를 이어갔다. 별칭 자동 학습을 구현한 것은 아니다.
- **비교 응답 검증 실패:** 3화 아이나르의 가족 관계는 재시도 후에도 유효한 비교 결과를 얻지 못했다. 기존 설정과 동일한 내용임을 직접 대조해 제외했다. 이 사례를 정상 비교 성공으로 계산하거나 검증 규칙을 완화하지 않았다.
- **회차 안의 시점 판단:** 5화에서 치료 후 부상 종료를 제안하면서도 앞 장면의 출혈은 현재 상태 추가를 제안했다. 원문 흐름을 확인해 출혈을 이력으로 선택했다. 상태 간 시점 일관성은 추출·비교 품질의 후속 검토 대상이다.
- **개인 사례의 과잉 일반화:** ‘나는 방패 하나만 가진 바바리안’이라는 개인 장비 설명이 종족 전체의 전투 특성으로 제안됐다. 해당 세계관 후보는 제외했으며 기존 종족 설정은 유지했다.

원래 작품을 대상으로 앞서 수행했던 점검 변경은 백업과 대조해 선택적으로 복원했고, 새 검수 작품의 1~5화 결과는 남겼다. 실제 검수 완료는 이 한 작품·다섯 회차의 결과이며 모든 작품의 AI 응답 정확도를 보장하는 검증은 아니다.

## 2026-10-03 캐릭터 조작 정리와 전체 재비교 원인

현재 반영·이력 선택 카드의 하단 반복 띠를 없애고, `캐릭터 연결 변경 → 수정 → 제외`를 제목 옆에 배치했다. 별도의 연결 작업 행은 제거했다. 기존 인물 선택과 새 인물 등록은 같은 연결 모달에서 제공하며, 미상 인물의 직접 선택 카드는 유지한다. 등장 후보의 연결/신규 정보는 기존 인물 표시 영역에 남긴다. 일반 선택은 확정 전 다시 바꿀 수 있고 실제 저장은 기존 그룹 확정 계약을 따른다.

**기존 원인:** 한 후보를 수정·제외하면 서버의 묶음 비교 정책 때문에 같은 인물 전체가 비교 중으로 바뀌었다. 아래 원인 분석 이후 사용자가 최종 결과 존중 정책을 선택하여 수정했다. 단일 회차 직접 검토의 `CONFIRMED_ONLY` 경로에서 확인했다.

1. `SettingCandidateServiceImpl.dismissSettingCandidate`는 후보를 제외한 뒤 `enqueueScopes`로 이전 비교 대상을 다시 예약한다. 내용이 실제 바뀐 수정도 `enqueueIfNeeded`로 이어진다. 내용이 동일한 PATCH나 단순 현재/이력 선택이 항상 이 경로를 타는 것은 아니다.
2. `CharacterFactComparisonJobCoordinator`의 범위는 업로드 묶음과 연결된 캐릭터 ID(미연결이면 정규화한 이름)이다. 같은 설정 키나 FactType까지만 좁히지 않는다. `schedule`은 이 범위의 남은 후보에 `requestComparison`을 호출해 비교 결과·검토 결정을 초기화하고 새 AI 비교 작업을 만든다. 다른 인물이나 모든 뒤 회차를 재분석하는 동작은 아니다.
3. 화면의 `CharacterReviewComparison`은 서버 상태가 `PENDING/PROCESSING`이면 선택 카드를 숨기고 비교 안내를 표시한다. 그룹 확정도 최신 제안이 없으므로 잠긴다. 수정·제외 HTTP 요청 중에는 `actionPending` 때문에 다른 저장 버튼도 잠시 잠긴다. 원문·탐색까지 AI 비교 완료를 기다려야 한다는 뜻은 아니다.
4. 앞 후보의 제안을 뒤 후보의 비교 문맥에 누적하기 때문에, 예를 들어 앞의 ‘소속 A’를 제외하면 이를 바탕으로 작성한 뒤의 병합 문장을 그대로 적용하면 안 된다. 이 의존성을 보호하려는 목적은 유효하지만, 무관한 설정까지 같은 범위로 재비교하는 현재 단위는 지나치게 크다.
5. 단순히 `enqueueScopes`를 빼면 안전한 최적화가 되지 않는다. 확정 시 `CharacterFactComparisonBatchWorker.hasCurrentContext → requireCurrentGroupInput`이 후보 ID·내용·대상 등이 포함된 전체 입력 hash를 다시 확인한다. 하나를 제외한 것만으로 hash가 달라져 `SETTING_CANDIDATE_COMPARISON_STALE`이 발생한다. 완료된 중복 제외 제안도 이 계약부터 조정해야 개별 제외 후 결과를 재사용할 수 있다.

### 적용한 계약: 같은 회차의 최종 결과 존중

완료된 한 회차의 직접 검토는 수정한 값과 화면에 남은 최종 제안을 그대로 그룹 확정한다. 한 후보 수정·제외로 다른 후보의 비교 상태·문장·선택을 초기화하지 않고, 확정에서도 AI 입력 hash 변화나 같은 회차 선행 후보 제외를 이유로 재비교하지 않는다. 수정한 값은 서버의 검토 초안으로 저장되어 새로고침 후에도 이어진다.

예를 들어 A를 제외해도 B의 병합 문장에 있던 A 관련 표현을 자동 삭제하지 않는다. 사용자는 B에 실제 표시된 최종 문장을 승인하며 필요하면 B도 수정한다. 상태 제거의 대상이 앞선 제외로 없어졌다면 이미 없는 상태를 다시 제거하는 작업은 아무 변경 없이 완료한다.

현재 원문, 후보별 수정 시각, 실제 캐릭터 snapshot, 값 형식, 그룹 전체 요청, 후행 회차·직접 수정값 보호는 유지한다. 다른 캐릭터 연결은 기존 대상 비교를 다시 진행한다. 여러 원본 Job이 섞인 구형 그룹과 자동 순차 분석은 이번 단일 회차 계약과 구분한다. 프론트가 `acceptDisplayedResults=true`와 모든 후보의 시각을 보내고 서버가 완료된 동일 수동 Job인지 확인한다.

검증(이번 추가): Java 관련 회귀 580개를 통과했고 실패 우회 방지 보완 후 수동 검토·현재값 보호 91개를 다시 통과했다. 새 시나리오를 합친 고유 회귀 수는 581개다. 프론트 수정·제외·확정 및 자동 반영 잠금 회귀는 고유 105개 통과. 별도 H2 실제 HTTP 서버에서 브라우저로 수정 → 제외 → 새로고침 → 그룹 확정도 확인했다.

검증: 캐릭터·연결·자동 처리 잠금 회귀 102개 중 제거된 문구와 과거 로딩 화면을 참조하던 테스트를 갱신하여 모두 통과했다. 랜딩·공개 체험 18개, 첫 안내 8개도 통과했다(총 128개, 캡처 재실행은 중복 집계하지 않음). 별도 실계정 최초 안내 live 테스트 1개는 환경 조건이 없어 건너뛰었다. 320px에서 가로 넘침 없이 선택을 다시 바꾸고, 연결 모달에서 신규 이름을 제출할 때 기존 `CREATE_NEW` 계약을 사용하는 것을 확인했다. lint(기존 경고 2개)·typecheck·build·unused 검사를 통과했다. 실제 로컬 6화 화면에서 제목 버튼과 신규 등록 모달을 열어 확인했으며 해당 6화 후보는 수정·제외·확정하지 않았다. 구현 화면 모음의 대표 캐릭터 비교 캡처도 갱신했다.

## 추가 범위: 소개·체험·첫 업로드 안내

사용자 후속 요청에 따라 랜딩의 검토 예시, 로그인 없이 체험하기, 첫 업로드의 5단계 안내를 실제 Clear Blue 검토와 맞췄다.

- 새 캡처는 `docs/screens/gh215/landing-*`, `demo-*`, `analysis-guide-*`이며 [실제 구현 화면 모음](review-clear-blue-preview.html)에서 확인한다. 제품은 이 캡처를 표시하지 않고 컴포넌트를 렌더링한다.

`.pen` 연결은 `transport not connected to app: visual_studio_code`로 사용할 수 없었다. `.pen`은 수정하지 않았으며 `design/PENCIL_MIGRATION.md`에 동기화 대기를 기록했다. 현재 기준은 새 React 화면과 구현 캡처이며 연결 복구 후 Pencil 참고 프레임을 동기화한다.

확정 후 결과 조회에서 제외된 후보에 재비교 안내가 남던 표시도 제거했다. `snapshotChanges.before`는 조회 시 현재 snapshot이므로 확정 완료 카드에서는 이를 과거의 반영 전 값으로 표시하지 않고 저장된 결과를 표시한다. 이력·제외 카드의 현재값 유지 안내와 원문 근거는 유지한다. React Doctor 전체 검사는 기존 WorldSettingDatabase의 진단 2개 및 maintainability 검사 일부 미완료가 남아 통과로 집계하지 않는다.

## 2026-10-03 실제 6화 검토 → 7~11화 자동 분석

앞의 6화 조회 점검 이후, 사용자 요청으로 같은 로컬 QA 작품에서 실제 후보 수정·제외·확정과 다회차 업로드를 수행했다. localhost:3000, 로컬 Java/PostgreSQL과 실제 AI Worker를 사용했다. 원고 업로드와 검토 변경은 브라우저에서 수행하고 DB는 결과 대조에만 사용했다.

### 6화 직접 검토

- 캐릭터 부상 설명을 수정하고 현재 반영↔이력 선택을 바꾼 뒤 새로고침하여 저장된 결정을 확인했다. 중복 종족 후보를 제외해도 다른 후보는 비교 중으로 바뀌지 않았고 그룹 확정이 가능했다. 수정·제외 직후 해당 두 후보 외의 행과 수정 시각이 그대로였으며 신규 AI 비교 Job은 0개였다.
- 세계관의 범위 미정 조명 설정을 기존 1층에 포함하도록 선택한 뒤, 최종 문장의 중복을 직접 정리하여 확정했다. 같은 대상의 두 설정 중 하나를 제외한 뒤에도 남은 설정을 재비교 없이 확정했다.
- 최종 결과는 캐릭터 11개 확정/3개 제외, 세계관 11개 확정/1개 제외로 총 22개 확정/4개 제외/미처리 0개다. 4개 제외 중 2개는 이번 검수 전에 이미 제외되어 있던 후보다.
- 수정한 부상 설명은 Fact 이력에 저장되었다. 이 작품에는 V73 이전의 내용 수정 여부를 구분할 수 없는 수동 수정 근거가 있어 기존 현재값 보호가 적용되었다. 현재 반영을 선택해도 현재값을 바꾸지 않는 기존 정책이며, 완료 카드의 `현재 설정은 유지하고, 이 회차의 이력에 저장했습니다.` 안내도 재진입하여 확인했다. 이를 현재값 갱신 성공으로 집계하지 않는다.
- `내용을 고쳐 다시 비교`라는 선택 문구는 재비교를 하지 않는 직접 검토 저장과 맞지 않아 `현재 반영할 내용 수정`으로 변경했다.

### 7~11화 다회차 자동 분석

- 연결 미리보기: 인물을 고르면 `GET /characters/{id}`로 이름·역할·첫 등장·나이/레벨, `대상에 저장된 현재 설정`(프로필 상위 3개), `이 설정의 기존값`을 보여 준다. 기존값은 후보 key(`resolvedCanonicalFactKey` → `comparisonTargetFactKey` → `attributeName`, 나이·레벨은 상세 필드)로 찾고, 없으면 표시명으로 한 번 더 찾는다. 서버 비교 결과가 아니므로 비교 표현을 쓰지 않는다. 모달 맨 위에는 무엇을 연결하는지(`설정명 · 이번 값 · N화`) 요약한다.
- 캐릭터 선택 연결: 대기 카드의 체크박스와 `모두 선택(N)`으로 고른 설정만 `선택 항목 연결`에서 기존 인물 또는 이름을 입력한 새 인물에 연결한다(D5). 화면에 그려진 대기 후보만 체크할 수 있어 필터로 숨은 후보는 요청에 들어가지 않는다. 성공하면 단건 연결과 같이 읽던 묶음·스크롤을 유지하고 `N개를 ‘이름’에 연결했어요`·`연결한 묶음 보기`를 안내하며, 묶음이 비면 직전 목록 순서의 다음 미처리 묶음을 연다. 거절되면 `error.context.candidateIds`의 카드만 표시하고 선택과 모달 입력을 유지한다.
- 미연결 묶음(D1): 묶음 전체 `캐릭터 일괄 연결`을 없앴다. 이름 있는 묶음은 유지하고 머리 설명으로 `이 이름 묶음 전체`와 `체크한 설정만`을 구분한다. 1차에서 미뤘던 묶음 일괄 연결의 응답 유실도 선택 연결과 같은 저장 추적(체크한 후보를 모두 다시 읽어 확인)으로 처리한다.
- 세계관 선택 대상 연결: 행 체크(공유 결정의 원문은 함께 체크, 필터로 숨을 수 있으면 잠금) → `선택 항목 대상 연결` → 분류·실제 대상 검색 또는 새 대상 이름 → 미리보기 → 적용. 대상에 같은 경로(범위+설정명)가 없는 행만 원문 경로·추출값 그대로 `ADD` 초안으로 한 번에 저장한다(D4). 같은 경로가 있는 행, 원문 충돌을 아직 정리하지 않은 행, 체크한 행끼리 경로가 겹치는 뒤쪽 행은 저장하지 않고 고른 대상과 함께 행의 병합/교체 카드(또는 최종 내용 편집)를 `대상은 골랐어요…` 안내와 함께 연다. 저장 뒤에도 읽던 묶음에 남고 `N개 저장(추가) · M개는 내용 결정이 남았어요`·`첫 항목으로`·`연결한 묶음 보기`를 안내한다.
- `분류·대상 일괄 수정`의 활성 조건은 그대로다. 결정이 없는 설정이 있으면 비활성 이유와 `선택 항목 대상 연결` 사용을 안내한다.

### 알려진 한계

- 검색 대기(300ms) 중에는 직전 결과를 흐리게 남겨 두므로 그 행을 고를 수 있다. 다음 결과에 그 인물이 없으면 선택이 미리보기·연결 대상에서 빠지고 다시 고르게 한다.
- 미리보기는 인물을 고를 때마다 상세를 한 번 읽는다(묶음 썸네일과 캐시를 공유한다). 세계관은 대상을 고를 때 상세를 한 번, 결정으로 남긴 행이 패널을 열 때 다시 읽는다.
- 세계관에서 결정으로 남긴 행의 대상은 화면 안 초안이다. 묶음·필터·페이지를 바꾸거나 새로고침하면 사라지고 행은 원래 상태(대상 미정 등)로 돌아간다. 의도한 한계다.
- 공유 결정의 원문이 서로 다른 초안을 가리키면(호환되지 않으면) 그 행만 따로 체크된다. 필터가 적용된 동안 공유 결정 행은 체크할 수 없다.
- 묶음의 마지막 설정까지 연결하면 1차의 다음 묶음 규칙(직전 목록에 없던 묶음은 뒤에 있던 묶음으로 본다)에 따라 방금 연결한 대상 묶음이 열릴 수 있다.

### 바뀐 동작

- 고정 확정 영역(캐릭터·세계관 공용 `ReviewGroupActionBar`): 상세 스크롤 영역 하단에 붙는다. 왼쪽은 `확정 가능 N · 이력 저장 H · 제외 E`(0 생략)와 `결정 필요 M`(경고 잉크), 막는 이유 한 줄, 오른쪽은 `다음 미결정 항목`과 주 버튼이다. 주 버튼은 같은 탭에 열 묶음이 남으면 `확정하고 다음`, 마지막 묶음이면 `모두 확정`, 요청·결과 확인 중이면 `확정 중…`이다. 막힌 주 버튼도 `aria-disabled`라 초점을 받고 이유가 `aria-describedby`로 읽힌다. 세계관에서 같은 문장의 경고가 위에 이미 있으면 문장을 되풀이하지 않고 그 경고에 잇는다.
- 기존 footer가 고정되지 않던 원인: 브라우저로 확인하니 캐릭터 확정 footer(`position: sticky`)는 부모 article의 `overflow: hidden`이 스크롤 컨테이너가 되어 1280×800·320×568 모두 고정되지 않았다(800px 내린 뒤 footer top 6013px, 뷰포트 800px). 세계관 카드도 같은 구조였다. 두 article을 `overflow: clip`으로 바꿔 `.setting-review-main` 기준으로 고정한다. 액션 바를 article 밖으로 옮기거나 모바일 `fixed`를 따로 두지 않아도 두 너비에서 하단에 붙는다(e2e `review-action-bar`가 `bottom == innerHeight ±1`을 확인).
- 차단 사유 계산: 캐릭터 `computeGroupConfirmBlock`, 세계관 `computeWorldGroupConfirmBlock`이 기존 문장 체인의 첫 문장과 함께 후보 때문에 막힌 후보 ID를 화면 순서로 돌려준다. 그룹 전체 사유(일부만 표시·대기 0·자동 반영 대기·필터)는 후보 없이 돌려준다. 세계관은 결정 없는 행·원문 충돌·미저장 수정·사용량 중단·중복 경로·설정집 선택 미정·묶음에서 대상만 고른 행을 결정 필요로 센다.
- `다음 미결정 항목`: 첫 차단 카드로 스크롤(움직임 줄이기면 즉시)하고 카드에 초점을 둔다. 누를 때마다 마지막으로 초점이 머문 카드 다음의 차단 카드로 돌고, 끝이면 처음으로 돌아간다.
- `확정하고 다음`: 기존 그룹 확정 그대로이고, 성공 뒤 직전 목록 순서의 다음 미처리 묶음 제목에 초점을 두며 상세를 맨 위에서 읽게 한다. 다음 묶음 규칙은 ① 사라진 묶음 뒤에 있던 묶음 ② 직전 목록에 없던 묶음(다음 페이지에서 당겨진 묶음·연결로 생긴 묶음) ③ 현재 첫 묶음 순이다(1차 규칙의 결함 — 연결로 생긴 `existing:<id>` 묶음이 원래 다음 묶음을 앞지르던 문제 — 을 함께 고쳤다). 마지막 줄 묶음이어도 앞쪽 묶음이나 다른 페이지가 남아 있으면 `확정하고 다음`이다. 탭의 마지막 묶음 뒤에는 자동 전환 없이 `캐릭터 검토를 마쳤어요` + `세계관 후보 N개가 남았어요` + 기존 `세계관 후보 검토로` 버튼을 보여 준다.
- 선택 바와의 배치: 체크한 설정이 있으면 선택 바를 같은 고정 영역 맨 위에 쌓는다. 650px 이하에서는 선택 바 버튼과 확정 버튼 줄을 각각 두 칸(44px)으로 놓고, 선택 중에는 막는 이유 문장을 접어(설명으로는 유지) 320×568에서 고정 영역이 화면의 약 3분의 1을 넘지 않는다. 세계관의 이동 안내·순차 분석 영향 안내는 고정 영역 위 일반 흐름으로 옮겼다.
- 요약 카드(D6): 결정이 끝난 대기 카드는 처음 열 때 한 줄 요약(설정명, 반영 방식 · 최종값, 배지 `저장했어요`/`제외 예정`/`선택됨 · 확정할 때 적용`/`연결됨`, `펼치기`)으로 접는다. 요약에서도 체크박스와 `캐릭터 연결 변경`·`수정`·`제외`가 남고, 펼치면 원문·근거를 그대로 보며 `접기`로 되돌린다. 막는 후보·저장 중·결과 미확인·오류·값 오류·자동 반영 대기·선택 연결 거절·묶음에서 대상만 고른 행은 항상 펼친다. 접힘은 카드가 처음 그려질 때만 정하므로 이 화면에서 방금 고른 카드는 펼친 채 남는다.
- 반복 줄이기: `이력에만 저장` 예문은 묶음에서 접히지 않는 첫 비교 카드에만 둔다. 근거 끝의 연결 상태 줄은 제목 줄에 이미 드러나면(인물 이름·미연결·인물 확인 필요) 생략한다. 연결이 모호한 캐릭터 후보의 인라인 인물 선택은 6명+페이지에서 등록 인물 3명 + `새로운 인물` + `검색으로 찾기`(원문 표현을 검색어로 넣은 작품 전체 검색)로 줄였다. 세계관 묶음에 대상 미정 행이 둘 이상이면 행마다 검색 목록을 펼치지 않고 이번 검토에서 고른 대상(최대 3, 같은 분류) + 새 등록 + `대상 검색`을 먼저 보여 주며 목록은 누른 행만 불러온다.
- 저장 상태 문구는 버튼 이름에 맞춰 `저장했어요 · 확정 전까지 바꿀 수 있어요`, `선택됨 · 확정할 때 적용`으로 바꿨다.

### 단축키(D7)

상세 패널에 초점이 있을 때만 동작한다. 글자 입력 컨트롤·선택 메뉴·`contenteditable`, 한글 조합 중(`isComposing`·keyCode 229), 모달이 열린 동안에는 처리하지 않는다.

| 키 | 동작 |
| --- | --- |
| `Alt + ↓` / `Alt + ↑` | 다음·이전 설정 카드로 초점과 스크롤(묶음 제목에서는 첫 카드부터) |
| `Alt + Shift + ↓` / `Alt + Shift + ↑` | 다음·이전 묶음 열기. 페이지 끝이면 다음 페이지의 첫 묶음·이전 페이지의 마지막 묶음 |
| `Alt + Enter` | 확정 영역의 주 버튼으로 초점만 옮긴다(요청 없음) |
| `Alt + .` | 다음 미결정 항목 |

- 선택 카드(`ReviewChoiceCards`)는 radiogroup/radio(`aria-checked`)와 roving tabindex를 쓴다. 방향키는 초점만 옮기고 Space·Enter로 고른다(고르면 서버에 저장되는 카드가 많아 이동만으로 저장하지 않는다). 저장 중에는 `aria-disabled`로 잠가 초점을 잃지 않는다. 가족 관계·검수 판단 카드는 범위 밖이라 기존 `aria-pressed` 토글을 유지한다.
- 확정 영역 끝 `단축키` 버튼이 네 줄 안내를 열고 Esc·바깥 클릭으로 닫는다(768px 이하에서는 숨김).
- 세계관 수정 창은 캐릭터 모달과 같은 키보드 계약(Esc 닫기·Tab 가두기·닫으면 연 `수정` 버튼으로 초점 복귀)을 쓴다. 기존 `.review-modal` 배치와 선택자를 유지하려고 Radix `WorldSettingDialog`로 감싸지 않고 캐릭터 `ModalLayer`의 키보드 처리를 `useModalFocusTrap`으로 꺼내 함께 쓴다.

### 알려진 한계

- 요약 접힘은 카드가 처음 그려질 때 정하므로 묶음을 다시 열거나 새로고침하면 방금 고른 카드도 요약으로 보인다.
- 세계관 축소형 대상 선택의 `최근 고른 대상`은 화면 안 기억이다. 새로고침·작품/묶음 범위가 바뀌면 비고, 같은 분류의 기존 대상만 보인다.
- 공개 체험·랜딩·최초 안내의 전용 버튼(`1개 설정 모두 확정` 등)은 이번 범위가 아니라 그대로다. 체험 코치마크의 “실제 화면과 같은” 버튼 이름은 이제 실제 화면과 다르다.
- 단축키는 macOS에서 Option 조합이다. `Alt + .`은 문자 대신 물리 키(`code === 'Period'`)로 판단한다.
