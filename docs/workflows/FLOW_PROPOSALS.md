# CatchHole Flow 개선 제안

[`FLOW_AUDIT.md`](FLOW_AUDIT.md)에서 확인한 불일치와 누락을 실제 작업 항목으로 옮길 때 사용할 제안서입니다. 우선순위는 사용자 기대와 실제 목적지가 다른 문제를 가장 높게 두었습니다.

## P0 — 목적지가 잘못되거나 현재 단계를 오인하는 문제

### 1. 챗봇 사이드바의 목적지 보존

제안:

- 대시보드 밖에서 `nav(id)`를 호출할 때 `/dashboard?nav=<id>`로 이동합니다.
- 또는 `navigate`의 state로 `activeNav`를 전달하고 대시보드가 이를 쿼리 파라미터로 동기화합니다.
- 쿼리 파라미터 방식이 이미 대시보드 딥링크 규칙과 맞으므로 더 단순합니다.

완료 조건:

- 챗봇에서 설정 DB, 분석 리포트, 그래프 뷰, 원고 목록을 각각 누르면 선택한 섹션이 바로 열립니다.
- 브라우저 새로고침 후에도 같은 섹션이 유지됩니다.

### 2. 회차 업로드 Stepper 현재 단계 수정

권장 계산:

| 화면 상태 | 표시 단계 |
| --- | --- |
| `select-mode` | 1 |
| `boundary-preview` | 2 |
| `settings-review` | 3 |
| `processing` | `stepLabels.length` |

추가 검토:

- 2B 입력 화면에서 회차 분리 확인을 미리 활성화하지 않도록 `select-mode`는 업로드 모드 선택 여부와 무관하게 1로 유지하는 편이 자연스럽습니다.

완료 조건:

- A/B/C 방식과 설정집 포함 여부의 모든 조합에서 실제 콘텐츠와 활성 Stepper 라벨이 일치합니다.

### 3. 설정 후보 검토 완료 CTA의 의미 결정

둘 중 하나를 선택해야 합니다.

1. 실제로 검사를 시작할 계획이면 `/episode-upload`의 신규 회차 검수 모드 또는 전용 검사 시작 화면으로 연결합니다.
2. 지금처럼 대시보드로 돌아가는 동작을 유지한다면 버튼을 `검토 완료 · 대시보드로 돌아가기`로 바꿉니다.

완료 조건:

- CTA 문구만 보고 예측한 결과와 실제 도착 화면이 일치합니다.

## P1 — 구현 상태와 보드 상태 정합성

### 4. 발행 전 전체 검수 0건 상태 결정

선택지:

1. WF-05의 디자인 제안을 구현하고 `activeCount === 0`일 때 성공 UI를 표시합니다.
2. 구현 계획이 없다면 Pencil 원본 화면과 Workflow Board에서 해당 제안 상태를 제거합니다.

현재 보드는 혼동을 막기 위해 빨간색 `코드 미구현`으로 표시했습니다.

완료 조건:

- 0건 데이터로 진입했을 때 빈 목록이 아니라 의도된 성공 상태가 표시되거나, 제품 범위에서 명시적으로 제외됩니다.

### 5. 리포트의 무동작 버튼 처리

- `범위 변경`: 검수 범위 선택 모달 또는 회차 선택 패널을 연결합니다.
- `전체 펼치기`: 모든 ErrorCard의 펼침 상태를 제어합니다.
- `리포트 복사`: 클립보드 복사 후 성공·실패 피드백을 제공합니다.
- 이번 스프린트 범위가 아니라면 버튼을 숨기거나 `준비 중` 상태로 표시해 클릭 가능한 동작으로 오인되지 않게 합니다.

### 6. 대시보드 모달 딥링크 정책 통일

딥링크가 필요한 후보:

- 캐릭터 설정 빌더
- 세계관 설정 빌더
- 공유 모달과 활성 탭
- 레거시 업로드 모달을 유지할 경우 해당 모달

제안:

- 공유·재현 가치가 있는 모달만 `modal=<id>` 쿼리로 승격합니다.
- 일회성 입력 중간 상태는 로컬 상태로 유지하고 `screen-flow.md`의 “모두 딥링크” 표현을 제한적으로 수정합니다.

### 7. 리포트 공유 모달의 실제 첫 탭 반영

- `ShareModal / 내보내기 탭` 원본 상태를 Pencil에 별도로 만듭니다.
- WF-05는 공용 협업자 탭이 아니라 이 원본을 참조합니다.
- 에디터 공유 흐름을 보드에 추가할 때는 `ShareModal / 링크 탭` 원본을 사용합니다.

## P2 — Workflow Board 범위 보강

### WF-01 인증·작품 진입

- 로그인 실패와 제출 중 상태
- 회원가입 검증 실패와 제출 중 상태
- 작품 API 오류 → 다시 시도
- 작품 Empty → 새 작품 등록 모달 → 생성 성공 → Loaded
- 로그아웃 → 로그인

### WF-02 작품·대시보드

- 긴 순차 배열 대신 중앙 대시보드 허브에서 설정 DB·리포트·그래프·원고·챗봇으로 갈라지는 구조를 권장합니다.
- 업로드 모달은 `삭제`, `재연결`, `참고용 유지` 중 하나를 결정해야 합니다. 참고용으로 유지할 경우 화면 제목과 메타데이터에 `진입점 없음`을 계속 표시합니다.

### WF-03 원고·편집·분석

- 보기 모드 → 편집 모드 전환
- 분석 요청 모달 → 취소 → 에디터
- 에디터 → 뒤로 → 대시보드 원고 목록
- 분석 진행 중 → 자동 완료 → `WF-05 / 단일 회차 검수`

### WF-04 회차 업로드

- 헤더 뒤로 → 대시보드
- 파일 형식·용량 오류 → 재선택
- 분석 실패 → 재시도 또는 대시보드 복귀
- 처리 중 이탈 정책과 중복 제출 방지
- 데모 모드 제안 모달 → 데모 전환 또는 취소

### WF-05 검토·리포트

- 설정 후보 검토·회차 검사 결과 → 대시보드
- 단일 회차 리포트 → 원고 에디터
- 공유 모달 → 닫기 → 기존 리포트
- 발행 전 전체 검수 → 단일 리포트로 돌아가기

## 공통 보드 표현 규칙 제안

- 사용자 이동: 보라색, 긴 화살표, 동사형 라벨
- 조건·모달·결과 분기: 주황색
- 사용자의 추가 입력 없이 끝나는 자동 처리: 초록색
- 코드 미구현·진입점 없음·결정 필요: 빨간색
- 보드 간 이동: 전체 화면을 중복 복제하지 말고 `다음 Workflow` 캡슐로 연결
- 구현된 상태와 디자인 제안 상태는 같은 초록색을 사용하지 않음
- 화살표는 축소 보기에서도 방향이 남도록 가로 120px 이상, 주요 화면 사이에서는 240px 수준을 유지

## 최종 검증 체크리스트

- 각 보드의 모든 화살표가 시작 화면, 행동, 도착 화면을 한 번에 설명하는가?
- 순서가 없는 메뉴를 순차 프로세스처럼 보이게 하지 않았는가?
- 자동 완료와 사용자 버튼 선택을 색상과 라벨로 구분했는가?
- 코드 미구현 상태가 구현 완료 화면처럼 보이지 않는가?
- 뒤로, 취소, 실패, 재시도 경로 중 제품상 필요한 것이 빠지지 않았는가?
- `snapshot_layout(problemsOnly: true)` 결과가 모든 보드에서 비어 있는가?
- 내보낸 WF-01~WF-05 PNG가 현재 Pencil 상태와 일치하는가?
