## 원고 목록 (대시보드 원고 탭)

**URL**: [`/dashboard?nav=manuscripts`](https://www.catchhole.com/dashboard?nav=manuscripts)

![대시보드 - 원고 탭](../screens/pUaEk.png)

**1. 화면에 표시할 데이터**

- 현재 선택한 작품명
- 업로드된 설정집
  - soft delete되지 않은 설정집 원본 목록
  - 원본 파일명, 업로드 시점(`YYYY.MM.DD`)
  - 최근 업로드 순
  - 설정집 분석·추출 결과는 MVP에서 표시하지 않음
- 업로드된 원고
  - soft delete되지 않은 실제 회차의 전체 개수: `총 N개 회차`
  - 회차 번호 내림차순의 페이지 목록
  - 회차 번호: MVP에서는 정수만 지원. `151-1` 같은 분할 회차와 업로드되지 않은 회차의 가상 행은 표시하지 않음
  - 제목: 감지하지 못한 경우 `제목을 찾지 못했어요`와 제목 입력 액션 표시
  - 원문 변경일: 최초 파일 업로드 또는 파일 교체 시점(`YYYY.MM.DD`). 제목만 수정하면 변경하지 않음
  - 글자 수: 현재 원문에서 공백과 줄바꿈을 제외한 문자 수
  - 분석 상태: 분석 완료 / 재분석 필요 / 분석 중 / 분석 실패
  - 미처리 항목: 최신 유효 분석 리포트에서 아직 처리하지 않은 충돌 의심 항목 수. 분석 완료일 때 `N건` 또는 `없음`, 그 외 상태에서는 `—`
- `미분석`, `missing` 상태와 원고 검색은 MVP에서 제공하지 않음

**2. 사용자 액션**

- 회차 올리기 → [회차 업로드](./upload.md#회차-업로드-sepisodeupload)
- 설정집 업로드
  - 원고 탭의 설정집 영역에서 단독 업로드 모달 열기
  - 한 번에 TXT 또는 DOCX 파일 하나(최대 10MB)를 업로드하며, 반복해서 여러 설정집 추가 가능
  - 기존 회차 업로드의 `설정집도 함께 업로드` 진입점도 유지
  - 어느 진입점이든 MVP에서는 원본만 저장하고 설정집 분석은 실행하지 않음
  - 회차와 함께 업로드할 때 한쪽이 실패해도 성공한 다른 쪽의 결과는 유지하고, 실패한 파일만 다시 시도
- 설정집 행
  - 파일명 또는 행 클릭 → 공통 원문 보기
  - `⋯` 메뉴 → 삭제 확인 후 soft delete
- 회차 제목
  - 제목 감지 실패 시 `제목 입력`, 제목이 있으면 수정 아이콘 표시
  - 행 안에서 제목을 직접 입력하고 저장 또는 취소
  - 제목 수정은 원문 변경일과 분석 상태에 영향을 주지 않음
- 회차 상태별 기본 액션
  - 분석 완료: `결과 보기` → 해당 회차의 최신 유효 리포트
  - 재분석 필요: `재분석` → 사용자 요청 후 분석 진행 화면
  - 분석 중: `분석 중` 비활성화
  - 분석 실패: `다시 시도` → 현재 파일로 재요청 후 분석 진행 화면
- `원문 보기`
  - 기존 에디터 보기 모드를 단순화한 전체 페이지형 읽기 전용 화면 사용
  - 회차·설정집 모두 파일명과 문단·줄바꿈을 유지한 텍스트 원문만 표시
  - 편집 전환, 설정 DB 패널, 충돌 분석 패널, 전체 분석 실행, 이미지·글꼴·페이지 레이아웃 재현은 MVP에서 제외
- 회차 `⋯` 관리 메뉴
  - `회차 파일 변경`: 새 파일 선택 후 아래 안내를 확인해야 교체
    > 파일을 변경하면 기존 분석 결과는 현재 원고에 적용되지 않으며 재분석이 필요합니다.
  - 새 파일의 업로드·검증이 모두 성공한 뒤 같은 회차의 원문을 교체하고, 회차 식별자와 회차 번호는 유지
  - 기존 분석 결과는 무효화해 더 이상 제공하지 않고 상태를 `재분석 필요`로 변경. 자동 재분석하지 않으며 사용자가 `재분석`을 눌러 시작
  - 파일 변경 실패 시 기존 파일과 분석 결과 유지
  - `삭제`: 아래 확인 후 soft delete하여 목록에서 숨김
    > 이 회차를 삭제할까요? 삭제한 회차는 원고 목록에서 사라지며 현재 서비스에서는 직접 복구할 수 없습니다.
- 설정집 삭제도 대상 명칭만 바꾼 같은 확인 문구를 사용
- 분석 중인 회차는 원문 보기만 허용하고 파일 변경·삭제·중복 분석 요청은 비활성화
- 분석 중인 행이 하나라도 있으면 현재 목록의 상태를 10초 간격으로 한 번에 갱신. 모두 완료·실패하거나 화면을 벗어나면 중단
- 회차 번호 수정, 원고 내용 편집, 삭제 복구, 파일 버전 이력은 MVP에서 제공하지 않음

**3. 화면 전환 식별자**

- 현재 선택된 작품을 구분하는 식별자
- 결과 보기·원문 보기·파일 변경·삭제 대상 회차를 구분하는 식별자
- 원문 보기·삭제 대상 설정집 원본을 구분하는 식별자
- 분석 진행 화면에서 추적할 작업과 결과 화면에서 열 최신 유효 리포트를 구분하는 식별자

실제 필드명과 타입은 Swagger와 BE 도메인 문서를 따른다.

**4. 데이터 없음 / 실패 표시**

- 원고와 설정집 빈 상태를 서로 독립적으로 표시
  - 원고만 없음: 설정집 목록은 유지하고 원고 영역에 `아직 업로드된 원고가 없습니다`와 회차 업로드 액션 표시 ([빈 상태](../screens/v4hg9.png))
  - 설정집만 없음: 원고 목록은 유지하고 설정집 영역에 빈 상태와 설정집 업로드 액션 표시
  - 둘 다 없음: 각 영역에 각자의 빈 상태 표시
- 목록 조회 실패도 영역별로 처리
  - 성공한 영역은 그대로 표시
  - 실패한 영역에 오류 안내와 `다시 시도` 표시
  - 기존 데이터가 있는 상태에서 갱신만 실패하면 데이터를 유지하고 오류 안내
- 변경 액션은 서버 성공 후에만 화면에 반영
  - 삭제 실패: 행 유지
  - 파일 변경 실패: 기존 파일·분석 상태 유지
  - 제목 저장 실패: 기존 제목 유지 후 오류 안내
  - 설정집 업로드 실패: 목록에 추가하지 않고 다시 시도 제공
- 분석 상태 갱신 실패 시 현재 상태를 유지하고 다음 갱신을 다시 시도

**5. 화면 데이터 요구사항**

**5-1. BE → FE 제공 데이터 요구사항**

아래 묶음은 화면이 데이터를 사용하는 단위이며, API나 응답 DTO를 같은 단위로 만들어야 한다는 뜻은 아니다. 실제 결합·분리 방식과 필드명은 Swagger와 BE 도메인 문서에서 정한다.

**원고 목록**

| 데이터 의미 | 형태·필수성 | 값 없음·조건 |
| --- | --- | --- |
| 현재 작품명 | 단일 값·필수 | 화면 제목에 표시 |
| 활성 회차 전체 개수 | 0 이상의 정수·필수 | 회차가 없으면 `0`; soft delete된 회차 제외 |
| 현재 페이지 회차 목록 | 목록·필수 | 회차가 없으면 빈 목록; 회차 번호 내림차순 |
| 페이지 이동 정보 | 단일 값·필수 | 다음·이전 페이지가 없음을 구분할 수 있어야 함 |

각 회차 항목은 다음 의미를 제공한다.

| 데이터 의미 | 형태·필수성 | 값 없음·조건 |
| --- | --- | --- |
| 회차 고유 식별자 | 단일 값·필수 | 결과·원문 조회와 변경·삭제 대상 식별 |
| 회차 번호 | 정수·필수 | MVP에서는 분할 회차를 제공하지 않음 |
| 제목 | 단일 값·선택 | `null`이면 제목 감지 실패로 표시 |
| 원문 변경 시점 | 단일 값·필수 | 최초 업로드 또는 파일 교체 시점; 제목 수정으로 바뀌지 않음 |
| 글자 수 | 0 이상의 정수·필수 | 현재 원문의 공백·줄바꿈 제외 문자 수 |
| 분석 상태 | 단일 상태값·필수 | 분석 완료 / 재분석 필요 / 분석 중 / 분석 실패 |
| 미처리 항목 수 | 0 이상의 정수·조건부 | 분석 완료일 때 필수이며 `0`은 미처리 항목 없음. 다른 상태에서는 `null` |

분석 상태를 갱신할 때는 현재 페이지 회차들의 고유 식별자, 분석 상태, 조건부 미처리 항목 수를 한 번에 받을 수 있어야 한다. 리포트에서 개별 항목을 처리한 뒤 다시 조회하면 최신 미처리 항목 수를 제공한다.

**설정집 목록**

| 데이터 의미 | 형태·필수성 | 값 없음·조건 |
| --- | --- | --- |
| 활성 설정집 목록 | 목록·필수 | 설정집이 없으면 빈 목록; soft delete된 원본 제외, 최근 업로드 순 |
| 설정집 원본 식별자 | 목록 항목별 단일 값·필수 | 원문 조회와 삭제 대상 식별 |
| 원본 파일명 | 목록 항목별 단일 값·필수 | 화면에 그대로 표시 |
| 업로드 시점 | 목록 항목별 단일 값·필수 | 목록 날짜 표시 기준 |

설정집 목록에는 분석 상태와 추출 결과를 제공하지 않는다.

**공통 원문 보기**

| 데이터 의미 | 형태·필수성 | 값 없음·조건 |
| --- | --- | --- |
| 대상 파일명 | 단일 값·필수 | 뷰어 제목에 표시 |
| 텍스트 원문 | 단일 값·필수 | TXT·DOCX에서 추출하며 문단·줄바꿈 보존. 스타일·이미지·페이지 레이아웃 제외 |

**작업 완료 후 갱신되어야 할 화면 데이터**

BE가 작업 응답으로 제공하거나 FE가 다시 조회해 다음 최신 상태를 확보할 수 있어야 한다.

| 작업 | FE가 확보해야 할 최신 데이터 |
| --- | --- |
| 제목 수정 | 저장된 제목 |
| 회차 파일 변경 | 원문 변경 시점, 글자 수, `재분석 필요` 상태 |
| 재분석·다시 시도 | 분석 작업을 추적할 식별 정보와 분석 중 상태 |
| 설정집 업로드 | 새 설정집 원본의 식별자, 파일명, 업로드 시점 |
| 회차·설정집 soft delete | 대상이 제외된 최신 목록. 회차 삭제라면 변경된 활성 회차 전체 개수도 포함 |

**5-2. FE → BE 전달 데이터 요구사항**

- 원고 목록 조회·갱신
  - 현재 작품 식별자, 페이지 위치와 크기, 회차 번호 내림차순 정렬 의도
  - 분석 중 회차가 있을 때 현재 목록 상태를 10초 간격으로 일괄 갱신하기 위한 조회 문맥
- 제목 저장
  - 대상 회차 식별자와 사용자가 입력한 제목
  - FE는 앞뒤 공백을 제거한 값을 전달
- 결과·원문 조회
  - 결과를 열 대상 회차 또는 최신 유효 리포트 식별자
  - 원문을 열 대상 회차나 설정집 원본 식별자
- 회차 파일 변경
  - 대상 회차 식별자와 새 원문 파일
  - 회차 업로드와 동일한 파일 검증을 통과하고 사용자가 교체를 확인한 경우에만 전달
  - 회차 번호 변경은 전달하지 않음
- 분석 요청
  - 재분석 또는 다시 시도할 대상 회차 식별자와 사용자의 분석 시작 의도
- 회차 삭제
  - 대상 회차 식별자와 목록에서 제거하려는 사용자의 삭제 의도
- 설정집 업로드
  - 현재 작품 식별자와 TXT·DOCX 원본 파일 하나
  - 단독 업로드인지 회차 업로드의 선택 첨부인지 구분할 수 있는 문맥
- 설정집 삭제
  - 대상 설정집 원본 식별자와 목록에서 제거하려는 사용자의 삭제 의도

**6. BE와 협의할 범위·상태값**

- **BE**: 화면의 분석 완료 / 재분석 필요 / 분석 중 / 분석 실패를 현행 분석 작업·회차 상태에 매핑하는 기준. `미분석` 상태는 MVP에서 사용하지 않음
- **BE**: 회차 파일을 원자적으로 교체하고 기존 분석 결과를 무효화한 뒤 `재분석 필요`로 전환하는 계약. 무효화된 행의 물리 삭제·비활성화 방식은 참조 무결성을 지키면서 BE가 결정
- **BE**: 회차와 설정집 원본의 soft delete 계약, 활성 목록·전체 개수·중복 검사에서 제외하는 기준. 사용자 복구 UI는 MVP에서 제공하지 않음
