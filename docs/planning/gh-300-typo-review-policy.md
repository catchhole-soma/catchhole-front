# 신규 회차 오탈자 검사 범위와 작가 검토

2026-10-28 · GH300 · 사용자 합의 반영, 실제 검사·화면 미구현

관련 문서: [제품 기획](gh-300-error-report-product-brief.md), [구현 계획](gh-300-error-report-implementation-plan.md), [설정 질문·누락 보완](gh-300-validation-question-planning.md), [오류 리포트 화면 명세](../data-requirements/analysis.md#충돌-의심-상세-리포트-sepisodevalidationreport).

## 1. 첫 버전의 검사 범위

설정 충돌 검사와 독립적으로 같은 원고 버전 전체를 검사한다. 설정 질문/검색 결과가 없거나 실패해도 오탈자 분기의 원문 처리 자체를 생략하지 않는다. 별도 역할 설정을 사용하며 초기 모델은 사용자가 고른 **6.1 Terra**, 추론 강도는 `low`다. 사용자가 말한 `lite`는 가벼운 추론으로 해석해 공식 지원 값 `low`로 대응했으며 `lite` 자체를 API 값으로 전송하지 않는다. 평가를 모델 선택의 선행 조건으로 요구하지 않는다. 공식 호출 ID는 `gpt-6.1-terra`로 확인했다. [OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-terra)를 근거로 하며, 계정 사용 가능 여부·서비스 통합·한국어 오탈자 품질은 아직 검증하지 않았다. 분리·병렬 실행 자체가 정확도를 보장한다는 뜻은 아니다.

| 포함 범위 | 예시 | 경계 |
| --- | --- | --- |
| 명확한 문자 오타·맞춤법 | “됬다” → “됐다”, “열엇다” → “열었다” | 원문과 문맥에 근거한 짧은 교정 제안 |
| 띄어쓰기 | “할수 있다” → “할 수 있다” | 허용되는 표기까지 취향에 따라 통일하지 않음 |
| 분명한 문자·조사 중복이나 누락 | “문을을 열었다” → “문을 열었다” | 의도적인 말더듬·강조·반복은 오류로 단정하지 않음. 빠진 단어나 문장 내용을 추측해서 채우지 않음 |

**제외하기로 한 범위:** 윤문, 문체·말투 통일, 문장 전체 재작성, 빠진 의미의 추측 보충, 고유명사 표기 차이 자체. 인물·장소·기술 등의 이름이 기존 명칭과 조금 다르다는 이유만으로 오탈자 제안을 만들지 않는다. 별칭·새 이름·호칭일 수 있기 때문이다. 이름 주변의 일반적인 오타는 검사한다.

고유명사 표기 차이를 설정 오류로 자동 이관하지 않는다. 설정 검사는 그 분기의 기준에 따라 독립적으로 질문과 근거를 확인한다. 대사 전체를 검사에서 빼지는 않되 방언·의성어·의도한 표현을 일반적인 말투로 교정하지 않는다. 문장부호의 취향이나 반복 부호를 정규화하는 문체 교정을 추가하지 않는다.

## 2. 제안에 표시할 내용

원문 버전, 제안 ID, 정확한 원문 위치와 실제 표기, 짧은 교정 제안, 제안 이유, 작가 판단을 연결한다. 원문의 실제 위치·인용 일치는 서버가 검증한다. 수정 제안을 원문에 자동 적용하는 버튼은 제공하지 않는다.

설정 결과 세 유형과 `심각 / 주의 / 참고` 등급을 오탈자에 억지로 적용하지 않는다. 오탈자는 별도 분류·건수·실행 상태로 표시한다. 배치·필터·API 필드명은 후속 구현 설계이며 의미와 범위는 아래 합의를 따른다.

## 3. 항목별 작가 판단

| 행동 | 저장되는 의미 | 원문·추출에 미치는 영향 |
| --- | --- | --- |
| **원문 유지** | 해당 제안을 확인했고 현재 표기를 유지함 | 해당 항목의 미검토를 해소. 원문 수정·추출 시작·다른 항목 판단은 실행하지 않음 |
| **수정 필요** | 수정할 항목으로 표시함 | 원문은 그대로이며 수정 대기로 추출 보류. 실제 수정은 기존 파일 교체 흐름 사용 |
| **검토 필요로 되돌리기** | 해당 판단을 미검토로 되돌림 | 원문·AI 제안은 바꾸지 않고 추출을 보류 |

`수정 필요`와 `원문 유지` 사이 판단 변경도 가능하다. `원문 유지`는 현재 원고 버전의 해당 항목에 대한 판단이다. 작품 전체의 예외 사전 등록, 다른 위치/항목 무시, 이후 회차 또는 새 원고에 대한 자동 판단 승계는 하지 않는다. 첫 버전의 일괄 판단 제외는 유지한다.

`수정 필요` 선택은 수정 완료를 뜻하지 않는다. “수정할 항목으로 표시했어요. 수정한 파일을 올린 뒤 다시 검사해요.”와 같이 현재 상태를 설명하는 카피를 제안한다. ‘수정 완료’ 체크만으로 미수정 원고의 검토를 통과시키는 행동은 제공하지 않는다.

내부 상태는 예를 들어 `PENDING / NEEDS_FIX / KEEP_ORIGINAL`로 표현할 수 있으나 **이 enum과 필드명은 API 제안**이다. 설정 항목의 `NOT_CONFLICT`를 오탈자 판단으로 무조건 재사용하지 않는다. 작가 판단과 AI 제안, 실행 상태는 별도로 보존한다.

## 4. 수정·재검사·설정 추출 연결

1. 검사가 실행 중일 때 발견된 제안은 읽기 전용으로 보여준다. 완료 또는 중단 후 판단을 저장할 수 있지만, 일부 중단/실패가 남으면 추출할 수 없다.
2. 작가는 제안을 확인해 원문 유지 또는 수정 필요를 판단한다. 수정 동선에 들어가기 위해 반드시 수정 필요 표시를 먼저 저장해야 하는 것은 아니다.
3. 실제 수정은 외부에서 원고를 고친 뒤 같은 최신 회차의 기존 파일 교체 기능을 사용한다. 교체 저장이나 리포트 복귀만으로 재검사를 자동 실행하지 않고 기존의 명시적 재검수 흐름을 사용한다.
4. 변경된 원고는 새 검사로 처리하며 옛 원고의 판단·검토 허가를 그대로 승계하지 않는다. 아직 설정 추출 후보는 없으므로 사전 후보의 재추출/수정을 요구하지 않는다.
5. 같은 원고의 실패/일부 중단을 재시도할 때는 변경 없는 성공 결과와 판단을 보존하고 미완료 범위를 재시도한다. 새 발생 위치나 교정 제안 등 판단 내용이 바뀐 항목만 검토 필요로 되돌리고 기존 판단은 이력으로 남긴다. 같은 입력 재시도와 원고 변경 후 새 검사를 구분한다.

**자동 추출:** 설정 검사와 오탈자 검사 모두 정상 완료·유효하고, 설정 결과 세 유형 합계와 오탈자 제안이 모두 0건일 때다. 수정한 원고의 새 검사에서도 이 조건을 적용한다.

**명시적 검토 완료 후 추출:** 표시 항목이 있었다면 설정 항목 전부 `충돌 아님`, 오탈자 항목 전부 확인 완료·수정 대기 없음, 두 검사 정상 완료와 원고/기준 유효성을 확인한 뒤 기존 `검토 완료 후 설정 추출` 버튼으로 진행한다. 현재 원고의 오탈자 제안을 모두 원문 유지로 판단한 경우에도 실제 수정이나 제안 삭제를 강제하지 않는다. 마지막 판단 저장만으로 추출을 시작하지 않는다.

오탈자 미검토·수정 대기·실패·일부 중단·재시도 실패는 설정 검사 성공 여부와 무관하게 추출을 보류한다. 오탈자 검사 없이 진행하는 우회는 제공하지 않는다.

## 5. 구현 계획과 검증 사례

원고 구간 입력과 위치·제안·이유·처리 범위 출력은 [단계별 입출력 설계안의 오탈자 계약](gh-300-validation-stage-contracts.md#9-오탈자-분기의-최소-계약)에 정리했다. 작가 판단은 모델 응답과 분리한다.

**초기 평가 방향 — 사용자 합의:** 선택한 Terra 모델과 역할별 추론 강도를 유지하고, 기대 결과를 정한 소수의 충돌·정상·모호한 사례로 실제 동작을 확인한다. 설정 오류를 놓치거나 잘못 지적하면 질문 생성·근거 검색·판정 중 원인을 찾아 보완한다. 초기 작업에 모델 간 비교·순위 실험을 넣지 않으며, 심각한 오류 한 건 누락만으로 모델 채택을 보류하는 기준은 합의하지 않았다. 오탈자는 간단한 맞춤법·띄어쓰기·명백한 오타를 찾고 고유명사·의도한 표현을 건드리지 않는지 기본 예시로 확인한다. 개발 중 평가 사례와 결과는 작업자가 정리하고 작품 해석이 필요한 부분을 함께 확인한다. 모든 실제 원고나 내부 질문을 사람이 전수 검토하는 흐름은 아니며, 실제 서비스에서 작가는 리포트에 게시된 항목만 검토한다.

전체 구현 계획 Task 3에서 독립 검사·모델 설정·원문 위치·제안을, Task 4/5에서 상태·판단 저장·추출 허가를, Task 6/7에서 항목별 화면과 파일 교체·재검사 연결을 구현하는 안이다. #303 기반 코드가 이 기능을 구현한 것으로 표시하지 않는다.

- 문자 오타·맞춤법·띄어쓰기·명확한 중복/누락의 양성 사례와 허용 표기·의도한 반복·말더듬·방언의 정상 대조 사례를 준비한다.
- 고유명사 표기 차이만으로 제안/설정 오류를 만들지 않으며 이름 주변의 일반 오타는 찾는지 확인한다.
- 문장 윤문·내용 추측 보충·원문 자동 쓰기 없이 원문 위치와 짧은 교정 제안을 반환하는지 확인한다.
- 원문 유지가 해당 원고 항목만 해소하고 다른 항목·새 원고·이후 회차·작품 사전에 영향을 주지 않는지 확인한다.
- 수정 필요가 판단 저장만 수행하고 추출 0건을 유지하는지, 되돌리기·판단 변경·저장 실패 시 선택 보존을 확인한다.
- ‘수정 완료’ 체크/직접 API 요청으로 실제 파일 교체·새 검사를 우회하지 못하는지 확인한다.
- 미검토/수정 대기/실패/일부 중단에서 추출 0건, 원문 유지 후 명시 완료의 멱등 추출 1건, 두 검사 0건 자동 추출을 검증한다.
- 같은 입력 재시도의 성공 항목/판단 보존과 원고 변경의 늦은 결과 차단·판단 초기화를 검증한다.

이 목록은 검증 계획이다. 실제 모델의 누락·잘못된 교정 제안·고유명사 오탐·시간·사용량은 아직 측정하지 않았다. 초기 모델 **6.1 Terra**, 추론 `low`(사용자 표현 lite를 낮은 추론으로 해석)로 기록했으며 품질 수치·공개 기준·처리 시간 한도는 아직 정하지 않았다. 실제 원고 평가는 선택한 모델의 동작을 확인하는 후속 작업이다.
