# GH260·GH261 관계도 — 가계도와 가족 관계 검토

2026-10-21 공개 결정에 따라 관계 화면은 기본 ON이다. 사이드바 `관계도` 메뉴는 2026-10-30부터 인물 관계도를 기본으로 연다. 가족 화면은 오른쪽 `가계도` 탭 또는 `/dashboard?workId=<id>&nav=graph&relationMode=family`에서 연다. `VITE_RELATIONSHIP_WORKSPACE_ENABLED`가 정확히 문자열 `false`인 빌드에서만 OFF이며, 미설정·빈 문자열·그 외 값은 ON이다. OFF에서는 좌측 `그래프 뷰 · 업데이트 예정`과 작품 설정의 `관계도 · 업데이트 예정` 안내만 유지하고 신규 가족 관계 탭이나 관계 화면을 제공하지 않는다. 이 정책은 아래 날짜별 메뉴 통합·검증 기록보다 우선한다.

ON 화면은 현재 PROFILE을 바탕으로 정리한 가족 관계를 보여주며 작품 설정 안에 가족 관계 탭을 중복 노출하지 않는다. 확정한 설정과 직접 수정한 설정을 동일한 현재 설정 입력으로 사용한다. 기존 AI 추출·설정 후보 검토 옵션과 집계는 바꾸지 않는다. 명확한 가족 관계는 서버가 자동 반영하며, 대상·의미·시점이 모호한 내용은 `확인·연결`의 확인 대상으로 모은다. GH261은 확인된 가족 관계와 현재 설정에 이름이 명시된 미등록 가족을 가계도로 배치한다. 일반 인간관계는 별도 [회차별 인물 관계도](episode-relationships-ui.md) 계약을 따른다.

이 플래그는 프론트 빌드 시 결정되는 화면 노출 조건이다. 값을 바꾸면 재빌드·배포가 필요하다. Backend 자동 후처리·관계 API·DB는 유지하며 인증과 작품 소유권 검증을 대신하지 않는다. 운영의 기존 데이터는 2026-10-21에 별도 일회성 백필을 완료했다. 화면 진입·플래그 변경·머지는 백필을 실행하지 않는다.

## 화면과 URL

OFF에서는 `nav=graph`, 이전 `nav=settingDB&tab=relations`, nav 없이 `tab=relations`만 있는 직접 주소를 `nav=settingDB&tab=characters`로 replace한다. 작품 선택을 유지하고 관계 전용 보기·페이지·후보·관계·원문 파라미터를 정리한다. 관계 컴포넌트를 열거나 관계 API를 호출하지 않는다.

ON에서 `nav=graph`가 관계도의 진입점이며 종류를 생략한 일반 진입은 인물 관계도다. 가족 화면은 `relationMode=family`로 명시한다. 종류가 없는 기존 가족 상세 키가 있으면 가족 화면으로 호환한다. 이전 `nav=settingDB&tab=relations` 링크와 nav 없이 `tab=relations`만 있는 링크는 명시된 종류를 우선하고 없으면 `relationMode=family`를 남겨 `nav=graph`로 방문 기록을 replace한 뒤 `tab`을 제거한다. `workId`와 아래 보기·페이지·선택 항목은 그대로 보존하므로 공유 링크, 새로고침과 뒤로가기에서 같은 검토 문맥으로 이어진다.

- `relationView=tree|list|review`: 가계도 / 가족 관계 목록 / 확인·연결. 생략하면 가계도다.
- `familyFocus`: 선택한 활성 인물과 연결된 가족 전체를 조회한다. 1단계 이웃 제한이 아니며, 연결이 없으면 선택한 인물 하나를 보여준다.
- `familyHistory=true`: 유효한 과거 가족 관계도 포함한다. 생략하면 현재 관계만 조회한다.
- `modal=char-detail&charId`: 가계도 위에서 기존 프로필·편집·원문·이력 UI를 재사용한다.
- `relationPage`: 각 보기의 1부터 시작하는 서버 페이지. 보기 전환 시 초기화한다.
- `relationshipCandidate`: 검토 후보 상세. 새로고침·뒤로가기로 복원한다.
- `relationshipId`: 가계도에서 선택하거나 목록에서 펼친 관계의 근거. 목록 페이지에 없는 직접 링크도 상세 API로 조회하며, 독립 카드에 양쪽 인물·관계 종류·세부 종류·시점·유효 상태를 근거와 철회 액션보다 먼저 표시한다.
- `relationshipFactId`: 원문 근거 모달. 선택한 Fact의 기존 evidence API만 요청한다.

서버 페이지 수가 줄면 마지막 유효 페이지로 복귀한다. 작품 변경 시 컴포넌트를 새로 구성하고 이전 요청 결과가 새 작품의 화면을 바꾸지 않게 한다. 사이드바에서 다른 메뉴로 나가면 관계 보기·페이지·선택 상세·원문 키를 지운다. 작은 화면에서는 보기 버튼을 native select로 바꾸고 폼과 액션을 한 열로 표시한다.

요청 결과는 시작 때의 로그인 세션 번호(`privateImageSessionEpoch`)와 현재 번호가 같고 화면이 유지될 때만 반영한다. 정상 access token 갱신은 같은 세션이므로 성공 결과를 적용한다. 로그아웃·새 로그인·계정 변경 뒤에는 늦은 성공과 오류, 로딩 상태 변경을 무시하며 비운 캐시에 이전 작품 데이터를 다시 넣지 않는다.

## 처리 상태와 집계

ON 화면에서 GET `relationship-processing`을 생성 SDK로 호출한다. `NEVER_PROCESSED`, `PENDING`, `FAILED`는 로딩/재시도와 구분해 표시하고 `SUCCEEDED`는 화면 안내 없이 갱신 감지에만 사용한다. 처리 중 3초, 그 외 30초 간격으로 상태를 확인하고 입력/완료 상태가 바뀌면 목록을 갱신한다. `현재 설정에서 관계 찾기` 상시 버튼은 제공하지 않으며, `FAILED` 안내 안에서만 현재 데이터를 유지한 채 `관계 정리 다시 시도`를 제공한다. 이 액션의 POST는 현재 설정의 관계 정리만 요청하며 AI 작업을 만들지 않는다. `NEVER_PROCESSED`·`PENDING`·`SUCCEEDED`에는 처리 요청 버튼이 없다. OFF에서는 상태 조회와 재시도도 호출하지 않는다.

재시도 요청의 응답이 실패했더라도 이후 상태 조회가 `PENDING` 또는 `SUCCEEDED`를 확인하면 이전 요청 오류를 지운다. 조회가 실패하거나 여전히 `FAILED`이면 오류를 유지한다. 상태 복구 확인이 늦은 요청 오류보다 먼저 도착한 경우도 복구된 상태를 우선한다.

`autoConfirmedCount`와 `reviewRequiredCount`는 **최근 처리 실행에서 발견한 개수**다. `확인·연결`의 현재 개수는 `relationship-candidates?status=PENDING`의 `totalElements`만 사용하며 선택적 연결 후보도 포함한다. `unsupportedSourceCount`는 명시적 형식으로 읽지 못한 설정 수이며 관계가 없다는 뜻으로 표시하지 않는다. 원래 설정 검토 화면의 대기 개수에는 더하지 않는다.

`SUCCEEDED`의 최근 처리 결과와 실행 건수는 가계도·가족 관계 목록·확인·연결 모든 보기에서 표시하지 않는다. 접힌 성공 요약도 제공하지 않는다. 처리 중·실패·아직 처리하지 않음과 조회 오류는 유지한다. 처리 상태 조회와 완료 시 Query 무효화는 계속 수행하며, 현재 PENDING 후보 집계는 별도로 유지한다.

## 설정집 업로드 안내

가계도 보기에는 설정집에 가족 관계를 적고 분석하면 확인된 관계가 반영된다는 짧은 안내와 `설정집 업로드하기` 버튼을 제공한다. 같은 작품의 `/dashboard?workId=…&nav=settingDB&tab=worldrules&modal=setting-book-upload`로 이동하며 기존 업로드 모달을 연다. 이동만으로 업로드·분석·가족 관계 생성을 요청하지 않는다. 실제 파일 제출은 기존 설정집 분석 계약을 따르고, 새 관계는 현재 설정 반영과 가족 관계 검증을 거친다. 원고 분석을 통한 기존 경로도 유지한다.

## 명시된 조상·후손 관계

`ANCESTOR_OF`는 주체가 상대의 조상, `DESCENDANT_OF`는 주체가 상대의 후손이라는 뜻이다. 확정 관계와 가계도 응답은 조상→후손의 `ANCESTOR_OF`로 정규화하며 후보 편집은 두 방향을 지원한다. 직접 부모·자녀와 별도로 표시하고 중간 인물이나 부모·혼인 관계를 추정해서 생성하지 않는다. 기존 설정의 명시적 관계를 정리하는 범위이며 추가 LLM 추출·비교는 요청하지 않는다.

후보·확정 관계·가계도와 수정 요청의 nullable `generationGap`은 조상·후손에만 사용할 수 있는 1 이상의 정수다. 명시된 값은 `N대손`, null/누락은 `세대 차이 미상`으로 표시하고 프론트에서 원문을 재해석하여 수치를 채우지 않는다. 세부 관계는 `UNSPECIFIED`·`BIOLOGICAL`만 제공한다. 원래 가족 설정과 근거 인용은 세대 수와 별도로 보존한다.

후보 그림은 조상 위·후손 아래의 두 카드와 점선으로 표시한다. 확정 요약은 조상 왼쪽·후손 오른쪽을 유지하며 후보 목록과 미등록 인물 근거도 관계 방향을 지킨다. 그림·목록·근거 요약의 `중간 계보 생략`은 해당 연결의 중간 인물을 표시하지 않는다는 뜻으로, 작품 전체에 중간 계보가 없다고 단정하지 않는다.

`대손 수`는 조상·후손 수정에서만 선택 입력으로 제공한다. 비우거나 다른 종류로 바꾸면 기존 수치를 제거한다. `판단 저장`은 저장된 세대 수를 유지하고 미저장 수치와 관계 편집은 화면에 보존한다. 외부 수정은 기존 `변경 내용 확인`을 거치며 직접 바꾼 수치와 호환되는 관계 종류를 함께 보존한다. `GENERATION_GAP_CONFLICT`는 기존 관계·원문 확인 안내로 표시하고 저장 응답에 검토 사유가 남으면 확정하지 않는다.

## 미등록 인물을 직접 묶기

표시 가능한 미등록 후보의 근거 패널에서 `같은 인물로 묶기`를 연다. 현재 관계와 사용자가 선택한 다른 관계의 주체·상대·관계·현재 설정 및 원문 근거를 확인한 뒤 2~20개를 명시적으로 묶는다. 이름이 같아도 자동 선택·병합하지 않는다. 이미 묶인 후보는 선택할 수 없으며 기존 묶음을 해제한 뒤 다시 선택한다.

`POST /relationship-mention-groups`에 표시 이름(1~200자), `requestId`, 각 `candidateId`·`expectedVersion`을 보낸다. 선택 때 개별 후보를 다시 읽어 근거를 보여 주고 서버는 버전과 현재 출처를 재검증한다. 충돌은 선택을 보존하며 필요한 경우에만 `선택한 근거 다시 확인`을 표시한다. 응답 유실 후 같은 요청의 재시도는 같은 `requestId`를 재사용한다.

가계도 묶음 노드는 `mentionGroupId`·`candidateIds`를 사용하며 클릭하면 각 관계로 전환해 별도의 근거를 읽는다. 프로필을 생성하지 않고 각 후보·간선·원문을 보존한다. `묶기 해제`는 그룹의 `expectedVersion`으로 모든 구성원을 분리한다. 개별 관계 내용·판단 저장, 프로필 연결·확정 또는 제외는 해당 후보만 묶음에서 분리한다. 원문 기반 처리와 LLM 추출 설정은 바꾸지 않는다. 관련 UI는 `FamilyMentionGrouping.tsx`·`family-mention-group.css`, mock 검증은 `e2e/family-mention-groups.spec.ts`에 둔다.

생성 시 순환·세대 충돌은 409로 거절된다. 생성 후 다른 설정 변경으로 그룹 조회의 `reviewReasons`에 충돌이 생기면 숨김 안내와 구체 사유를 표시하며 해제는 유지한다. `MENTION_GROUP_SOURCE_CHANGED`는 일부 구성원의 현재 근거가 달라졌다는 뜻으로, 남아 있는 유효 관계까지 모두 숨겨졌다고 안내하지 않는다.

2026-10-20 mock 검증: 그룹 E2E 6개와 기존 미등록 인물 E2E 5개가 통과했다. 명시 선택 전 쓰기 없음, 선택한 버전만 전송, 묶기·근거 전환·해제, 409의 선택 보존·명시 재확인, 응답 유실의 동일 요청 재시도 및 조회로 성공 확인 후 선택 폼 종료, 충돌 사유와 해제, 320px 넘침 없음·취소 초점을 확인했다. 관련 lint·TypeScript·diff 검사를 통과했으며 이 기록은 실제 서버·DB 또는 Pencil 검증을 대신하지 않는다.

## 확정 가족 관계 목록

가족 관계 목록은 하나의 흰 표면 안에서 구분선으로 행을 나눈다. 두 인물의 이름을 동등한 크기와 강조로 보여 주고 각 인물의 역할을 함께 읽게 한다. 부모는 왼쪽, 자녀는 오른쪽에 놓으며 `PARENT_OF`는 주체→상대, `CHILD_OF`는 상대→주체 순서로 표시한다. 배우자·형제자매는 두 이름 사이의 동등한 관계 표기를 사용한다. 관계 요약은 내용 폭에 맞춰 배치해 짧은 이름 사이에 큰 빈 열이 생기지 않게 한다. 긴 이름은 화면 폭 안에서 줄바꿈하며 가운데 관계 표기는 고정 폭으로 자르지 않는다. 응답에 없는 성별 호칭이나 사진을 추가 조회·추정하지 않고 `부모`·`자녀`를 사용한다. 가운뎃점으로 연결한 이름이나 반복되는 현재 관계 메타 정보는 넣지 않는다.

두 인물 아래의 메타 정보 줄에는 `validity`에 따른 반영됨·현재 설정 확인 필요·보관된 인물 포함·철회된 관계를 항상 표시한다. `VALID`가 아니면 `관계 기록`을 붙이고 정상적인 현재 가족 관계로 단정하지 않는다. `CURRENT`의 반복 표시는 줄이되 과거·시점 미상·`timeLabel`·명시된 세부 유형은 별도 보조 표기로 보존한다. `반영됨`은 관계의 유효 상태이며 기본 가계도에서 현재 보인다는 뜻이 아니다.

각 행은 하나의 native button이며 `aria-expanded`와 연결된 근거 영역을 제공한다. 행을 누르면 기존 관계 상세 API를 조회해 바로 아래에 근거를 펼치고, `hasEvidence`와 `sourceFactId`가 있는 설정의 기존 Fact 근거 API를 조회해 실제 인용문까지 바로 보여 준다. 접힌 목록에서는 원문을 요청하지 않는다. 후보와 미등록 인물도 원문 영역을 펼쳤을 때 같은 인용 조회를 시작하며, 아래의 원문 펼침 계약을 따른다. 설정 → 출처 → 인용문을 중첩 카드 없이 표시하고 작은 `전체 원문 보기`로 기존 모달을 연다. 원문 로딩·실패 후 재시도·빈 인용·전체 원문 없이 저장 인용만 있는 상태를 구분하며 조회 오류가 나면 이전 캐시 인용을 보여 주지 않는다. 펼침만으로 저장하지 않으며 다시 같은 행을 누르면 접는다. 페이지 밖 직접 링크와 가계도의 선택한 관계에도 같은 요약과 근거를 사용한다. 페이지·선택 URL, 이전 근거 보존, 철회 확인과 `expectedVersion`, 주기 조회·인증 보호는 유지한다.

펼친 설정은 근거의 `characterId`가 관계 양쪽 인물의 ID와 일치할 때 `인물 이름의 가족 설정`으로 소유자를 표시한다. 현재 프로필·이전 근거·직접 수정 여부와 구조화된 현재값의 표시/세부 설정 충돌도 보존하며, 일치하는 이름이 없으면 기존 일반 제목을 사용한다. 인물 순서나 설정 문장으로 근거 소유자를 추정하지 않는다. `current=false`여도 `hasEvidence=true`면 이전 인용을 조회할 수 있지만 현재 프로필 내용으로 대신하지 않으며, 보관된 인물처럼 `hasEvidence=false`인 근거는 원문 요청을 하지 않는다.

## 후보 검토와 동시 변경

후보 편집은 두 인물의 관계 그림 → 필요한 선택 → 자세한 근거 순서로 읽는다. 부모는 위, 자녀는 아래에 두고 배우자·형제는 같은 높이로 잇는다. `PARENT_OF`/`CHILD_OF`의 방향을 지키고 성별이나 추가 가족을 추정하지 않는다. `assertion`이 `ASSERTED`가 아니면 후보의 배치는 유지하되 점선·`확인 필요`·`검토할 관계`로 표시한다. 불확실한 관계를 확정된 가계도로 오해시키지 않으며, 프로필이 없다는 상태와 가족인지 불확실한 상태를 분리한다.

그림의 상대 인물 카드에 `프로필 미등록`/`프로필 등록됨`을 표시하고, 카드를 누르면 해당 인물과 같은 프로필을 고르는 목록을 연다. 상대는 작품의 인물 API를 페이지별로 조회해 직접 선택하며 같은 이름을 자동으로 연결하지 않는다. 선택 목록은 모든 인물을 이름과 `첫 등장 N화`로 통일하며 회차가 없으면 `첫 등장 회차 미확인`을 표시한다. 대표 속성값으로 첫 등장 정보를 대체하지 않는다. 목록을 닫거나 인물을 선택하면 상대 카드로 키보드 초점을 돌린다. 선택은 로컬 초안에만 반영하고 `연결할 프로필 · 저장 전`으로 표시한다. 선택을 해제하면 다시 `프로필 미등록`으로 보이며, 프로필 선택만으로 가족 여부를 확정하지 않는다. 별도 `상대 인물` 행과 중복 요약·긴 안내는 그림으로 대체한다.

실제 가족 설정은 그림 아래의 짧은 보조 정보로 보존한다. `ASSERTED` 후보는 `가족 관계예요`와 `판단 변경`을 표시하고, 불확실 후보는 `실제 가족이에요`·`가족이 아니에요`·`아직 모르겠어요`의 선택을 펼친다. `판단 저장`으로만 판단을 저장하며 다른 편집 초안을 함께 전송하지 않는다. 프로필만 없는 명확한 관계는 선택적 연결을 제공한다. 시점 미상은 별도 입력으로 드러내고 종류·세부 종류·시점 설명·원문 호칭은 접힌 `관계 내용 수정`에서 고친다. 표시값과 세부 설정값이 다르면 둘 다 보존하며 원문 근거는 접어서 제공한다. 가계도에서 여는 미등록 인물 근거 상세는 기존의 관계 문장 → 실제 가족 설정 → 접힌 원문 순서를 유지한다.

`관계 내용 수정`은 상대 이름과 `기준 인물에게 어떤 가족인가요?` 질문을 먼저 보여 준다. 선택지는 상대의 역할 기준이며 `부모`는 `CHILD_OF`, `자녀`는 `PARENT_OF`에 대응한다. 원문에 나온 이름, 가족의 세부 관계와 시점은 목적별 입력 묶음으로 나눈다. 수정 영역 끝에는 `변경사항 저장`을 둔다. 가족 여부 판단은 위쪽의 세 선택으로 통일하고 상시 재조회 버튼은 제거한다. 입력·초점·원문 호칭과 저장 방향은 유지하고 enum·API·추출 프롬프트는 바꾸지 않는다.

이전 `수정 저장` → `관계에 반영`의 두 버튼은 `프로필 연결하기` 또는 `가계도에 반영하기` 한 행동으로 대체했다. 필요한 PUT을 먼저 수행하고 **그 응답의 버전과 남은 보류 사유**로 확정 가능성을 확인한 뒤 confirm SDK를 호출한다. `ASSERTED`, 알려진 상대/시점, 유효 근거, 보류 사유 없음 조건과 서버의 최종 순환·보관·동시 변경 검증을 유지한다. 두 API를 원자적 요청으로 합친 것은 아니며 저장 뒤 확정 실패는 부분 성공을 안내하고 저장된 버전으로 재시도한다. 이전 철회 등 자동화 보류는 같은 명시적 행동의 저장 단계에서 재검토하며 남은 사유가 있으면 확정하지 않는다.

상대 프로필 없이도 `판단 저장`은 가능하며 저장 후 서버의 `displayableAsMention`을 다시 확인한다. 판단 저장만으로 가계도에 반드시 표시된다고 약속하지 않는다. `아직 모르겠어요`를 저장하면 `UNCERTAIN`으로 남기고 가계도에서 숨긴다. `선택 취소`는 판단만 원래대로 돌리고 다른 편집 초안은 유지한다. 후보 제외는 기존 가족 설정과 프로필을 삭제하지 않는다. 완료·제외된 후보에는 과거 판단 선택을 다시 표시하지 않는다.

`확인·연결` 목록은 현재 페이지에서 서버의 `displayableAsMention`에 따라 `확인할 가족 관계`와 `가족 프로필 연결`로 구분한다. 연결 제목 옆에는 `선택 사항`을 별도로 표시하며 이 구분을 작품 전체의 새 집계나 페이지 필터로 사용하지 않는다. 검토 목록과 후보 상세에서도 성공한 최근 처리 결과는 표시하지 않고 현재 판단을 우선하며, 처리 중·실패 안내는 유지한다. 표시 자격은 현재 초점·과거 포함 범위의 실제 그래프 포함 여부와 다르므로 `아직 가계도에 표시되지 않음` 같은 고정 안내를 붙이지 않는다.

후보 행은 하나의 흰 목록에서 구분선으로 나누며 상대 이름 → 기준 인물과의 관계 → 다음 행동 순으로 읽는다. `CHILD_OF`의 상대는 `비요른의 부모`, `PARENT_OF`의 상대는 기준 인물의 자녀로 표현하고 성별 호칭을 추정하지 않는다. 선택적 연결에는 단순한 현재 관계 메타 정보를 반복하지 않지만 과거 관계·시점 설명·세부 유형은 보존한다. 필수 확인 행에는 관계 문장 뒤의 `관계 확인`과 기존 보류 사유를 표시한다. 행 전체는 하나의 버튼으로 상세를 열고 저장 요청을 하지 않는다. 목록으로 돌아오면 열었던 행에 초점을 복귀하며, 반영되어 사라진 행 대신 목록 제목이나 현재 보기 조작으로 돌아간다. 기존 후보 ID·페이지·수정 및 확정 계약은 유지한다.

후보 `expectedVersion`과 근거 `sourceToken`은 편집 시작 때의 값을 보낸다. 저장/결정 실패 시 초안을 유지하고 자동 재시도하지 않는다. 편집 진입·변경 감지·저장 충돌 때 최신 후보와 PROFILE 근거를 자동 조회하며 상시 최신 설정 버튼은 제공하지 않는다. 조회 실패 때만 `다시 시도`를 표시한다. 조회만으로 입력·가족 판단·선택한 토큰을 바꾸지 않는다. 다른 곳에서 후보가 바뀌면 최신 내용을 보여 주고 저장을 잠그며 `변경 내용 확인` 후에만 최신 버전을 기준으로 저장한다. 확인 시 수정한 필드는 유지하고 손대지 않은 필드만 최신값으로 맞추지만 근거 토큰은 유지한다. 사용자가 현재 설정 체크박스를 명시적으로 선택해야 그 Fact의 토큰을 교체한다. 현재 슬롯에서 사라진 기존 근거는 명시적으로 제거할 수 있다. 정상 상태에는 근거 선택 버튼과 목록을 표시하지 않고, 변경·누락·인물 불일치 시에만 필요한 선택을 드러낸다. 근거는 1~20개, 호칭과 시점 설명은 각 200자까지다.

저장·결정의 성공 응답은 후보 상세 캐시에도 반영한다. 후속 조회가 느리거나 실패해도 본인의 성공 응답을 외부 변경으로 오인하지 않는다. 진행 중인 이전 상세 조회는 취소하고, 이미 조회한 더 높은 버전은 성공 응답으로 되돌리지 않아 실제 외부 변경의 잠금을 유지한다. 자동 조회는 기준 버전과 선택한 근거 토큰을 바꾸지 않으며 늦은 응답·작품 이탈·인증 세션 변경 후 결과를 적용하지 않는다.

자동 처리 상태가 그대로여도 다른 창의 수동 검토를 감지하도록 현재 대기 개수, 보고 있는 검토 목록, 열린 `PENDING` 후보를 5초마다 조회하고 창 복귀 시에도 확인한다. 후보 상세를 열면 목록 주기 조회는 멈추되 현재 대기 개수와 해당 후보는 계속 확인한다. 숨겨진 창에서는 주기 조회를 멈추고, 확정/제외된 후보나 닫힌 상세는 주기 조회하지 않는다. 다른 창에서 확정/제외해 목록이 줄어들면 현재 대기 개수와 마지막 유효 페이지도 함께 갱신한다. 최신 조회 결과는 초안과 편집 기준 버전을 덮어쓰지 않는다. 버전이나 상태가 바뀌면 결정을 잠그며 사용자가 다시 확인한 뒤에만 새 버전으로 저장한다. 조회 사이의 동시 수정도 서버의 `expectedVersion` 검증으로 보호한다.

관계 목록에는 현재/과거·철회·근거 변경·보관 상태를 모두 표시한다. 잘못 확정한 관계는 `이 연결 삭제`로 영향 확인을 열고 `삭제하기`로 기존 철회 API를 실행한다. `WITHDRAWN`은 화면에서 `삭제된 연결`로 표시한다. 기존 관계의 철회 표시와 버전만 변경하며 프로필 설정·인물·원문은 유지한다. 가계도에서는 연결이 제외되고 목록에는 철회 이력이 남는다. 같은 정규화 관계는 새 근거가 생겨도 자동으로 복원하지 않고 `PREVIOUSLY_WITHDRAWN` 검토 대상으로 보류한다. 작품 속 이혼·관계 종료는 캐릭터 설정을 고쳐 정리할 내용이며 잘못된 연결 삭제와 구분한다. 정정 API를 사용하는 직접 관계 재작성 UI는 이번 범위에 없다.

보고 있는 관계 목록과 열린 관계 상세도 5초 간격 및 창 복귀 시 조회해 다른 창의 수동 확정·철회를 반영한다. 대기 개수가 바뀌지 않는 철회도 감지하며 목록 밖 직접 링크의 상세에도 같은 규칙을 적용한다. 다른 보기와 숨겨진 창에서는 주기 조회하지 않고 철회가 확인된 상세의 주기 조회는 멈춘다.

### 후보·미등록 인물의 원문 펼침

후보 편집과 프로필 미등록 인물 근거의 원문 영역은 닫힌 상태로 시작한다. 펼쳤을 때에만 `hasEvidence=true`이고 `sourceFactId`가 있는 근거를 기존 Fact 근거 Query로 조회해 출처와 `evidenceSpans[].quote`를 바로 표시한다. native `details`가 닫혀 있다는 이유만으로 자식 컴포넌트의 Query가 멈춘다고 가정하지 않으며 실제 펼침 상태로 조회를 제어한다.

판단할 현재 설정은 후보 그림 아래 또는 미등록 인물의 상단 설정 영역에 그대로 남기고, 원문 영역에서는 같은 `currentValue`를 다시 카드로 반복하지 않는다. `RelationshipCurrentSetting`의 표시값·구조값 충돌과 추가 속성은 위쪽에서 보존한다. `current=false`의 이전 근거 경고와 원문 조회 불가 안내는 원문 영역에도 유지한다. 현재 설정을 원문 인용으로 대신하거나 인용을 새로 추출하지 않는다.

로딩·실패·빈 인용·본문 없는 저장 인용을 구분하고, 재조회가 실패하면 이전 캐시의 인용을 노출하지 않는다. 전체 원문 행동은 기존 모달과 Fact ID를 사용한다. 조회만으로 관계 판단·수정·확정·제외를 요청하지 않으며 고정 근거 토큰, 초안, 작품·세션별 Query 격리와 로그아웃 시 취소·정리를 유지한다.

## GH261 가계도 화면과 조회 계약

가계도의 기본 조회는 `GET /api/v1/works/{workId}/family-tree?includeHistorical=false&limit=100`이다. 인물은 `{id,name}`, 간선은 실제 관계 ID·버전·양끝 ID·종류·세부 종류·시점·시점 설명만 받는다. 전체 근거나 원문을 그래프 응답에 넣지 않으며, 관계/Fact를 선택할 때 기존 상세 API를 읽는다. 목록 API의 20개 페이지를 반복 조회하거나 캐릭터 이름으로 별도 연결을 만들지 않는다. 생성 SDK는 변경된 Java OpenAPI에서 다시 생성했다.

서버는 `VALID+CURRENT`만 기본으로 제공하고 과거 옵션에서 `VALID+HISTORICAL`을 추가한다. 시점 미상·철회·재확인 필요·보관 인물 관계는 도형에 넣지 않고 기존 목록에서 확인한다. 노드는 반환 간선의 양끝 인물 및 선택 초점 인물이며 작품의 모든 무관계 인물을 한꺼번에 싣지 않는다. 응답은 최대 100개 간선을 표시하고 `truncated`, 상한 전 인물/간선 수를 함께 받는다(서버가 허용하는 최대 요청은 200). 잘림을 숨기지 않고 인물 중심 보기·전체 목록으로 안내한다. 현재 가계도 내 이름 검색과 전체 인물의 페이지 선택을 구분한다.

`FamilyTreeView`는 5초·창 복귀 시 조회하고, 숨겨진 창에서는 주기 조회를 멈춘다. 후보 결정·철회·처리 상태 변경은 가계도 캐시도 무효화한다. 서버의 revision은 자동 처리뿐 아니라 수동 결정·이름·범위의 변화를 표현하며 쓰기 버전이나 인증 수단이 아니다. 배치는 인물·간선 입력으로 별도 캐시하므로 후보 개수만 바뀐 조회는 배치 엔진을 다시 실행하지 않는다. 작품 이동/로그아웃은 기존 Query 취소·세션 격리를 따른다. 조회가 실패하면 과거 도형을 숨겨 보관 인물 등이 현재처럼 보이거나 클릭되지 않게 하며 재조회 복구 시 읽던 viewport를 유지한다.

React Flow가 이동·확대·선택을 맡고 ELK 및 가족 제약 함수가 위치를 계산한다. 인물 카드는 실제 인물 ID별 하나씩 제공한다. 화면의 connections는 확인된 부모 집합과 자녀를 한 줄기로 묶고, 모든 원본 관계 ID를 정확히 한 묶음에 보존한다. 한 관계는 바로 근거를 열고 여러 관계는 하단 선택 목록에서 각각의 근거를 연다. 순환·세대 충돌은 설명을 붙이고 원래 관계 방향을 뒤집지 않는다. 입양·재혼 가족·형제 종류·과거 표시는 선 모양과 글자로 구분한다. 좌우 순서는 성별/출생순을 뜻하지 않는다. 배치 알고리즘과 Mermaid 실측 비교는 [배치 검증 문서](family-tree-layout.md)에 기록했다.

처음 진입·표시 범위 변경·`전체 보기`만 인물과 관계 이름을 모두 포함한 전체 배치 영역으로 맞춘다. 주기 갱신·상세 열기/닫기는 확대·이동 상태를 보존한다. 키보드로 화면 밖 인물/관계 버튼에 초점이 오면 현재 확대 배율로 해당 위치를 보여준다. 긴 이름은 카드 두 줄로 제한하고 세부 관계 유형·시점 설명은 선택 목록과 근거에서 읽는다. 모바일은 동일한 가족 구조에 이름 중심의 112×72 카드를 사용하며 확대/축소/전체 보기 조작과 목록 보기를 제공한다. 드래그 좌표 저장·일반 관계·타임라인 재생·내보내기는 이번 범위가 아니다.

인물 카드의 크기와 연결 위치가 고정이므로 React Flow 노드의 `handles`도 명시한다. controlled 노드 갱신 때 측정된 연결점이 초기화되어 관계 버튼이 잠시 제거되고 초점을 잃는 문제를 막는다. 키보드 이동은 그래프 좌표와 현재 viewport로 가시성을 판단하여 브라우저의 순간적인 focus 스크롤과 구분한다. 관계 이름 클릭은 선의 클릭 이벤트로 중복 전파하지 않으며 근거 닫기는 URL 변경 뒤 현재 버튼으로 초점을 돌린다.

프로필은 `CharacterDatabase`의 `detailOnly` 경로로 기존 모달을 재사용한다. 인물 디렉터리를 뒤에서 중복 마운트하지 않는다. 가계도 진입의 프로필에는 초기 초점·Tab 순환·Escape 닫기와 호출 버튼으로 초점 복귀를 제공한다. 저장된 프로필은 기존 자동 정리 경로를 거쳐 가계도에 반영되며 LLM 호출/프롬프트/추출 스키마를 추가하지 않는다. 기존 작품 백필은 화면 버튼과 별개의 운영 절차이며 Backend의 `docs/family-tree-v1.md`를 따른다. 운영 데이터의 일회성 백필은 2026-10-21에 별도로 완료했고 화면 공개나 머지로 다시 실행하지 않는다.

## 2026-10-19 미등록 가족 이름과 선택적 인물 연결

비요른의 현재 프로필에 `얀델의 아들`이 있고 얀델이 캐릭터로 등록되지 않았더라도, 서버가 현재 근거와 명시성을 검증한 경우 가계도에 `얀델 · 설정에서만 언급`을 표시한다. `MENTION`은 캐릭터 등록이나 기존 캐릭터 간 관계 확정을 뜻하지 않는다. 캐릭터 행·LLM 호출·새 관계 테이블을 추가하지 않고 기존 후보의 이름과 근거를 표현한다. 기존 PENDING 상태는 직접 연결할 때까지 유지한다.

가계도 노드·간선 ID `mention:<candidateId>`는 같은 이름이라도 후보별로 분리한다. 노드의 `nodeType`, `characterId`/`candidateId`와 간선의 `sourceType`, `relationshipId`/`candidateId`, `subjectNodeId`/`objectNodeId`를 사용한다. 이 그래프 ID를 캐릭터 조회나 `focusCharacterId`로 보내지 않는다. 등록된 인물은 기존 프로필을 열고, 미등록 인물은 `언급된 인물 근거`에서 현재 설정·원문 근거를 표시한다. 검색에서 언급 이름을 선택해도 근거를 연다.

당시의 `인물 연결·수정` → 상대 인물 선택 → 수정 저장 → 관계에 반영 흐름은 이후 사용자 중심 교정으로 `프로필 연결` → 상대 선택 → `프로필 연결하기`로 대체했다. 기존 후보 API의 버전·현재 근거·작품 소유권·순환 검사를 유지하며 연결은 선택 사항이다. 같은 이름의 캐릭터가 나중에 나타나도 자동 연결하지 않는다. 연결이 확정되면 언급 노드는 사라지고 실제 캐릭터와 확정 관계로 표시한다. 위 초기 캡처와 검증 기록은 당시 화면에 대한 기록이다.

`pendingCandidateCount`는 작품의 전체 PENDING 수이고 `optionalLinkCount`는 현재 근거가 유효하여 선택적으로 연결할 수 있는 미등록 후보 수다. 두 수는 초점·과거 포함·표시 상한과 독립된 작품 전체 집계다. 화면은 `확인·연결`에서 필수 확인과 선택적 연결을 구분한다. 상세의 `displayableAsMention`도 서버가 판단하므로 프론트가 후보 이름이나 보류 문자열로 표시 가능성을 추측하지 않는다. 근거 소실·보관·제외·불확실·부정·상충 등의 안전 경계는 Backend의 현재 판정을 따른다.

실제 원고의 추출 품질과 합성 현재 프로필의 API·DB 연동 검증은 구분한다. 이번 실연동 시나리오는 직접 저장한 `얀델의 아들`에서 언급 표시·근거 확인·늦게 사용 가능해진 상대의 직접 연결을 확인하며 원고→LLM 추출 검증은 아니다.

### 2026-10-20 가족 판단 한 곳으로 통일

가족 선택은 기존 PUT으로 `ASSERTED`, 아직 모름은 `UNCERTAIN`을 저장하며 후보는 `PENDING`을 유지한다. 불확실 판단을 저장하면 가계도에서 제외되고 재진입해도 남는다. 가족이 아님은 기존 dismiss로 제외한다. 판단 저장은 확정을 호출하지 않으며 프로필을 자동 연결하지 않는다. 가족으로 다시 판단해도 서버가 표시 조건을 다시 검증한다. `선택 취소`와 목록 복귀는 저장하지 않는다. 이전의 무저장 보류 행동은 이 계약으로 대체한다.

판단 PUT은 baseline 관계 필드와 선택한 assertion, 사용자가 명시적으로 선택한 근거를 보낸다. 미저장 상대·관계·시점은 서버에 섞어 보내지 않고 화면에 보존하며 별도 수정 저장/프로필 반영을 사용한다. 판단 편집 중에는 이 별도 저장·반영을 잠근다. 현재 근거 토큰과 expectedVersion·중복 제출·늦은 응답·세션 변경·저장 후 확정 부분 실패 보호를 유지한다. 동일 원본 자동 처리는 수동 판단을 보존하지만 원본 Fact/슬롯 토큰이 변경되면 새 후보가 생길 수 있다. API·LLM·기본 OFF 정책은 바꾸지 않는다.
