# GH441 심사 계정 전용 결제 화면

[추적 이슈](https://github.com/catchhole-soma/catchhole-backend-java/issues/441). 이 작업은 상품 안내에서 KG이니시스 테스트 결제창을 여는 단계까지다. 서버 주문·결제 검증·충전 원장·실제 환불은 구현하지 않는다.

## 실행

```sh
npm install
npm run dev -- --port 3441
```

`http://localhost:3441/dev/payment-review`는 Vite 개발 모드에만 있는 미리보기다. 인증된 사용자 데이터/API를 읽거나 인증을 우회하지 않는다. 실제 회원용 `/billing`, `/billing/terms`, `/billing/privacy`는 `VITE_PAYMENT_REVIEW_ENABLED=true`일 때 기존 PrivateRoute와 서버 권한 확인을 모두 통과해야 열린다. 서버 `PAYMENT_REVIEW_ENABLED=true` 및 `PAYMENT_REVIEW_MEMBER_IDS`에 등록된 현재 회원만 허용하며 기본값은 OFF·빈 목록이다. 관리자도 자동 허용하지 않는다. 프론트 플래그만 켜면 일반 회원에게 노출되지 않는다.

개발 미리보기만 `.env.local`에 PortOne 콘솔에서 **테스트 / KG이니시스 / inicis_v2 / INIpayTest**임을 확인한 채널의 공개 식별값만 넣는다.

```dotenv
VITE_PAYMENT_REVIEW_ENABLED=true
VITE_PORTONE_TEST_STORE_ID=store-...
VITE_PORTONE_TEST_CHANNEL_KEY=channel-key-...
```

이니시스 MID는 PortOne storeId와 다르다. REST API secret·signkey·INIAPI Key는 프론트 환경변수에 넣지 않는다. TEST라는 환경변수 이름이 실제 채널 종류를 강제하지는 않으므로 콘솔에서 테스트 채널인지 확인한다. 실채널로 바꾸어 판매하는 것은 이 작업 범위가 아니다.

## 표시와 결과 처리

- 심사용 상품은 2,900원 400만 / 4,900원 800만 캐치홀 토큰, 모두 부가세 포함·일회 결제다. 고객 화면·구매조건과 런타임 상품 정의에서 이벤트 문구·기간·이후 판매가를 제거해 현재 결제 금액만 표시한다. 모델별 차감률을 적용한 서비스 사용량 단위이며 원시 토큰과 구별한다. 상품 카드·선택 요약·구매조건·PG 주문명에 지급량을 표시한다. 카드와 선택 요약에는 각각 예상 15~30 / 30~60회차를 표시하고, 회차당 공백 포함 5,000자 기본 분석 기준과 변동·공통 차감 안내를 함께 둔다.
- 원고 분석·재분석·설정집 분석·AI 대화 등 모든 AI 기능에서 공통 사용한다. 회차당 고정 차감이 아니라 실제 AI 사용량에 따라 소비한다. 무료분 우선, 유료분끼리는 먼저 만료되는 구매분부터 사용하며 무료분을 쓰는 동안에도 유료분의 12개월 기간은 연장하지 않는다.
- 구매분마다 12개월. 미사용 전액 / 일부 사용 잔여 유료분 비례 환불 / 만료·종료 잔여 유료분 자동 환불은 출시 전 구매조건 초안이다. 자동 환불이 현재 구현됐다는 의미가 아니다.
- `/billing`은 서버 `/api/v1/payment-reviews/page`의 구매조건·법률 원문을 렌더링한다. 개발 미리보기만 `docs/legal/*.paid.draft.ko.md`와 구매조건의 로컬 사본을 사용한다. 사용자의 화면 정리 요청으로 테스트·미리보기·초안 표시와 개발 상태 설명은 화면·메뉴·버튼에서 제거했으며, 실제 구현 범위는 이 내부 문서에서 관리한다. `PUBLISHED` 법률 문서처럼 가짜 ID·시행일을 부여하지 않는다. `/terms`, `/privacy`, 회원가입 동의는 기존 Backend 게시 문서 API를 그대로 사용한다.
- 선택 상품 변경·새로고침 시 확인 체크가 해제된다. 클릭 중에는 상품·구매정보·재요청을 잠근다. 개인정보는 입력 상태에만 두고 local/sessionStorage나 로그에 저장하지 않는다.
- PortOne V2 카드 결제, `DIGITAL`, `offerPeriod.interval=12m`. 실제 이니시스 PC 창이 `oid` 길이 40자를 제한하여 `review-` + 하이픈 제거 UUID(39자)를 사용한다.
- 동일 출처 복귀 URL에 상품 ID만 넣고 `forceRedirect=true`로 PC/모바일 결과 경로를 통일한다. 오류 원문·PG 메시지는 표시하지 않는다. 성공처럼 생긴 임의 query에도 결제 완료·잔액 증가를 표시하지 않고 서버 쓰기 API를 호출하지 않는다.
- SDK 로딩 실패는 같은 SDK가 실패 Promise를 보관하므로 화면 새로고침을 안내한다. 자동 재요청하지 않는다.

## 심사 및 판매 전 남은 준비

1. 지급량·차감 단위·사용 순서는 확정했다. 시스템 오류로 실패한 작업의 차감분 복원, 수동 재분석 차감, 원 미만 환불액 올림, 환불 요청일부터 3영업일 이내 취소·환급 조치를 확정했다. 후속 결제 원장에서 구현한다. 현재 무료 사용량 코드의 동작을 유료 정책으로 암묵적으로 승인하지 않는다.
2. 고객센터는 070-8027-2690, 전화 상담 평일 10:00~18:00으로 확정했다(2026-11-19 사용자 제공). Front 기본값과 심사 원문에 반영했으며 수신 테스트와 운영 반영은 남아 있다. `VITE_CUSTOMER_SERVICE_PHONE`에 기존 다른 값이 설정되어 있으면 배포 전 확정 번호로 맞춘다. 통신판매업 신고 여부를 확인한 뒤 실제 신고번호가 있으면 `VITE_MAIL_ORDER_REGISTRATION`에 넣는다. 미확정 상태를 면제로 표시하지 않는다.
3. 심사에서는 허용된 계정에만 `/billing/terms`, `/billing/privacy`로 개정안을 제공한다. 실판매 전 유료 조건·처리기한·PG 개인정보 처리 내용을 확정하고 법률 문서의 **새 버전**을 Backend에 게시한다. 기존 게시 원문과 동의 이력은 보존한다. 미리보기 초안과 실제 구매 동의 기록은 구별한다.
4. 일반 회원과 동일한 인증의 새 심사용 계정을 준비한다. 일반 회원 권한과 비어 있는 개인 작업 공간을 사용하며 특별한 심사자 역할은 만들지 않는다. 실제 생성된 회원 번호를 서버의 심사 허용 목록에 등록하는 것은 별도 운영 단계다. 이메일·브라우저 저장소로 권한을 부여하지 않는다. URL을 숨기는 것만으로 계정이 분리되는 것은 아니다. ID/PW는 코드·이슈에 기록하지 않는다.
5. 실제 서비스 URL에 확정 상품·사업자 정보·약관과 테스트 결제창을 반영한 뒤 심사를 요청한다. 실행 순서와 사용자에게 남은 항목은 [배포 준비 절차](payment-release-readiness.md)에 기록한다.
6. 이벤트 계획은 내부 기록으로만 유지한다(정식 유료 판매 시작일부터 60일, 이후 기본 9,900원/더블 16,900원). 심사 후 출시 준비에서 실제 시작·종료 시각을 확정하고 화면·구매조건·서버 적용 가격에 함께 반영한다. 현재 런타임에는 예정가나 자동 가격 전환이 없다. 서버 가격 검증, 주문/승인/웹훅 멱등성, 지급·차감 원장, 환불·만료 처리와 동의를 구현·검증한다.

## 확정한 지급량과 차감 단위

2026-11-18 사용자 결정: 최종 상품은 기본 충전권 2,900원에 **4,000,000**, 더블 충전권 4,900원에 **8,000,000** 캐치홀 토큰을 지급한다. 이번 결정으로 정확한 지급량을 확정했으며 회차 수 실측을 가격·지급량 확정의 선행 조건으로 두지 않는다. 모든 AI 기능에서 공통 사용, 무료분 우선·유료분 만료순, 구매별 12개월·잔여분 비례 환불 조건은 유지한다.

- 차감 단위는 Java `AiTokenChargePolicy.MODEL_WEIGHTED_V1`의 `charged_tokens`와 같다. raw input/output 합계와 구별한다. `gpt-6-luna`는 raw의 1/20, 그 외 모델은 1배이며 서비스 부담 백필은 0이다. cached input은 input에 포함되어 다시 더하지 않는다. 이 계산은 개발·운영용 내부 기준이며 고객 화면과 구매조건에는 모델명·환산율·캐시 계산을 노출하지 않는다. 공개 안내는 캐치홀 토큰이 서비스 이용 단위임을 정의하고, 확정 지급량과 실제 AI 사용량 및 기능·원고·누적 설정·대화 분량에 따른 차감량 변동을 설명한다. 모델 선택·환산율 변경 때에는 공개한 예상 분량과 구매조건에 미치는 영향을 다시 검토한다.
- `AI_TOKEN_DEFAULT_GRANT`의 코드 기본값 2,000,000은 별도 무료 지급 설정이다. 이번 유료 상품 결정으로 무료 지급량이나 기존 회원의 잔액을 바꾸지 않는다.
- 프론트 상품 정의는 미리보기 표시용이다. 서버의 실제 지급·차감·환불이나 단가 검증은 아직 구현하지 않았다. 후속 서버 상품 설정에는 4,000,000 / 8,000,000을 명시하고 클라이언트 표시를 지급 권한으로 사용하지 않는다.
- 사용자 선택으로 공백 포함 5,000자 기준 기본 예상 15~30회차 / 더블 예상 30~60회차를 안내한다. 이는 상품 안내용 추정치이며 동일 조건의 실측 분포나 최소·최대 보장량이 아니다. 기존 운영 표본은 공백 제외 분량·서로 다른 모델/버전이므로 이 구간을 검증한 결과처럼 쓰지 않는다. 원고 길이·누적 설정의 양과 복잡도·분석 방식에 따라 범위를 벗어날 수 있고, 다른 AI 기능과 공통 차감하므로 잔액·환불은 토큰 수량을 기준으로 한다. 상품량 2배를 누적 회차 비용이 선형이라는 근거로 사용하지 않는다.
- 추후 안내 분량의 정확도를 검증할 때는 원고 사용 권한·현재 분석 버전·AI 호출 예산을 정하고 격리된 새 작품 1~20회차의 전체 기본 분석과 자동 반영 완료까지 측정한다. 모든 관련 하위 호출의 `charged_tokens`를 모으며 채팅·수동 재분석·운영 백필과 미완료·사용량 미확인 실행은 분리한다. 이번 작업에서는 새 유료 AI 호출을 실행하지 않았다.

## 검증

### 2026-11-18 운영 사용량 확인

사용자 요청으로 본인 작품의 21~40화 운영 원장을 읽기 전용으로 확인했다. 2026-11-03 실행이며 20화 모두 `SUCCEEDED`·`SEALED`·자동 반영 완료다. 총 354개 호출 원장 중 352개는 정산, 2개는 예약 해제이며 미정산/UNKNOWN은 없다. 해당 회차 분석 Job에 속한 추출·비교·관계 분석과 실행 중 재시도를 합산했고, 챗봇·검수·서비스 부담 색인은 섞지 않았다.

- 원시 토큰 합계 5,960,858, 실제 환산 차감 합계 **5,581,670.25**, 회차 평균 **279,083.5125**다. 이 실행의 평균에 대입하면 250만은 약 8.96화, 500만은 약 17.92화다. 이는 변경 전 250만/500만 상품에 대한 당시 비교 기록이며, 현재 400만/800만 상품의 예상 구간을 실측한 결과가 아니다.
- DB의 `char_count`는 공백 제외 기준이다. 20화 합계 103,122자·평균 5,156.1자여서, 이전에 논의한 ‘공백 포함 5,000자 × 신규 1~20화’와 같은 실험 조건이 아니다. 11월 3일 이후 모델/프롬프트도 바뀌었으므로 현재 모든 작품의 사용량으로 일반화하지 않는다.
- 현재 운영 API 이미지 revision `9ca148db0c3c5832fdcf8e805ff7f446b549c671`의 정책과 실제 원장이 일치한다. 정확한 `gpt-6-luna`는 용도와 무관하게 1/20, 다른 모델은 1배다. 챗봇에만 1/10을 적용하는 분기는 없다. 챗봇 검색 임베딩은 1배, 서비스 부담 백필은 0이다.
- 현재 AI 워커와 챗봇은 이미지 `sha-2224096`이다. 챗봇은 Luna, 인물 추출·비교는 Terra, 세계관 추출은 Sol, 지칭어/대상 선택은 Luna 설정이다. 분석 전체가 Luna로 바뀐 상태가 아니다.
- 운영 `AI_TOKEN_DEFAULT_GRANT`는 **5,000,000**이다. 앞서 확인한 코드 기본값 2,000,000과 구별하며, 이번 상품 설정으로 이 무료 지급 설정을 바꾸지 않았다. 운영 데이터·설정 변경과 추가 AI 호출은 하지 않았다.

개인 계정의 작품 식별자와 상세 조회 결과는 이 저장소/공개 이슈에 넣지 않는다. 로컬 `.codex-artifacts/payment-usage-audit-20261118/`에 소유자 전용 JSON·회차별 CSV·읽기 전용 SQL을 보관한다.

### 2026-11-18 추가 작품 비교

사용자 요청으로 운영에서 20화 이상 완료된 19개 작품을 찾고, 다른 작품 4개의 20화 구간을 익명 집계했다. 재분석이 섞인 최신 후보 1개와 미정산 예약이 있는 구간은 주 비교에서 제외하고, 각 구간의 회차별 완료 분석 20개·자동 반영 완료·미정산 없음·분량 메타데이터와 원문 리비전 일치를 확인했다. 분석 하위 호출과 실제 실행 중 사용량은 합산하되 챗봇·회차 검수는 제외한다.

- 추가 작품 4개의 실제 차감 합계는 **1,574,990.70 / 2,035,672.50 / 2,389,802.85 / 4,525,448.75**다. 앞의 3개는 1~20화·공백 제외 회차 평균 약 3,317~4,068자, 마지막은 21~40화·평균 약 6,019자다. 편의표본이며 전체 이용자의 평균·공백 포함 5,000자 실험으로 간주하지 않는다.
- 같은 사용자 작품의 1~20화는 **2,961,502.15**, 21~40화는 **5,581,670.25**였다. 원고 분량은 10.88% 증가했지만 설정 비교 호출은 149→236회, 호출당 평균 입력은 12,612→17,692 토큰, 비교 차감량은 2,001,539→4,361,810으로 늘었다. 이 두 구간에서 비교 모델은 동일한 Sol이며 회차 분석 작업은 각각 20개다. 반복된 전체 재분석을 합쳐서 생긴 차이가 아니다.
- 따라서 단일 후반 구간을 모든 작품의 기본 비용으로 일반화하거나 지급량을 자동으로 600만/1,200만으로 바꾸지 않는다. 당시 비교 단계에서는 250만/500만 상품을 유지했으며, 이후 사용자가 400만/800만으로 변경하기로 했다. 250만 이내에 20화를 완료한 사례가 3개 있지만 작품·분량·누적 설정·실행 버전에 따라 달라지므로 모든 작품에 약 20화를 약속하는 문구는 넣지 않는다.
- Meter의 `attempt`는 호출마다 누적하는 순번이므로 `attempt > 1`을 실패 재시도 횟수로 해석하지 않는다. 상세 익명 비교는 로컬 `comparison-20-episodes.csv`·`comparison-summary.json`에 남겼다. 운영 원장·설정 수정이나 새 AI 호출은 없었다.

개정 이용약관·개인정보처리방침은 허용 회원의 `/billing/terms`, `/billing/privacy`와 개발 전용 미리보기에서 확인한다. 서버 resources/payment-review의 세 원문이 심사 응답의 출처이며 이 저장소 docs/legal의 사본과 일치시킨다. 공개 `/terms`, `/privacy`와 가입 동의는 기존 Backend 게시본을 유지한다. 로컬 원문과 개발 경로는 운영 번들에 포함하지 않는다.

## 2026-11-19 심사 계정 접근 제한

- `GET /api/v1/payment-reviews/access`: 인증 회원의 접근 여부만 반환. `GET /api/v1/payment-reviews/page`: 매번 허용 목록을 검사하고 일반 회원은 403. 두 응답은 `Cache-Control: no-store`다.
- `page` 응답으로 채널 설정·구매조건·이용약관·개인정보처리방침을 받는다. 회원 ID는 클라이언트 요청으로 받지 않고 기존 JWT→DB의 현재 활성 회원을 사용한다. 유료 주문·원장·회원 역할·DB schema는 추가하지 않는다.
- 메뉴와 세 화면은 권한 조회 실패·미완료·불완전 응답이면 닫는다. 비로그인은 로그인, 미허용 회원은 내 작품으로 이동한다. Query는 기존 인증 세대에 묶고 이전 세대의 지연 응답/캐시를 재사용하지 않는다.
- 결제창 직전 `page`를 캐시 없이 재조회하고, SDK 로드가 끝난 뒤에도 인증 세대와 현재 경로를 확인한다. 화면을 떠나면 진행 중인 권한 조회를 취소하고 뒤늦은 결제창을 열지 않는다. 실패 envelope의 잔여 data로 접근을 허용하지 않는다. 허용 목록 회수 뒤 새 결제창 요청은 막힌다. 이미 내려받은 공개 SDK 식별값을 비밀 키나 결제 승인 권한으로 간주하지 않는다. 이미 열린 외부 PG 창을 서버 설정으로 회수하는 기능은 없다.
- 서버 환경변수 `PAYMENT_REVIEW_ENABLED`, `PAYMENT_REVIEW_MEMBER_IDS`(쉼표 구분), `PAYMENT_REVIEW_STORE_ID`, `PAYMENT_REVIEW_CHANNEL_KEY`는 API Compose에 전달된다. Worker 설정에는 필요 없다. 변경 뒤 API 재시작/재배포가 필요하며 운영 적용은 수행하지 않았다.
- 기존 상품 표시의 가격·지급량은 UI 정의다. 실제 결제를 출시할 때 서버의 주문/가격/지급 검증을 추가해야 한다. 본 PR은 TEST 채널만 연결한다.
- [공식 PortOne 안내](https://help.portone.io/content/requirements)는 실 서비스에서 특정 로그인 계정에게만 심사 상품을 노출하는 방식을 허용한다. 메인 사업자 정보는 공개를 유지한다.
