# 첫 분석의 설정 반영 방식 안내

계정 전체에서 아직 분석을 시작하지 않은 작가에게 자동 반영과 직접 검토의 저장 시점을 예시로 보여준다. 작품마다 또는 첫 2~3회 분석마다 반복하지 않는다.

## 진입과 노출

- `/episode-upload?workId=<id>`에서 업로드 방식을 선택하면 안내 자격을 조회한다. 서버가 계정 전체 분석 이력과 안내 기록을 판단한다. 프론트에서 작품별 목록을 합산하거나 브라우저 저장소로 자격을 판단하지 않는다.
- `GET /api/v1/analysis-mode-guide`는 `{ shouldShow }`를 반환하며 기록을 변경하지 않는다. `POST /api/v1/analysis-mode-guide/claim`이 다시 자격을 확인하고 계정당 한 번만 `true`를 반환한다. 생성 SDK를 사용하며 Query 캐시는 회원 ID로 구분한다.
- 다른 모달·사용자 메뉴·입력 조작 중에는 자동 안내를 기다린다. 조회/선점 실패는 업로드를 막지 않으며 자동 재시도하지 않는다. 선점 후 화면 이탈 등으로 실제 표시가 취소되더라도 자동 안내를 반복하지 않는 정책이다.
- 한 번 안내한 계정은 닫기·새로고침·새 작품·다른 브라우저에서 다시 자동 노출하지 않는다. 이미 분석한 계정도 자동 안내하지 않는다. 별도 `다시 보지 않음` 선택 없이 닫으면 충분하다.
- `두 방식의 차이 보기` 도움말은 언제든 연다. 다회차는 `자동 반영 과정 보기`만 제공한다. 안내를 열거나 닫아도 기존 업로드 방식·직접 검토 선택·입력을 변경하지 않는다.

## 예시 흐름

| 단계 | 내용 |
| --- | --- |
| 1. 반영 방식 | 실제 업로드 화면에서 자동 반영 또는 직접 검토가 선택된 모습을 보여준다. |
| 2. 분석 결과 | 자동 반영은 명확한 2개 저장/1개 확인, 직접 검토는 0개 저장/3개 확인으로 비교한다. |
| 3. 검토 화면 | 실제 상세에서 자동 반영은 대상이 모호한 치유 능력 1개, 직접 검토는 종족·직업·치유 능력 3개를 확인하는 차이를 보여준다. |
| 4. 확정 후 | 사람이 남은 설정을 직접 확인하고 확정한 뒤의 예시로, 두 방식 모두 반영됨 3개/직접 확인 0개를 보여준다. 안내의 다음 버튼이 실제 설정을 확정하지 않는다. |

- 방향키 ←/→, 이전/다음, 단계 버튼으로 이동한다. 방식 탭에 초점이 있으면 방향키/Home/End는 탭만 바꾸고 같은 단계를 유지한다. 대상 선택·확정 실습 입력은 없다.
- 모달은 최대 1,320px, 화면 높이에 맞춰 최대 1,080px까지 확장한다. 모든 화면 크기에서 탭으로 한 방식씩 크게 비교한다. 600px 이하에서는 실제 모바일 화면 캡처를 표시한다. 다회차는 자동 반영 예시와 앞 회차 저장 후 다음 회차 분석 안내만 보여준다.
- 모달 안 본문만 스크롤하며 닫기·이전·다음은 320×568에서도 접근할 수 있다. 초점 가두기·Esc·원래 버튼으로 초점 복귀는 공용 Radix 모달 계약을 따른다.
- `guide=analysis-mode`, `guideStep=1..4`, 선택적 `guideVariant=multiple`, `guideMode=automatic|manual`을 URL에 저장한다. 단계·방식 변경은 history를 대체하며 닫기는 이 네 값만 제거한다. 새로고침 시 단계와 비교 방식이 복원된다.
- 안내는 실제 업로드·설정 검토 컴포넌트에 가상의 예시 데이터를 넣어 촬영한 정적 화면이다. 이미지에 단계별 대체 설명을 제공하며, 로드 실패 시 설명과 탐색은 유지한다. 실제 분석·원고 업로드·설정 생성/확정 API와 LLM을 호출하지 않는다. 서버에 남는 것은 계정의 안내 기록뿐이다. 서버 오류를 예시 데이터로 대체하는 기능이 아니다.

## 실제 화면 자산 갱신

`e2e/analysis-guide-capture.spec.ts`가 실제 `/episode-upload`, `/setting-review`를 fixture API로 렌더링한다. `src/assets/onboarding/`의 2방식 × 4단계 × 데스크톱/모바일 PNG 16장을 생성한다. 실제 UI가 바뀌면 캡처를 다시 생성하고 안내의 단계별 의미·미처리 개수와 모바일 잘림을 함께 확인한다.

```bash
CATCHHOLE_CAPTURE_ANALYSIS_GUIDE=1 npx playwright test e2e/analysis-guide-capture.spec.ts --workers=1
```

일반 E2E 실행에서는 자산 생성 테스트를 건너뛴다. 촬영은 가상의 원고·인물·설정만 사용하며 실제 회원 데이터나 서버 쓰기 요청을 사용하지 않는다. 런타임에는 번들 자산을 로드하며 캡처용 fixture API를 설치하지 않는다.

## 검증과 디자인

- `e2e/analysis-mode-guide.spec.ts`: 계정 1회, 새 작품/새로고침, 오류/동시 선점, 수동 도움말, URL 복원, 탭·방향키·단계 탐색, 현재 업로드 선택 보존, 실습 입력·설정 쓰기 부재, 320px 본문 스크롤·모바일 이미지·44px 버튼.
- `e2e/analysis-mode-guide-live.spec.ts`: 분석 이력 없는 격리 계정용 `CATCHHOLE_GUIDE_E2E_EMAIL/PASSWORD`와 `CATCHHOLE_E2E_API_BASE_URL`이 있을 때만 실행한다. 실제 계정에 안내 기록이 남고 작품 설정·캐릭터·분석 작업이 생성되지 않는지 확인한 뒤 만든 작품을 정리한다.
- Pencil 프레임: `gh194AnalysisGuideDesktop`, `gh194AnalysisGuideManualDesktop`, `gh194AnalysisGuideMobile`. `docs/screens/gh194/analysis-guide-{desktop,manual-desktop,mobile}.png`에서 실제 안내 화면과 두 방식의 예시를 확인한다. desktop/mobile은 실제 로컬 API 연결의 격리 계정으로도 검증한다.
- 서버 구현·V64·계정 이력 보존은 Java 저장소의 `docs/analysis-mode-guide.md`를 따른다. 배포는 Java V64/API 적용 후 프론트 순서다.
