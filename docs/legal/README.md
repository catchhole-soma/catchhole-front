# CatchHole 법률 문서 운영 기준

이 디렉터리의 Markdown은 CatchHole 법률 문서의 작성·리뷰 원문이다. 실행 시에는 Backend의 `legal_documents`에 게시된 동일 원문을 API로 조회해 표시하며 Front에 약관 문장을 하드코딩하지 않는다.

- GitHub: [catchhole-backend-java #136](https://github.com/catchhole-soma/catchhole-backend-java/issues/136)
- Jira: [NVM-303](https://aiswmproject.atlassian.net/browse/NVM-303)
- 공식 서비스 주소: [https://www.catchhole.com](https://www.catchhole.com)
- 현재 locale: `ko-KR`
- 현재 게시 버전: `2026-08-24`
- 공고일·시행일: 2026년 8월 24일
- 탈퇴·파기 후속 작업: [NVM-313](https://aiswmproject.atlassian.net/browse/NVM-313)

이 디렉터리의 문서는 `privacy-kr` 스킬의 법률 체크리스트와 문서 구조를 참고해 작성했다. CatchHole은 Next.js가 아닌 Vite 기반 React 프로젝트이므로 스킬의 Next.js 렌더러는 사용하지 않고, 검토 가능한 Markdown 원문으로 관리한다.

## 문서 상태와 가입 기록

- [`terms-of-service.ko.md`](./terms-of-service.ko.md)와 [`privacy-policy.ko.md`](./privacy-policy.ko.md)는 `2026-08-24` `PUBLISHED` 원문이다.
- 기존 회원가입 화면의 `2026-08-23` 간략 문구는 당시 동의 이력을 보존하기 위해 `RETIRED` 문서로 저장한다.
- 새 문서는 이번 배포에서 `DRAFT`를 거치지 않고 바로 `PUBLISHED`로 등록한다. 이후 편집에는 `DRAFT → PUBLISHED → RETIRED` 수명주기를 사용할 수 있다.
- 버전은 시행일 기준 `YYYY-MM-DD` 형식이며 같은 날 다시 게시하면 `YYYY-MM-DD.2`, `.3`처럼 순번을 붙인다. 게시된 행의 원문은 제자리에서 수정하지 않는다.
- 회원가입 화면은 API로 받은 원문을 실제 렌더링하고, 가입 요청에 사용자가 확인한 `termsDocumentId`와 `privacyPolicyDocumentId`를 보낸다.
- Backend는 두 ID가 가입 시점의 현재 게시본인지 같은 트랜잭션에서 검증하고 정확한 문서 FK·종류·버전·행위·서버 기록 시각을 `member_legal_records`에 저장한다.
- 가입 도중 문서가 바뀌면 가입을 거절하고 최신 문서를 다시 표시해 재확인받는다.
- 원문은 UTF-8·LF 기준 SHA-256 해시와 함께 보존한다.

### 사업장 주소 공개 원칙

- 개인정보처리방침에는 사업장 주소와 사업자등록번호를 넣지 않는다. 개인정보 보호법 제30조 제1항 제6호에 따라 개인정보 보호 업무 및 고충처리 담당 부서명과 연락처를 공개한다.

- 법문은 동·호수를 별도로 지칭하지 않지만, 동·호수가 등록 주소의 일부라면 일부만 잘라 표시하지 않는다.

## 확정한 운영 정책

- 대한민국 이용자를 대상으로 하는 한국어 AI 창작 보조 서비스다.
- 만 14세 이상만 가입할 수 있도록 운영한다.
- 현재 결제, 정기구독과 광고성 이메일 발송은 제공하지 않는다.
- 이용자가 업로드한 원고와 작성한 설정의 저작권은 이용자에게 남는다.
- 원고는 이용자가 요청한 설정 추출·비교·정리 기능을 제공하는 범위에서만 처리한다.
- CatchHole 또는 외부 범용 AI 모델의 학습·미세조정·평가 데이터로 원고를 사용하지 않는다.
- OpenAI API 요청은 `store: false`로 보낸다.
- AI 결과는 창작 보조 제안이며 이용자가 검토·수정·확정한다. 법적 또는 이에 준하는 중대한 효과를 자동으로 결정하지 않는다.
- GA4와 Meta Pixel은 별도 가입 체크박스나 쿠키 동의 배너를 두지 않고, 자동 수집 항목·목적·보유기간·국외 처리와 거부방법을 개인정보처리방침에 공개한다.
- Google 사용자 제공 데이터 수집, Meta 고급 매칭과 Meta Conversions API는 사용하지 않는다.
- 분석·광고 사업자에는 회원 ID·이메일·전화번호·원고·작품 제목·캐릭터·세계관·검색어·프롬프트·AI 결과를 보내지 않는다.
- 측정 이벤트는 방문, 공개 데모 시작·완료, 가입 완료, 첫 분석 완료와 자문 신청 전환으로 제한한다.
- GA4 사용자·이벤트 데이터 보유기간은 14개월, CatchHole Meta 맞춤 대상은 최대 180일로 설정한다.

## 코드에서 확인한 현재 처리 흐름

### 회원가입과 인증

- 회원가입 시 이메일, 비밀번호, 표시 이름, 인증된 휴대전화번호를 처리한다. 비밀번호는 해시로 저장한다.
- 휴대전화 인증 원문 번호와 인증 흐름은 Redis에 최대 5분, 일회용 가입 토큰은 최대 10분 보관한다.
- 발송 제한용 전화번호·IP 해시는 시간·일·월 단위 만료 키로 보관한다.
- SOLAPI의 공개 방침상 수신번호와 인증문자 발송 이력은 발송일로부터 1년 보관될 수 있다.
- access token 유효기간은 30분이며 브라우저 `localStorage`에 저장한다.
- refresh token 유효기간은 14일이며 원문은 HttpOnly 쿠키, 해시는 Backend DB에 저장한다. 만료·폐기된 DB 행의 실제 삭제 주기는 아직 확인되지 않았다.
- 회원가입 화면은 이용약관 동의와 개인정보처리방침 확인을 한 체크박스로 표시한다. Backend는 화면에 표시한 현재 문서 ID를 검증하고 두 의미를 각각의 문서 FK·버전·행위·서버 기록 시각으로 저장한다.

### 원고와 AI 분석

- 업로드 원본 파일과 회차 원문은 AWS S3에, 작품·회차 메타데이터와 분석 결과·설정·근거·검토 이력은 PostgreSQL에 저장한다.
- AI Worker는 S3 원문을 읽어 청크와 설정 후보를 만들고 원문 일부를 OpenAI Responses API에 전송한다.
- OpenAI 요청에는 `store: false`를 명시한다. API 입력·출력은 운영 계정에서 데이터 공유에 별도 참여하지 않는다.
- #130 구현은 작품 삭제 요청 시 작품을 `PURGING`으로 잠그고, S3 현재 객체·과거 버전·delete marker를 먼저 삭제한 뒤 DB 원본·파생 데이터를 자식부터 파기한다. 실패 재시도, 24시간 SLA 경고, 내용을 제외한 1년 감사 기록을 포함한다.

### 인프라와 자동 수집

- Front는 Vercel, Backend·AI·PostgreSQL·Redis는 단일 AWS EC2 배포 정의, 원고는 AWS S3를 사용한다.
- 코드의 기본 AWS 리전은 `ap-northeast-2`이지만 실제 운영 계정·버킷·백업 리전은 확인해야 한다.
- GA4와 Meta Pixel의 실제 설치는 NVM-308·NVM-309에서 진행한다. 현재 변경은 실제 자동 수집을 시작하지 않고 개인정보처리방침의 공개 구조를 먼저 확정한다.
- 개발용 Figma HTML 캡처 외부 스크립트는 운영 산출물에서 제거한다.
