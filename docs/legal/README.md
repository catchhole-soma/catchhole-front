### 사업장 주소 공개 원칙

- 개인정보처리방침에는 사업장 주소와 사업자등록번호를 넣지 않는다. 개인정보 보호책임자의 성명·직책·전화·이메일만 공개한다.
- 이용약관과 서비스 초기 화면은 전자상거래법상 사이버몰 표시의무가 적용되는 경우 사업자등록증상 실제 영업소 주소를 사용한다.
- 법문은 동·호수를 별도로 지칭하지 않지만, 동·호수가 등록 주소의 일부라면 일부만 잘라 표시하지 않는다.
- 주거지 공개가 곤란하면 서비스 공개 전에 사업장 주소를 적법한 사무실 또는 비상주 사무실로 변경한 뒤 변경된 주소를 표시한다.

## 초안에 반영한 전제

- 대한민국 이용자를 대상으로 하는 한국어 AI 창작 보조 서비스다.
- 만 14세 이상만 가입할 수 있도록 운영한다.
- 현재 결제, 정기구독, 광고성 정보 발송, 맞춤형 광고와 GA4를 사용하지 않는다.
- 이용자가 업로드한 원고와 작성한 설정의 저작권은 이용자에게 남는다.
- 원고는 이용자가 요청한 설정 추출·비교·정리 기능을 제공하는 범위에서만 처리한다.
- CatchHole 또는 외부 범용 AI 모델의 학습·미세조정·평가 데이터로 원고를 사용하지 않는다.
- AI 결과는 창작 보조 제안이며 이용자가 검토·수정·확정한다. 법적 또는 이에 준하는 중대한 효과를 자동으로 결정하지 않는다.

전제가 실제 운영 정책과 달라지면 약관과 개인정보처리방침을 함께 수정해야 한다.

## 선택한 보유·파기 정책

아래 기간을 NVM-303의 목표 운영 정책으로 정한다. 실제 삭제 작업·수명주기·백업 설정이 이 기간을 지키는지 검증한 뒤 공개한다.

| 정보 | 선택한 기간 |
|---|---|
| 회원 계정 정보 | 탈퇴 처리 시작 즉시 파기 절차를 개시하고 운영계에서 최대 7일 이내 삭제 |
| 원고·업로드 파일·파생 설정·AI 결과 | 작품 삭제 또는 탈퇴 처리 시작 즉시 파기 절차를 개시하고 운영계에서 최대 7일 이내 삭제 |
| 격리 백업에 남은 계정·원고 데이터 | 운영계 삭제 후 복구에 사용하지 않으며 최대 30일 이내 자동 만료 |
| 약관·개인정보처리방침 동의 이력 | 이용계약 종료 후 5년간 최소 항목만 분리 보관 |
| access token | 발급 후 최대 30분 |
| refresh token | 발급 후 최대 14일, 만료·폐기된 DB 기록은 30일 이내 삭제 |
| 휴대전화 인증 흐름·가입 토큰 | 인증 흐름 최대 5분, 가입 토큰 최대 10분 |
| 휴대전화·IP 발송 제한 해시 | 시간·일 단위 기록은 해당 기간 종료 시, 월 단위 기록은 다음 달 시작 시 만료 |
| SOLAPI 문자 발송 이력 | 발송일로부터 1년 |
| 일반 문의 이메일 | 처리 완료 후 1년 |
| 소비자 불만·분쟁 기록 | 처리 완료 여부와 관계없이 관련 법령이 적용되는 범위에서 3년 |
| 서비스 접속·보안·오류 로그 | 생성일로부터 3개월 |
| OpenAI API 데이터 | `store: false` 적용을 목표로 하며, 제공자의 abuse monitoring log는 최대 30일 |

운영계 7일은 삭제 요청을 임의로 유예하는 기간이 아니라 분산된 DB·S3·캐시의 파기와 실패 재시도를 끝내기 위한 최장 처리기한이다. 삭제 요청을 받으면 신규 처리를 즉시 중지하고 파기 작업을 시작한다.

## 코드에서 확인한 현재 처리 흐름

### 회원가입과 인증

- 회원가입 시 이메일, 비밀번호, 표시 이름, 인증된 휴대전화번호를 처리한다. 비밀번호는 해시로 저장한다.
- 휴대전화 인증 원문 번호와 인증 흐름은 Redis에 최대 5분, 일회용 가입 토큰은 최대 10분 보관한다.
- 발송 제한용 전화번호·IP 해시는 시간·일·월 단위 만료 키로 보관한다.
- SOLAPI의 공개 방침상 수신번호와 인증문자 발송 이력은 발송일로부터 1년 보관될 수 있다.
- access token 유효기간은 30분이며 브라우저 `localStorage`에 저장한다.
- refresh token 유효기간은 14일이며 원문은 HttpOnly 쿠키, 해시는 Backend DB에 저장한다. 만료·폐기된 DB 행의 실제 삭제 주기는 아직 확인되지 않았다.
- 회원가입 화면은 이용약관과 개인정보처리방침을 한 체크박스로 묶고 있으며, Backend에는 문서 버전과 동의 시각을 전달하지 않는다.

### 원고와 AI 분석

- 업로드 원본 파일과 회차 원문은 AWS S3에, 작품·회차 메타데이터와 분석 결과·설정·근거·검토 이력은 PostgreSQL에 저장한다.
- AI Worker는 S3 원문을 읽어 청크와 설정 후보를 만들고 원문 일부를 OpenAI Responses API에 전송한다.
- 현재 OpenAI 요청은 `store: false`를 명시하지 않는다. OpenAI의 공개 문서상 Responses API는 기본적으로 응답 상태를 최소 30일 저장하며 abuse monitoring log도 30일 보관한다.
- OpenAI API 입력은 명시적으로 옵트인하지 않는 한 모델 학습에 사용되지 않는다고 공개되어 있지만, 운영 계정의 데이터 공유·보관·리전 설정은 별도 확인이 필요하다.
- 현재 작품 삭제는 DB 삭제, 회차 삭제는 보관 상태 변경 중심이며 S3 원본·이전 버전·파생 데이터의 일괄 영구 파기를 보장하지 않는다.

### 인프라와 자동 수집

- Front는 Vercel, Backend·AI·PostgreSQL·Redis는 단일 AWS EC2 배포 정의, 원고는 AWS S3를 사용한다.
- 코드의 기본 AWS 리전은 `ap-northeast-2`이지만 실제 운영 계정·버킷·백업 리전은 확인해야 한다.
- 저장소에서는 GA4나 맞춤형 광고 SDK를 찾지 못했다.
- `index.html`에는 개발용으로 보이는 Figma HTML 캡처 외부 스크립트가 포함되어 있다. 운영 배포 전에 제거하고 배포 산출물에서 다시 확인해야 한다.
